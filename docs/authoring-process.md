# Процесс написания главы

## 0. Подготовка

```bash
npm install
npm run reference     # если нет reference/open-games
npm run dev           # dev-сервер на http://localhost:5173 — нужен для всех проверок
```

Прочитайте:

- строки главы в `docs/course-plan.md` — план шагов (он ориентир, а не закон: фактический состав шагов глав 1–7 в нескольких местах отличается, см. «Фактическое состояние» ниже);
- **последний шаг предыдущей главы** целиком (`content/<глава>/<последний шаг>/solution/*`). Это стартовая точка новой главы;
- соответствующие файлы оригинала в `reference/open-games/puzzling-potions/src/`.

## 1. Сверка API до написания кода

Никаких утверждений об API по памяти. В интернете и в памяти модели много PixiJS v6/v7. Перед главой выпишите все API, которые она вводит, и проверьте каждое:

```bash
D=node_modules/pixi.js/dist/pixi.js.d.ts   # собранные типы
M=node_modules/pixi.js/dist/pixi.mjs       # собранный код — для поведения и значений по умолчанию
grep -n "defaultOptions = {" -A12 $M        # значения по умолчанию систем
python3 -c "..."                            # для поиска сигнатур удобнее Python + re, чем grep в zsh
```

Что проверять:

- сигнатуры и названия параметров;
- **значения по умолчанию** (они часто не такие, как кажется: например, обводка по умолчанию белая, `resolution` по умолчанию 1);
- **поведение** — читать реализацию в `pixi.mjs`, а не только комментарии. Пример: `hitArea` отсекает детей, только если точка **вне** области.

## 2. Код шагов

Код каждого шага — полные снимки файлов в `start/` и `solution/`. Удобнее всего генерировать их Python-скриптом **во временной папке** (не в репозитории): общие куски кода — строковые константы, шаги — их комбинации. Так цепочка «решение шага N = старт шага N+1» получается автоматически, а правка в общем куске применяется ко всем шагам.

Правила:

- первый шаг главы — `startFrom: custom`, его старт — очищенное решение последнего шага прошлой главы. Что убрали или вынесли в файлы, объясняется в тексте первого шага;
- если старт отличается от прошлого решения хотя бы строкой `// TODO`, шаг тоже `startFrom: custom`;
- новый файл, появившийся в шаге, — тоже `custom`. В старте лежит заготовка с `// TODO`;
- сцена должна помещаться в превью **500 × 600** без растягивания панелей. Поле 9 × 7 с клеткой 50 занимает 350 × 450 (+ отступы);
- после генерации: `npx tsc -p tsconfig.content.json` — весь код уроков проверяется по настоящим типам `pixi.js`.

## 3. Визуальная проверка до текста

До того как писать текст, посмотрите на результат каждого важного шага:

```bash
node tools/e2e/run-dir.mjs content/07-logic/08-cascade/solution   # консоль + скриншот в tools/e2e/out/
```

Затем откройте скриншот и проверьте глазами. Так найдено много проблем: дуга таймера с лишней линией, белый круг, вращение которого не видно, ряд зелий шире превью, крошечная иконка.

Для экспериментов с API, которые предлагаются в тексте, создайте временную папку с `main.ts` и запустите её тем же `run-dir.mjs`.

## 4. Текст уроков

По `docs/writing-guide.md`. Структура шага: зачем → объяснение → код с подсветкой строк → `::: task` → «Что получилось» → эксперименты → связь с оригиналом → `::: deep`. Практикум: `::: task` со списком, `::: hint` от общего к конкретному, «Проверьте себя», «Итоги главы» с мостиком к следующей главе.

## 5. Проверка каждого утверждения в тексте

Самый важный этап. Каждое фактическое утверждение и **каждый предложенный эксперимент** («поставьте X — увидите Y») проверяется кодом или исходниками. Ошибки, которые нашлись именно так (то есть сначала были написаны неверно):

| Утверждение в черновике | Как на самом деле |
|---|---|
| Маска, не добавленная в сцену, работает от начала экрана | Содержимое просто пропадает. Маска должна быть в дереве сцены |
| Спрайт с текстурой выгруженного атласа «исчезнет» | Рендер падает: `Cannot read properties of null (reading 'addressModeU')` |
| `boundsArea` не влияет на `getLocalBounds` | Влияет, но локальные границы кэшируются: задавать `boundsArea` до первого запроса |
| `worldTransform` можно читать сразу | До первого кадра это устаревший кэш. Точные значения — `getGlobalTransform()`, `toGlobal()` |
| Резолвер берёт «ближайшее» разрешение | Ищет точное совпадение, иначе берёт вариант по умолчанию (`@1x`) |
| Загрузчик ограничен 50 одновременными загрузками | Ограничения нет; фоновый загрузчик — строго по одному файлу |
| `interactive = true` выводит предупреждение | Не выводит, просто ставит `eventMode = 'static'` |
| `target` события — спрайт внутри фишки | Цель — самый глубокий **интерактивный** объект, то есть сама фишка |
| Смена текстуры сбрасывает размер, заданный через `width` | Спрайт запоминает `width`/`height` и применяет к новой текстуре |
| `alignment: 0` — внутри | `1` — внутри, `0` — снаружи |
| Цвет обводки по умолчанию чёрный | Белый |
| Без `moveTo` линии сетки станут зигзагом | Зигзаг будет при замене `moveTo` на `lineTo` |
| Звезда с равными радиусами — многоугольник с тем же числом вершин | С удвоенным |
| `Texture.WHITE` — 16 × 16 | 1 × 1 |
| `arc()` после `circle()` рисуется сам по себе | Соединяется прямой с текущей точкой пера; нужен `moveTo` |

Вывод: **не доверяйте себе**. Если утверждение нельзя проверить, лучше его не писать.

## 6. Регистрация и прогон в платформе

```bash
# добавить папку главы в content/course.json → chapters
npm run validate                                  # структура, цепочка start/solution, YAML, типы
node tools/e2e/run-chapter.mjs 07-logic           # все шаги в настоящем интерфейсе: «Решение», консоль, ошибки
```

`run-chapter` должен закончиться строкой `Ошибки страницы: []`, а в каждом шаге консоль должна выводить то, что обещает текст. Скриншоты лежат в `tools/e2e/out/`, просмотрите хотя бы несколько.

Если в главе есть взаимодействие или игровая логика, напишите для неё проверку в `tools/e2e/checks/` по образцу `ch06-interaction.mjs` (мышь: клики, свайпы) и `ch07-logic.mjs` (согласованность модели и вида после ходов). Числа из этих проверок можно и нужно цитировать в тексте («мы проверили: …»).

# Ловушки окружения

- **YAML во frontmatter:** фигурные скобки внутри списка `api: [...]` ломают разбор. Такие элементы — в кавычках: `api: [ticker.remove, 'destroy({ children })']`.
- **TypeScript 7** (Go-версия) в `node_modules` не имеет JS API (`ts.transpileModule` нет). Для компиляции в скриптах используется `esbuild`, для проверки типов — `tsc` из терминала.
- **Node 20** не запускает `.ts` напрямую: скрипты в `scripts/` и `tools/` — `.mjs`.
- **Vite `optimizeDeps.include`**: новые динамически импортируемые модули платформы нужно добавить туда, иначе после первого запуска страница падает с «Failed to fetch dynamically imported module».
- **Скриншоты в headless** нужно делать через 3+ секунды после запуска: первый кадр с ресурсами появляется не сразу.
- **zsh**: `$k[?]` в шаблонах grep интерпретируется как glob. Для сложного поиска используйте Python.
- **Не пишите во временные файлы `/tmp`**: используйте папку scratchpad сессии или `tools/e2e/out/` (она в `.gitignore`).
- **`manifest-basic.json`** — для глав 5–12 (без звуков и Spine). Полный `manifest.json` подключать с главы 13 вместе с `@pixi/sound`, иначе консоль засыпана предупреждениями «don't know how to parse».
- **Monaco: «TypeScript not registered!»** — при первом открытии страницы TS-воркер может быть ещё не готов. `compileStep` ждёт его с повторными попытками (`src/editor/monaco.ts`). Если увидите в `run-chapter` ошибку страницы с пустым сообщением — ищите похожую гонку.
- **`Assets.unloadBundle` с атласами** в 8.22 печатает безвредное предупреждение «not found in the Cache». В коде уроков — `Assets.unload('<псевдоним атласа>')`.

# Следующий шаг: глава 8 «Игровой цикл и анимация»

План шагов — в `course-plan.md`. Рекомендации, которые уже продуманы:

- **Старт главы:** решение 7.9 без `tests.ts` и вызова `runTests` (тесты оставить как файл можно, но чище убрать).
- **8.1–8.2 Ticker:** вращать подсветку выбранной фишки (`highlight.rotation`, как `renderUpdate` в `Match3Piece`), сравнить `deltaTime` и `deltaMS`, показать независимость от FPS через `app.ticker.maxFPS = 30`.
- **8.3 Свой твин:** файл `tween.ts` с функцией `tween(target, props, durationMs, easing): Promise<void>` на `Ticker`. Анимированный `swap` в `Board`. Важно: на время анимации блокировать фишки (`piece.eventMode = 'none'` или `interactiveChildren`), сбрасывая состояние нажатия, как `Match3Piece.lock()`.
- **8.4 Easing:** `quadOut`, `backOut` и «одиночный отскок» для падения (в оригинале кастомная кривая `easeSingleBounce` для `animateFall`, длительность 0.5 с; обмен — `quad.out`, 0.2 с; исчезновение — `alpha` за 0.1 с; появление — масштаб от 2 до 1 с `back.out`, 0.2 с).
- **8.5 Асинхронный каскад:** `process` превращается в `async`: `await` анимаций исчезновения, падения и досыпания (новые фишки начинают выше поля: `y = -BOARD_HEIGHT / 2 - n × TILE_SIZE`, где n — номер новой фишки в столбце; маска поля их обрежет). Неверный ход: обмен туда и обратно с анимацией, как в оригинальном `Match3Actions.swapPieces`. Модель (`grid.ts`) не меняется ни на строку — это нужно подчеркнуть в тексте.
- **8.6 `onRender`:** перенести вращение подсветки в `this.onRender` фишки; объяснить разницу с `ticker.add` и что `onRender` вызывается только для объектов на сцене.
- **8.7 TilingSprite:** фон из `background` бандла `preload` (как `TiledBackground.ts` оригинала: `tileTransform.rotation = -π × 0.15`, движение `tilePosition`).
- **8.8 GSAP:** добавить в `scripts/copy-vendor.mjs` копирование `gsap` (ESM-сборка) в `public/vendor/` и в import map `public/preview.html` (`"gsap": "/vendor/gsap.mjs"` или аналог), установить `gsap` в devDependencies, добавить типы для Monaco (`addExtraLib` с `.d.ts` из пакета `gsap`, путь `file:///node_modules/gsap/index.d.ts`). Переписать `tween` на `gsap.to`, показать `killTweensOf`.
- **8.9 AnimatedSprite:** в ресурсах игры покадровых анимаций нет. Варианты: сгенерировать кадры кодом (`renderer.generateTexture`) или сделать демо на кадрах `num-stroke-1..5` (цифры обратного отсчёта) — проверить, как это выглядит.
- Для проверки анимаций в `tools/e2e/checks/` пригодится ожидание окончания каскада (например, флаг `board.processing`) и проверка согласованности из `ch07-logic.mjs` после серии ходов.
