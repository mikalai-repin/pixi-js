# PixiJS — интерактивный курс

Интерактивный учебник по PixiJS v8 на русском языке. Ученик проходит курс в браузере: слева текст урока, в центре редактор кода с вкладками файлов, справа живой результат на canvas (по образцу официальных туториалов pixijs.com).

Сквозной проект курса — упрощённая, но полноценная версия игры **Puzzling Potions** (match-3) из [pixijs/open-games](https://github.com/pixijs/open-games). Ученик пишет её с нуля, шаг за шагом, а в финале разбирает оригинальный «профессиональный» код.

## Целевая аудитория

- Хорошо знает JavaScript и TypeScript (классы, модули, async/await, массивы, замыкания).
- **Ни разу не писал на PixiJS** и вообще не делал 2D-графику/игры.
- Цель — разобраться в PixiJS **максимально глубоко**: не только «как сделать», но и «почему так устроено» и «что происходит под капотом».

Следствие: основы JS не объясняем, а всё, что касается графики, рендеринга, игрового цикла и API PixiJS, объясняем подробно, с нуля.

## Ключевые решения

- **PixiJS 8.22.0** (зафиксирована точно, см. architecture.md). Никаких API из v7 (`beginFill`, `interactive = true`, `new Application({...})` без `init` и т. п.).
- **Язык уроков** — TypeScript. Тексты — на русском, идентификаторы в коде — на английском, комментарии в коде — на русском.
- **Ассеты** — оригинальные из `reference/open-games/puzzling-potions/raw-assets` (лицензия MIT, указываем авторство). В первых главах грузим отдельные PNG, атласы и AssetPack вводим позже.
- **Анимации**: сначала пишем свои твины на `Ticker` (чтобы понять принцип), затем подключаем GSAP, как в оригинале.
- **Сторонние библиотеки** (`@pixi/ui`, `@pixi/sound`, GSAP, Spine) появляются только после того, как ученик понял, как то же самое делается на «голом» PixiJS.

## Команды

- `npm run dev` — платформа на http://localhost:5173
- `npm run validate` — проверка структуры уроков и типов их кода (запускать после любых правок в `content/`)
- `npm run build` — проверка типов платформы и продакшен-сборка
- `npm run assets` — пересборка ресурсов через AssetPack в `public/assets/packed` (нужен `reference/`)
- `node tools/e2e/run-dir.mjs <папка шага>` — запустить код шага в чистом превью: консоль + скриншот в `tools/e2e/out/`
- `node tools/e2e/run-chapter.mjs <папка главы>` — пройти все шаги главы в интерфейсе платформы с «Решением»
- `node tools/e2e/checks/ch06-interaction.mjs`, `ch07-logic.mjs`, `ch08-animation.mjs`, `ch09-text.mjs` — проверки мышью, согласованности игры, анимированных ходов, счёта и таймера
- `node tools/e2e/exp.mjs <папка> <сценарий.mjs>` — прогнать эксперимент из текста урока со своим сценарием действий
- Все проверки требуют запущенного `npm run dev` и Chrome (`CHROME_PATH`, по умолчанию путь macOS)

`reference/` не редактируем: это эталон. Его нет в git; если папки нет — `npm run reference`.

## Текущий статус

Написаны главы 1–9 (75 шагов): вся первая часть (основы), логика match-3, анимация (тикер, твины, асинхронный каскад, `onRender`, `TilingSprite`, GSAP, `AnimatedSprite`) и текст (`Text`, стили, веб-шрифт Nunito, `BitmapText`, `HTMLText`, счёт и комбо). GSAP подключён к превью (`public/vendor/gsap.mjs`, типы в Monaco). **Следующая — глава 10 «Интерфейс и адаптивность»**: подробные рекомендации в конце `docs/authoring-process.md`. Перед продолжением прочитайте этот файл целиком: в нём процесс, по которому сделаны главы 1–9, и таблица ошибок, которые уже были найдены проверками.

## Пользователь и тон работы

- Пользователь — автор курса. Общение на русском.
- Названия игр (Puzzling Potions, Bubbo Bubbo) **не переводим**.
- Перед большой работой — короткий план; по ходу — короткие сообщения о том, что делается; в конце — итог: что сделано, как проверено, что осталось.

## Как работать над уроками

1. Найти шаг в `docs/course-plan.md`, проверить, какие API и понятия он вводит и что уже известно ученику из предыдущих шагов.
2. Писать по `docs/writing-guide.md`; термины — строго по `docs/glossary.md` (новый термин сначала добавить в словарь).
3. `start/` шага N+1 должен совпадать с `solution/` шага N (если не оговорено иное).
4. Решение каждого шага должно запускаться без ошибок и давать видимый результат. После правок — `npm run validate`.
5. Проверять факты об API по исходникам/типам `pixi.js` установленной версии, а не по памяти: в интернете много устаревших примеров для v6/v7.
6. Каждое утверждение и каждый эксперимент из текста урока проверять запуском кода (`tools/e2e/run-dir.mjs`). Полный процесс — в `docs/authoring-process.md`.
