# PixiJS — интерактивный курс

Интерактивный учебник по PixiJS v8 на русском языке. Ученик проходит курс в браузере: слева текст урока, в центре редактор кода с вкладками файлов, справа живой результат на canvas (по образцу официальных туториалов pixijs.com).

Сквозной проект курса — упрощённая, но полноценная версия игры **Puzzling Potions** (match-3) из [pixijs/open-games](https://github.com/pixijs/open-games). Ученик пишет её с нуля, шаг за шагом, а в финале разбирает оригинальный «профессиональный» код.

## Целевая аудитория

- Хорошо знает JavaScript и TypeScript (классы, модули, async/await, массивы, замыкания).
- **Ни разу не писал на PixiJS** и вообще не делал 2D-графику/игры.
- Цель — разобраться в PixiJS **максимально глубоко**: не только «как сделать», но и «почему так устроено» и «что происходит под капотом».

Следствие: основы JS не объясняем, а всё, что касается графики, рендеринга, игрового цикла и API PixiJS, объясняем подробно, с нуля.

## Ключевые решения

- **PixiJS 8.22.0** (зафиксирована точно, см. architecture.md). Никаких API из v7 (`beginFill`, `interactive = true`, `new Application({...})` без `init` и т. п.).
- **Язык уроков** — TypeScript. Тексты — на русском, идентификаторы в коде — на английском, комментарии в коде — на русском.
- **Ассеты** — оригинальные из `reference/open-games/puzzling-potions/raw-assets` (лицензия MIT, указываем авторство). В первых главах грузим отдельные PNG, атласы и AssetPack вводим позже.
- **Анимации**: сначала пишем свои твины на `Ticker` (чтобы понять принцип), затем подключаем GSAP, как в оригинале.
- **Сторонние библиотеки** (`@pixi/ui`, `@pixi/sound`, GSAP, Spine) появляются только после того, как ученик понял, как то же самое делается на «голом» PixiJS.

## Структура репозитория (целевая)

```
CLAUDE.md

reference/open-games/ — копия pixijs/open-games (коммит 83b4676), только для чтения; не в git, скачивается `npm run reference`
content/              — уроки курса (см. lesson-format.md)
public/assets/        — ассеты игры по бандлам (game/, common/, preload/…), см. CREDITS.md
public/preview*.      — среда выполнения кода ученика (без сборщика)
src/                  — код платформы (Vite + React + TS)
scripts/              — copy-vendor, validate-content, step-files (старт шага по цепочке)
tools/authoring/      — steps.py: запись шагов главы — только изменённые файлы (для генераторов глав)
.steps/               — полные снимки всех шагов, пишет npm run validate (не в git)
```

## Команды

- `npm run dev` — платформа на http://localhost:5173
- `npm run validate` — проверка структуры уроков и типов их кода (запускать после любых правок в `content/`); заодно пишет полные снимки шагов в `.steps/`
- `node scripts/step-files.mjs content/<глава>/<шаг>/solution [папка]` — полные файлы одного шага (JSON или в папку)
- `npm run build` — проверка типов платформы и продакшен-сборка
- `npm run assets` — пересборка ресурсов через AssetPack в `public/assets/packed` (нужен `reference/`)
- `node tools/e2e/run-dir.mjs <папка шага>` — запустить код шага в чистом превью: консоль + скриншот в `tools/e2e/out/`
- `node tools/e2e/run-chapter.mjs <папка главы>` — пройти все шаги главы в интерфейсе платформы с «Решением»
- `node tools/e2e/checks/ch06-interaction.mjs`, `ch07-logic.mjs`, `ch08-animation.mjs`, `ch09-text.mjs`, `ch10-ui.mjs`, `ch11-screens.mjs`, `ch12-effects.mjs`, `ch13-sound.mjs`, `ch14-spine.mjs`, `ch16-under-the-hood.mjs` — проверки мышью, согласованности игры, анимированных ходов, счёта и таймера, интерфейса и раскладки, экранов и полного цикла игры, эффектов и спецфишек, звука и настроек, Spine, внутренностей рендерера (замеры, WebGPU, память)
- `node tools/e2e/exp.mjs <папка> <сценарий.mjs>` — прогнать эксперимент из текста урока со своим сценарием действий
- Все проверки требуют запущенного `npm run dev` и Chrome (`CHROME_PATH`, по умолчанию путь macOS). По умолчанию WebGL программный (swiftshader); `GPU=1` — настоящая видеокарта и WebGPU (нужно для замеров главы 16, `ch16-under-the-hood.mjs` включает его сам)

`reference/` не редактируем: это эталон. Его нет в git; если папки нет — `npm run reference`.

## Текущий статус

Написаны главы 1–16 (128 шагов): основы, логика match-3, анимация, текст, интерфейс, экраны, эффекты (слой `GameEffects`, пул объектов, частицы, фильтры, pixi-filters, спецфишки) и звук (`@pixi/sound`: эффекты и музыка с кроссфейдом, политика autoplay, звуковой фильтр под паузой, громкость, настройки в `localStorage`) и необязательная глава про Spine (дракон и котёл); глава 15 — разбор кода оригинала (шаги без решения); глава 16 — «Под капотом»: рендереры, батчинг, рендер-группы, отсечение, рендер-текстуры, меш и шейдеры, свой фильтр, расширения, профилирование, память (шаги 16.3–16.6 — лаборатория отдельным `main.ts`, в игре появились `debug.ts` со `StatsSystem` и `GreyFilter.ts`). Игра полная и со звуком: Home → Game → Result. GSAP, `@pixi/ui`, `pixi-filters`, `@pixi/sound` и Spine-runtime подключены к превью (у Spine лицензия не MIT — см. `docs/roadmap.md`). **Следующая — глава 17 «Финальный проект»**: рекомендации в конце `docs/authoring-process.md`. Перед продолжением прочитайте этот файл целиком: в нём процесс, по которому сделаны главы 1–16, и таблица ошибок, которые уже были найдены проверками.

## Пользователь и тон работы

- Пользователь — автор курса. Общение на русском.
- Названия игр (Puzzling Potions, Bubbo Bubbo) **не переводим**.
- Перед большой работой — короткий план; по ходу — короткие сообщения о том, что делается; в конце — итог: что сделано, как проверено, что осталось.

## Как работать над уроками

1. Найти шаг в `docs/course-plan.md`, проверить, какие API и понятия он вводит и что уже известно ученику из предыдущих шагов.
2. Писать по `docs/writing-guide.md`; термины — строго по `docs/glossary.md` (новый термин сначала добавить в словарь).
3. **Шаг хранит только изменённые файлы**: `start/` — отличия от результата предыдущего шага (через границу главы), `solution/` — отличия от старта; убранные из старта файлы — `remove:` во frontmatter. Старт шага N+1 по умолчанию — решение шага N (`startFrom: previous`, папки `start/` нет); `start/` и `remove` — только у `startFrom: custom`. Полные наборы собирают платформа, валидатор и `tools/e2e` (`scripts/step-files.mjs`); глазами их смотреть в `.steps/` после `npm run validate`. Генератор главы пишет шаги через `write_steps` из `tools/authoring/steps.py` — он сам вычисляет отличия. Правка раннего файла доходит до всех следующих шагов и глав — после неё проверяется весь курс.
4. Решение каждого шага должно запускаться без ошибок и давать видимый результат. После правок — `npm run validate`.
5. Проверять факты об API по исходникам/типам `pixi.js` установленной версии, а не по памяти: в интернете много устаревших примеров для v6/v7.
6. Каждое утверждение и каждый эксперимент из текста урока проверять запуском кода (`tools/e2e/run-dir.mjs`). Полный процесс — в `docs/authoring-process.md`.
