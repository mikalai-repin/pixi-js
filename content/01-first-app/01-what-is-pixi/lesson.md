Справа летают и отскакивают от краёв 60 зелий. Каждое движется и вращается со своей скоростью, и всё это перерисовывается около 60 раз в секунду. Это сделано на **PixiJS**, и к концу второй главы вы сможете написать такое сами.

Но сначала разберёмся, что такое PixiJS и почему вообще нужна отдельная библиотека, чтобы нарисовать картинку в браузере.

## Как браузер рисует

Обычная веб-страница состоит из DOM-элементов: `div`, `img`, `button`. Браузер сам решает, как их расположить и когда перерисовать. Для интерфейсов это удобно. Для игр — нет: если двигать 60 `img` через CSS каждый кадр, браузер каждый раз пересчитывает стили, раскладку и слои. Счёт идёт на тысячи объектов, и DOM начинает тормозить гораздо раньше.

Для графики в браузере есть элемент **`<canvas>`** — прямоугольник из пикселей, в котором можно рисовать кодом. Рисовать в нём можно тремя способами:

| API | Что это | Скорость |
|---|---|---|
| Canvas 2D | Простые команды вида «нарисуй прямоугольник», «нарисуй картинку». Выполняются в основном на процессоре | Хватает для сотен объектов |
| WebGL | Доступ к видеокарте (GPU) через низкоуровневый API OpenGL ES | Десятки тысяч объектов |
| WebGPU | Новый API для видеокарты, преемник WebGL | Ещё быстрее и гибче, но поддерживается не везде |

Видеокарта умеет рисовать огромное количество треугольников параллельно. Но разговаривать с ней через WebGL тяжело: нужно писать шейдеры на языке GLSL, загружать данные в буферы, вручную управлять текстурами. Чтобы вывести одну картинку, понадобится около сотни строк кода.

## Что делает PixiJS

**PixiJS** — это библиотека 2D-рендеринга. Она берёт на себя всю работу с видеокартой и даёт вместо неё удобную модель: на сцене есть объекты (картинки, фигуры, текст), у них есть позиция, размер, поворот и прозрачность. Вы меняете свойства объектов, а PixiJS каждый кадр превращает их в команды для GPU.

```
ваш код  →  объекты сцены  →  PixiJS  →  WebGL / WebGPU  →  видеокарта  →  <canvas>
```

Компонент, который превращает сцену в пиксели, называется **рендерер**. В PixiJS v8 их три: WebGL, WebGPU и Canvas 2D (запасной вариант для устройств без GPU). Код при этом один и тот же: рендерер выбирается автоматически.

::: tip
Слово «рендеринг» (отрисовка) в этом курсе означает превращение сцены в пиксели на экране. «Отрендерить кадр» — нарисовать одну картинку из всех объектов сцены.
:::

## PixiJS — не игровой движок

Это важное отличие. Игровые движки вроде Phaser дают готовые физику, звук, сцены, загрузку уровней и управление. PixiJS делает одно: **быстро рисует**. Всё остальное — правила игры, экраны, анимации, звук — вы пишете сами или подключаете отдельные библиотеки.

Звучит как минус, но для изучения это плюс: в PixiJS нет магии. Каждую часть игры мы напишем сами и будем понимать, как она работает. А ещё PixiJS используют не только для игр, но и для интерактивных сайтов, визуализаций данных, редакторов графики — везде, где нужно быстро рисовать много объектов.

## Что мы будем делать в курсе

Сквозной проект курса — игра **Puzzling Potions** в жанре «три в ряд» (match-3). Это открытая игра от команды PixiJS из репозитория [open-games](https://github.com/pixijs/open-games). Мы напишем её учебную версию с нуля, по шагам, на оригинальной графике. А в конце разберём оригинальный код и посмотрим, как PixiJS устроен внутри.

Курс состоит из трёх частей:

1. **Основы** — приложение, спрайты, контейнеры, графика, загрузка ресурсов, события.
2. **Игра** — логика match-3, анимации, текст, интерфейс, экраны, эффекты, звук.
3. **Глубже** — разбор оригинала и устройство PixiJS: рендереры, батчинг, шейдеры, производительность.

## Как устроен этот интерфейс

- **Слева** — текст шага. Блоки «Задание» говорят, что сделать в коде.
- **В центре** — редактор. Это TypeScript с подсказками: наведите курсор на любое слово из PixiJS (например, `Sprite`), и появится документация. Сочетание `Ctrl` + пробел показывает список доступных свойств и методов.
- **Справа** — результат и консоль. Код перезапускается сам через секунду после правки (галочка «Автозапуск»), или по кнопке «Запустить» / `Ctrl`/`Cmd` + `Enter`.
- **«Сброс»** возвращает стартовый код шага, **«Решение»** показывает готовый ответ (ваш код сохранится, его можно вернуть).

Всё, что вы пишете, сохраняется в браузере: можно закрыть вкладку и продолжить позже.

::: task
Найдите в коде константу `COUNT` и замените `60` на `600`. Посмотрите, справится ли браузер. Потом попробуйте `5000`.
:::

Скорее всего, даже несколько тысяч зелий будут двигаться плавно. Это и есть главная причина использовать PixiJS: видеокарта рисует все эти картинки за доли миллисекунды.

::: deep Под капотом: почему тысячи картинок — это быстро
Видеокарта рисует не картинки, а треугольники. Каждое зелье — это прямоугольник из двух треугольников, на который «натянута» текстура. Если отправлять на GPU каждое зелье отдельной командой, всё упрётся в накладные расходы на сами команды. Поэтому PixiJS собирает много объектов в одну пачку и отправляет её одной командой. В пачку могут попасть даже спрайты с разными текстурами, если текстур немного (обычно до 16 — зависит от видеокарты). Это называется **батчинг** (batching), и мы подробно разберём его в главе 16. Именно поэтому 5000 зелий шести видов почти ничего не стоят.
:::
