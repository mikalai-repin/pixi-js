`Application` — это не какой-то один механизм, а удобная обёртка над четырьмя частями, с которыми вы будете работать постоянно. Разберём каждую и заставим фон «дышать», чтобы увидеть игровой цикл в действии.

## Четыре части приложения

```
Application
├── stage     — сцена: корень дерева всех объектов, которые нужно нарисовать
├── renderer  — рендерер: превращает сцену в пиксели на canvas
├── ticker    — тикер: вызывает код каждый кадр
└── screen    — прямоугольник видимой области (x, y, width, height)
```

### `app.stage` — сцена

Сцена (**stage**) — это корневой контейнер. Всё, что должно появиться на экране, нужно добавить в него или в его потомков. Объект, который не добавлен в сцену, существует в памяти, но не рисуется, как и canvas, не добавленный в документ.

Сейчас сцена пуста: `app.stage.children.length` равно `0`. В следующей главе мы добавим в неё первый спрайт, а в главе 3 подробно разберём, как устроено дерево сцены.

### `app.renderer` — рендерер

Рендерер знает, как превратить сцену в картинку конкретным способом: через WebGL, WebGPU или Canvas 2D. Обычно его не трогают напрямую, но через него доступны полезные вещи: `app.renderer.name`, размер холста, а ещё **фон**, который можно менять на лету:

```ts
app.renderer.background.color = '#2a1450';
```

### `app.ticker` — тикер

Тикер (**ticker**) — это сердце приложения. Он вызывает функции **каждый кадр**, обычно 60 раз в секунду, а на мониторах 120 Гц — 120 раз. Сам PixiJS тоже подписан на тикер: каждый кадр приложение вызывает `app.render()`, и рендерер рисует сцену заново.

Своя функция добавляется так:

```ts
app.ticker.add((ticker) => {
  // этот код выполняется каждый кадр
});
```

Функция получает сам тикер, а у него есть **`deltaTime`** — сколько времени прошло с прошлого кадра. Время измеряется не в миллисекундах, а в «кадрах при 60 FPS»: на мониторе 60 Гц `deltaTime` около `1`, на 120 Гц — около `0.5`. Если умножать любую скорость на `deltaTime`, анимация будет одинаково быстрой на любом мониторе. Подробно об этом поговорим в главе 8.

### `app.screen` — экран

**`app.screen`** — прямоугольник видимой области в логических пикселях: `x`, `y`, `width`, `height`. С `resizeTo: window` он всегда равен размеру окна. Через него мы будем ставить объекты в центр (`app.screen.width / 2`) и прижимать интерфейс к краям.

## Оживляем фон

Соберём всё вместе. Выведем в консоль размер экрана и число объектов на сцене, а затем через тикер будем каждый кадр немного менять оттенок фона:

```ts main.ts {12-20}
import { Application } from 'pixi.js';

const app = new Application();
await app.init({
  background: '#1e1035',
  resizeTo: window,
  antialias: true,
});

document.body.appendChild(app.canvas);

console.log('Рендерер:', app.renderer.name);
console.log('Экран:', app.screen.width, '×', app.screen.height);
console.log('Объектов на сцене:', app.stage.children.length);

// Каждый кадр немного сдвигаем оттенок фона
let hue = 260;
app.ticker.add((ticker) => {
  hue = (hue + 0.5 * ticker.deltaTime) % 360;
  app.renderer.background.color = { h: hue, s: 55, l: 14 };
});
```

Цвет задан в формате **HSL**: `h` — оттенок на цветовом круге (0–360°), `s` — насыщенность (%), `l` — яркость (%). Меняя только `h`, мы плавно проходим по всем цветам радуги, а насыщенность и яркость остаются неизменными. `% 360` возвращает оттенок к нулю после полного круга.

::: task
Выведите в консоль размер экрана и количество объектов на сцене, а затем добавьте в тикер функцию, которая меняет оттенок фона.
:::

## Что получилось

Фон медленно переливается: фиолетовый → синий → зелёный и так далее по кругу. Полный круг занимает около 12 секунд: 360° / 0,5° за кадр = 720 кадров, а при 60 кадрах в секунду это 12 секунд.

Поэкспериментируйте:

- замените `0.5` на `5`: фон начнёт мелькать;
- уберите `* ticker.deltaTime` и подумайте, что изменится на мониторе 120 Гц;
- поменяйте размер превью и перезапустите код: размер экрана в консоли изменится.

::: deep Под капотом: что происходит за один кадр
1. Браузер перед каждой перерисовкой экрана вызывает `requestAnimationFrame`. На это событие подписан тикер.
2. Тикер вычисляет `deltaTime` и вызывает подписанные функции **по приоритету**. У вашей функции приоритет по умолчанию — `UPDATE_PRIORITY.NORMAL` (0). Приложение подписывает свой `render()` с приоритетом `LOW` (−25), поэтому он всегда вызывается **после** ваших функций: сначала вы меняете объекты, потом PixiJS рисует результат.
3. Рендерер обходит дерево сцены, собирает объекты в пачки и отправляет команды видеокарте.
4. Видеокарта рисует кадр в canvas, браузер показывает его на экране.

На всё это при 60 FPS есть около 16,7 мс. Если ваш код в тикере работает дольше, кадр не успеет, и анимация начнёт дёргаться. Поэтому в функциях тикера не стоит делать тяжёлых вычислений и лишних созданий объектов.
:::
