Любая программа на PixiJS начинается с объекта **`Application`**. Это «пульт управления»: он создаёт рендерер, сцену и игровой цикл и связывает их вместе. В этом шаге мы создадим приложение и убедимся, что PixiJS запустился.

## Два этапа: конструктор и `init`

В PixiJS v8 приложение создаётся в два этапа:

```ts main.ts
const app = new Application();
await app.init();
```

**Первая строка** создаёт пустой объект. Рендерера и canvas у него ещё нет, рисовать он пока не умеет.

**Вторая строка** — настоящий запуск. Метод `init()` асинхронный: он возвращает `Promise`, и его нужно дождаться через `await`. Вот что происходит внутри:

1. PixiJS выбирает рендерер. По умолчанию он пробует WebGL, если тот недоступен — WebGPU, а в крайнем случае — Canvas 2D.
2. Для выбранного рендерера создаётся элемент `<canvas>` и контекст рисования.
3. Запускаются внутренние системы рендерера: работа с текстурами, фоном, фильтрами и т. д.
4. Запускается тикер — игровой цикл, о нём в шаге 5.

Почему нельзя сделать всё это в конструкторе? Потому что часть операций в браузере асинхронная. Например, WebGPU выдаёт доступ к видеокарте только через `await navigator.gpu.requestAdapter()`. Конструктор в JavaScript не может быть асинхронным, поэтому инициализацию вынесли в отдельный метод.

::: warning
В старых статьях и ответах на Stack Overflow вы встретите `new Application({ width: 800 })` без `init()` и обращение к `app.view`. Это API PixiJS v7. В v8 параметры передаются в `init()`, а canvas называется `app.canvas`. Если пример из интернета не работает — первым делом проверьте, для какой он версии.
:::

## `await` на верхнем уровне

Обратите внимание: `await app.init()` написан прямо в файле, а не внутри `async function`. Это **top-level await**: в ES-модулях можно использовать `await` на верхнем уровне файла. Модуль просто «подождёт» в этой точке, прежде чем выполнять следующие строки.

В оригинальной Puzzling Potions, где сборка устроена иначе, весь запуск обёрнут в функцию `async function init()`. Это то же самое, только с лишним уровнем вложенности.

## Какой рендерер выбран

У рендерера есть свойство `name`, по которому видно, на чём PixiJS рисует: `'webgl'`, `'webgpu'` или `'canvas'`.

```ts main.ts {6}
import { Application } from 'pixi.js';

const app = new Application();
await app.init();

console.log('Рендерер:', app.renderer.name);
```

::: task
Создайте приложение, дождитесь `init()` и выведите в консоль имя рендерера.
:::

## Что получилось

В консоли под превью должна появиться строка `Рендерер: webgl`. А само превью… осталось пустым.

Это не ошибка. PixiJS создал canvas и уже рисует в него кадры, но canvas пока нигде не добавлен на страницу. Он существует только в памяти, как `document.createElement('canvas')`, который забыли вставить в документ. Исправим это в следующем шаге.

::: tip
Попробуйте убрать `await` перед `app.init()`. В консоли появится ошибка `Cannot read properties of undefined (reading 'name')`: следующая строка выполнилась раньше, чем закончилась инициализация, и рендерера ещё нет (`app.renderer` равен `undefined`). Верните `await` на место.
:::
