Убавьте музыку до 20 %, закройте настройки и перезапустите код. Музыка снова на полной громкости: `userSettings` — обычный объект в памяти, и при каждом запуске он создаётся заново. Для игрока это раздражает: игра, которая при каждом открытии орёт на всю громкость, быстро отправляется в закрытую вкладку.

Рекорд мы уже научились хранить в главе 11: `stats.ts` пишет его в **`localStorage`** — хранилище браузера, которое переживает перезагрузку страницы. С настройками всё так же, но с двумя отличиями: значений несколько, и их нужно не только записать, но и **проверить** при чтении.

## Объект в localStorage

`localStorage` хранит только строки: `setItem(ключ, строка)` и `getItem(ключ)`, который вернёт строку или `null`. Рекорд — одно число, его мы переводили в строку и обратно через `String` и `Number`. Объект настроек проще всего превратить в строку через JSON:

```ts
JSON.stringify({ music: 0.5, sfx: 1, hint: true }); // '{"music":0.5,"sfx":1,"hint":true}'
JSON.parse('{"music":0.5,"sfx":1,"hint":true}');    // снова объект
```

Ключ — с именем игры, как у рекорда: на одном сайте может быть много страниц и игр, и у всех один `localStorage`. Превью курса, кстати, тоже делит его со страницей курса: там под ключом `pixi-course:v1` лежит ваш код и прогресс.

## Чтение с проверкой

Что может оказаться в хранилище под нашим ключом? Что угодно:

- ничего — игрок открыл игру впервые;
- настройки старой версии игры — например, `{"speed":0.5,"hint":false}`, без громкостей;
- испорченная строка — кто-то поправил её руками в инструментах разработчика;
- значения не того типа: `"music": "громко"` или `"music": 7`.

Игра не должна падать ни в одном из этих случаев. Правило простое: начинаем с настроек по умолчанию и берём из сохранённого только те значения, которые **подходят**. Перепишите `userSettings.ts`:

```ts userSettings.ts
/** Ключ в localStorage: с именем игры, как у рекорда */
const SETTINGS_KEY = 'puzzling-potions:settings';

/**
 * Настройки игрока, общие для всех экранов: попап настроек их меняет, игра применяет.
 * Хранятся в localStorage и переживают перезагрузку. Как userSettings в Puzzling Potions
 */
export const userSettings = loadSettings();

/** Записывает настройки в браузер */
export function saveSettings() {
  try {
    localStorage.setItem(SETTINGS_KEY, JSON.stringify(userSettings));
  } catch {
    // Хранилище недоступно: настройки просто не запомнятся
  }
}

/** Читает сохранённые настройки. Чего нет или что испорчено, то берём по умолчанию */
function loadSettings() {
  const settings = {
    /** Громкость музыки: от 0 до 1 */
    music: 1,
    /** Громкость звуковых эффектов: от 0 до 1 */
    sfx: 1,
    /** Показывать ли подсказку под полем */
    hint: true,
  };
  try {
    const saved = JSON.parse(localStorage.getItem(SETTINGS_KEY) ?? '{}');
    // В хранилище может оказаться что угодно: данные старой версии игры, ручная правка.
    // Берём только значения подходящего типа
    if (isVolume(saved?.music)) settings.music = saved.music;
    if (isVolume(saved?.sfx)) settings.sfx = saved.sfx;
    if (typeof saved?.hint === 'boolean') settings.hint = saved.hint;
  } catch {
    // Испорченный JSON или недоступное хранилище: остаёмся с настройками по умолчанию
  }
  return settings;
}

/** Громкость — число от 0 до 1 */
function isVolume(value: unknown): value is number {
  return typeof value === 'number' && value >= 0 && value <= 1;
}
```

Несколько деталей:

- **`?? '{}'`** — если записи нет, `getItem` вернёт `null`, и мы разберём пустой объект;
- **`saved?.music`** — `JSON.parse('null')` вернёт `null`, и обращение к свойству без `?.` упало бы;
- **`try`** ловит две разные беды: `JSON.parse` бросает исключение на испорченной строке, а сам `localStorage` в некоторых браузерах и режимах недоступен — обращение к нему бросает исключение;
- **`value is number`** — защитник типа (type guard): после `isVolume(saved?.music)` TypeScript знает, что значение — число;
- тип `userSettings` TypeScript выводит из объекта `settings`, поэтому отдельный интерфейс не нужен.

## Когда сохранять

Сохранять можно на каждое движение слайдера, но это десятки записей за одно перетаскивание. Достаточно одного раза — когда игрок закрывает настройки. В `SettingsPopup`:

```ts SettingsPopup.ts
    done.onPress.connect(() => {
      saveSettings();
      navigation.dismissPopup();
    });
```

## Применить при запуске

Настройки прочитаны, но звук о них ещё не знает: `bgm` и `sfx` создаются с громкостью 1. Передадим им сохранённые значения до первого звука. В `main.ts`, после загрузки бандла `preload`:

```ts main.ts
// Громкость из сохранённых настроек — до того, как прозвучит первый звук
bgm.setVolume(userSettings.music);
sfx.setVolume(userSettings.sfx);
```

Подсказку под полем применять не нужно: экран игры и так читает `userSettings.hint` при создании.

3. В `main.ts` примените сохранённую громкость до первого звука.

## Что получилось

Убавьте музыку, выключите подсказку, нажмите «Готово» и перезапустите код. Меню встречает тихой музыкой, а в игре нет подсказки под полем. Посмотреть, что лежит в хранилище, можно в инструментах разработчика: вкладка Application (в Firefox — Storage), раздел Local Storage, адрес страницы курса, ключ `puzzling-potions:settings`.

Проверка запускала игру с разными записями в хранилище. С `{"music":0.3,"sfx":0.6,"hint":false}` музыка меню звучит на 0,3, слайдеры показывают 30 и 60 %, флажок подсказки снят. С испорченной строкой `{испорчено` и с `{"music":7,"sfx":"громко","hint":1}` — настройки по умолчанию, и ни одной ошибки в консоли. После «Готово» в хранилище оказывается ровно `{"music":0.5,"sfx":0.5,"hint":true}`.

## Эксперименты

- В инструментах разработчика замените значение ключа на `{испорчено` и перезапустите код. Игра запустится с настройками по умолчанию. Теперь уберите `try` в `loadSettings` и повторите: в консоли `SyntaxError: Expected property name or '}' in JSON`, а превью пустое — нет даже фона. Не выполнилась ни одна строка `main.ts`: модули, которые он импортирует, загружаются раньше его собственного кода, и `userSettings` упал прямо при загрузке. Мы проверили: на странице не появилось даже `canvas`. Верните `try`.
- Удалите ключ целиком (правой кнопкой → Delete) — так игра выглядит для нового игрока.

## Связь с оригиналом

В оригинале за это отвечают два файла. `utils/storage.ts` — обёртка над `localStorage` с методами `getNumber`, `setNumber`, `getObject` и другими. `utils/userSettings.ts` — класс `UserSettings`: каждая громкость хранится под своим ключом (`volume-master`, `volume-bgm`, `volume-sfx`), читается с запасным значением (`storage.getNumber(KEY) ?? 0.5`) и сохраняется сразу при каждом изменении. Конструктор применяет громкости к звуку — как наши две строки в `main.ts`. Ключи у оригинала без имени игры: окажись на том же сайте другая игра со своим `volume-bgm`, настройки двух игр смешались бы.

::: deep Под капотом: где живёт localStorage
`localStorage` привязан к **происхождению** страницы (origin): схема, домен и порт. `http://localhost:5173` и `http://localhost:5174` — разные хранилища, а все страницы одного происхождения делят одно. Объём — порядка 5 МБ на происхождение, данные хранятся только строками, а чтение и запись **синхронные**: браузер ждёт, пока операция закончится. Для пары настроек это ничтожно, но писать в `localStorage` каждый кадр не стоит.

Пользователь может в любой момент очистить данные сайта, а в приватном режиме хранилище удаляется вместе с окном. Поэтому в `localStorage` кладут то, что не жалко потерять: настройки, рекорд, прогресс простой игры. Для чего-то серьёзного — сохранения на сервере. Если данных много или они не строковые (например, картинки), есть асинхронная база в браузере — IndexedDB.
:::
