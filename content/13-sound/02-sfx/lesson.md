Один звук на совпадение — уже лучше тишины. Но в бандле `common` лежит целый набор: удачный и неудачный ход, взрыв спецфишки, «бульк», звуки кнопок. Звуки игры делятся на две группы:

- **звуковые эффекты** (sound effects, SFX) — короткие, одноразовые, привязаны к событию: ход, взрыв, нажатие;
- **фоновая музыка** (background music, BGM) — одна длинная дорожка, которая играет по кругу.

У них разные правила. Эффектов может звучать много сразу, музыка — всегда одна. В настройках игроки любят выключать музыку, оставив эффекты, и наоборот. Поэтому оригинал заводит для каждой группы свой объект: `sfx` и `bgm`. В этом шаге — эффекты, в следующем — музыка.

## Что изменилось в коде

Появился файл `audio.ts` с пустым классом `SFX` и готовым экспортом `sfx`. Это задание шага.

## Обёртка для эффектов

Зачем обёртка, если есть `sound.play`? Ради **громкости эффектов**: в шаге 6 появится слайдер «Звуки», и каждый эффект должен звучать с учётом его положения. Если вызывать `sound.play` из двадцати мест игры, громкость пришлось бы учитывать в каждом. Обёртка делает это в одном месте:

```ts audio.ts
import { sound, type PlayOptions } from '@pixi/sound';

/**
 * Звуковые эффекты: короткие одноразовые звуки. Своя громкость позволит
 * настраивать эффекты отдельно от музыки. Как SFX в Puzzling Potions
 */
class SFX {
  /** Громкость эффектов: от 0 до 1 */
  private volume = 1;

  /** Играет звук один раз. Громкость из options умножается на громкость эффектов */
  play(alias: string, options?: PlayOptions) {
    const volume = this.volume * (options?.volume ?? 1);
    sound.play(alias, { ...options, volume });
  }
}
```

**`PlayOptions`** — параметры одного проигрывания. Нам пригодятся два:

- **`volume`** — громкость этой копии, от 0 (тишина) до 1 (как записано). По умолчанию 1;
- **`speed`** — скорость. По умолчанию 1.

Есть и другие: `loop` (по кругу), `start` и `end` (играть кусок записи, в секундах), `complete` (функция, которую вызовут в конце), `filters` (о фильтрах — в шаге 5).

Пока громкость эффектов всегда 1, и умножение ничего не меняет. Метод, который её меняет, добавим вместе со слайдером.

## Звук хода

Удачный ход и неудачный должны звучать по-разному: игрок должен **слышать**, получилось или нет, ещё до того, как фишки доедут. Поле знает это сразу: `isValidMove` проверяет ход до анимации. Добавьте в `Board` колбэк, как `onPop` в главе 12:

```ts Board.ts
  /** Вызывается, когда игрок сделал ход: valid — получится ли совпадение */
  onMove?: (valid: boolean) => void;
```

И вызовите его в `onSwipe`:

```ts Board.ts {3}
    const valid = this.isValidMove(from, to);
    this.processing = true;
    this.onMove?.(valid);
```

Теперь слой эффектов. Звуки хода раздаются часто, пусть они будут потише:

```ts GameEffects.ts
/** Громкость звуков хода и взрыва: они звучат часто и не должны заглушать остальное */
const QUIET = 0.5;
```

```ts GameEffects.ts
  /** Игрок сделал ход: удачный он или нет, слышно сразу, ещё до конца анимации */
  onMove(valid: boolean) {
    sfx.play(valid ? 'common/sfx-correct.wav' : 'common/sfx-incorrect.wav', { volume: QUIET });
  }
```

Подключите его в `GameScreen` рядом с `onPop`:

```ts GameScreen.ts
    this.board.onMove = (valid) => this.vfx.onMove(valid);
```

## Комбо звучит выше

Каскад из нескольких раундов сейчас звучит одинаково: один и тот же звук совпадения раз за разом. Оригинал на каждом раунде немного поднимает **высоту звука** — и цепочка звучит как лесенка вверх, которая сама подсказывает: «ещё, ещё!».

Высота меняется через `speed`. Ускорили запись вдвое — каждое колебание стало вдвое короче, частота вдвое выше. В музыке это **октава**: тот же звук, но выше. Октава делится на 12 **полутонов**, и каждый полутон — это умножение частоты на одно и то же число, корень двенадцатой степени из двух, ≈ 1,0595. Двенадцать таких шагов подряд дают ровно 2. Значит, «на `n` полутонов выше» — это скорость `2 ** (n / 12)`:

```ts GameEffects.ts {3-4}
  /** Найдены совпадения: звучит звук, а на комбо поле трясёт — чем длиннее цепочка, тем сильнее */
  onMatch(round: number) {
    // Каждый раунд комбо звучит на полутон выше. Скорость 2 — это октава, а в октаве 12 полутонов
    sfx.play('common/sfx-match.wav', { speed: 2 ** ((round - 1) / 12) });
    if (round < 2) return;
```

Первый раунд — скорость 1, второй — 1,0595, третий — 1,1225. Импорт `sound` из `@pixi/sound` в `GameEffects` больше не нужен: замените его на `import { sfx } from './audio'`.

## Взрыв и «бульк»

Ещё два звука. Взрыв спецфишки — в начало `onSpecial`, после `const board = ...`:

```ts GameEffects.ts
    sfx.play('common/sfx-special.wav', { volume: QUIET });
```

А когда копия зелья долетает до счёта — короткий «бульк». В `playFlyToScore`, сразу после `await` твина масштаба:

```ts GameEffects.ts {2-3}
    await gsap.to(copy.scale, { x: scale, y: scale, duration, ease: 'back.in(3)' });
    // Копия долетела до счёта: «бульк»
    sfx.play('common/sfx-bubble.wav');
```

`sfx-bubble` длится 0,12 с, и копии прилетают в разное время (вспомните случайную добавку к длительности полёта), поэтому вместо каши получается быстрая дробь.

## Что получилось

Каждый свайп теперь звучит: удачный — одним звуком, ход без совпадения — другим. За удачным ходом следует звук совпадения и дробь «бульков», когда зелья ныряют в счёт; на комбо каждый следующий раунд звучит выше. Проверка подтвердила порядок: `sfx-correct` с громкостью 0,5, `sfx-match` со скоростью 1, три `sfx-bubble`; на ход без совпадения — один `sfx-incorrect`; третий раунд комбо — `sfx-match` со скоростью 1,1225.

## Эксперименты

- Поднимайте высоту не на полутон, а на целый тон: `2 ** ((round - 1) / 6)`. Или сделайте наоборот, каждый раунд ниже: `2 ** (-(round - 1) / 12)`. Какая лесенка звучит «победнее»?
- Поставьте `QUIET = 1` и сыграйте десяток ходов подряд. Звуки хода начнут спорить со звуком совпадения за внимание. Громкость — тоже инструмент: главное событие громче, служебные тише.
- Попробуйте другой звук на неудачный ход — например, `common/sfx-hover.wav`. Неудачный ход сразу «потеряет вес». Звук задаёт смысл не меньше, чем картинка.

## Связь с оригиналом

Наш `SFX` повторяет `SFX` из `utils/audio.ts` оригинала почти дословно. `GameEffects` оригинала играет те же звуки: `onMove` — `sfx-correct` или `sfx-incorrect` с громкостью 0,5, взрыв спецфишки — `sfx-special`, прилёт в котёл — `sfx-bubble`. На комбо оригинал тоже поднимает звук совпадения, но шагом 4 % за раунд (`speed: 1 - progress + combo * progress`, где `progress = 0.04`) — это чуть меньше полутона.

::: deep Под капотом: копии звука
Что происходит при каждом `sound.play`? Звук (`Sound`) хранит декодированную запись — один массив отсчётов на все проигрывания. А для каждого проигрывания создаётся **копия** (`IMediaInstance`) — маленькая цепочка звуковых узлов WebAudio: источник, который читает общую запись, и усилитель своей громкости. Источник WebAudio одноразовый: доиграл — и больше не запустится. Поэтому копия на каждое проигрывание своя, а запись общая.

Сами объекты копий библиотека не выбрасывает: у класса `Sound` есть статический пул копий, как наш `Pool` из главы 12. Доигравшая копия возвращается в пул, а следующий `play` берёт её оттуда. Мы проверили: после конца короткого `sfx-press` в пуле одна копия, и следующий `play` вернул тот же самый объект.

Громкость, которую услышит игрок, — произведение трёх множителей: громкость **всей библиотеки** (`sound.volumeAll`), громкость **звука** (`Sound.volume`, общая для всех его копий) и громкость **копии** (`volume` из `PlayOptions`). Скорость считается так же. Это пригодится нам в шаге 6.
:::
