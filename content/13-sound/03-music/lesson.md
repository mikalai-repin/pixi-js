Эффекты звучат, но между ходами — тишина. В бандле `common` есть две музыкальные **дорожки**: спокойная `bgm-main` для меню и результата (53 с) и более бодрая `bgm-game` для игры (70 с). Музыка должна:

- играть **по кругу**, сколько бы игрок ни сидел на экране;
- звучать **одна**: две мелодии одновременно — какофония;
- при смене экрана **плавно** переходить в другую, а не обрываться на полуноте.

Плавная смена, когда одна дорожка затихает, а другая в это же время нарастает, называется **кроссфейд** (crossfade).

## Класс BGM

Добавьте в `audio.ts` второй класс:

```ts audio.ts
/** Сколько секунд длится переход от одной музыки к другой */
const FADE_TIME = 1;

/**
 * Фоновая музыка: одна дорожка играет по кругу. Новая дорожка плавно сменяет старую.
 * Как BGM в Puzzling Potions
 */
class BGM {
  /** Псевдоним дорожки, которая играет сейчас */
  currentAlias?: string;
  /** Сама дорожка */
  current?: Sound;
  /** Громкость музыки: от 0 до 1 */
  private volume = 1;

  /** Включает музыку. Если играет другая, она плавно затихает, а новая плавно нарастает */
  play(alias: string, options?: PlayOptions) {
    // Эта музыка уже играет: не начинаем её сначала
    if (this.currentAlias === alias) return;

    if (this.current) {
      const previous = this.current;
      gsap.killTweensOf(previous);
      gsap.to(previous, { volume: 0, duration: FADE_TIME, ease: 'linear' }).then(() => previous.stop());
    }

    this.currentAlias = alias;
    this.current = sound.find(alias);
    // Громкость Sound действует на все его копии: начинаем с тишины и плавно её поднимаем
    this.current.volume = 0;
    this.current.play({ loop: true, ...options });
    gsap.killTweensOf(this.current);
    gsap.to(this.current, { volume: this.volume, duration: FADE_TIME, ease: 'linear' });
  }
}
```

И экспорт рядом с `sfx`:

```ts audio.ts
/** Фоновая музыка — одна на всю игру */
export const bgm = new BGM();
```

Импорты: `type Sound` из `@pixi/sound` и `gsap`.

Разберём по порядку.

**`sound.find(alias)`** возвращает сам объект `Sound`, а не копию. С музыкой нам нужно управлять звуком целиком: менять громкость, останавливать.

**`loop: true`** — копия играет по кругу: дойдя до конца записи, начинает сначала, без паузы.

**Кроссфейд — это два твина.** GSAP умеет анимировать любое числовое свойство любого объекта, не только объекты сцены: в главе 12 мы так анимировали силу тряски в обычном объекте `{ power }`. У `Sound` свойство `volume` — сеттер, который сразу пересчитывает громкость всех его копий. Старая дорожка за секунду уходит в 0 и после этого останавливается: `stop()` останавливает все копии звука. Новая начинает с 0 и за ту же секунду поднимается до громкости музыки.

**`ease: 'linear'`** — громкость меняется равномерно. С `quad.out` из главы 8 дорожка «выпрыгивала» бы сразу громко.

**`killTweensOf`** перед каждым твином: если сменить музыку посреди перехода, старый твин не должен дотянуть громкость до своего значения поверх нового.

## Музыка на экранах

Каждый экран сам решает, какая музыка ему нужна. В начале `show` у меню:

```ts HomeScreen.ts {2}
  async show() {
    bgm.play('common/bgm-main.mp3', { volume: 0.7 });
    gsap.from(this.logo, { y: -200, duration: 0.6, ease: 'back.out' });
```

У экрана игры:

```ts GameScreen.ts {2}
  async show() {
    bgm.play('common/bgm-game.mp3', { volume: 0.5 });
    await playCountdown(this, this.board.x, this.board.y);
```

У экрана результата — сразу после `this.buttons.visible = false`:

```ts ResultScreen.ts
    bgm.play('common/bgm-main.mp3', { volume: 0.5 });
```

`volume` в параметрах — громкость **копии**. Твин в `BGM` меняет громкость **звука**. Они перемножаются: в игре музыка в итоге звучит на 0,5 × 1 = 0,5. Эти числа — микширование, как в оригинале: в игре музыка тише, чтобы не заглушать эффекты.

Почему проверка `currentAlias` в начале так важна? Из результата по кнопке «Меню» мы возвращаемся в меню, а там та же `bgm-main`. Без проверки она начнётся заново — об этом эксперимент ниже.

::: task
1. Напишите класс `BGM` в `audio.ts` и экспортируйте `bgm`.
2. Включите музыку в `show` трёх экранов: `bgm-main` в меню (0,7) и на результате (0,5), `bgm-game` в игре (0,5).
:::

## Что получилось

В меню играет спокойная музыка. Нажмите «Играть»: за секунду она растворяется, и уже во время отсчёта звучит музыка игры. В конце игры, пока раскрывается «котёл» результата, возвращается музыка меню. Проверка подтвердила: в меню у `bgm-main` одна копия, по кругу, с громкостью 0,7; после отсчёта у `bgm-main` ни одной копии, а `bgm-game` играет; на результате — наоборот.

Если музыка в меню молчит, а зазвучала только после нажатия «Играть», — так и бывает, если вы только что открыли страницу и ещё ни разу по ней не щёлкнули. Почему — в следующем шаге.

## Эксперименты

- Поставьте `FADE_TIME = 4` и начните игру. Отсчёт идёт пять секунд, и почти всё это время слышны обе мелодии. Хорошо видно, как устроен кроссфейд, и так же хорошо слышно, почему он должен быть коротким.
- Уберите проверку `if (this.currentAlias === alias) return;`, доиграйте до результата и нажмите «Меню». Музыка меню зазвучит дважды, вразнобой, как эхо. Мы проверили: после повторного `play` той же дорожки у звука **две** копии, сдвинутые по времени. Почему? `previous` и новый `current` — один и тот же объект `Sound`. Твин затухания создаётся на нём и тут же убивается вторым `killTweensOf`, поэтому старая копия не останавливается, а громкость звука возвращается к 1 для обеих копий. Верните проверку.
- Уберите `loop: true` и подождите в меню минуту: через 53 секунды музыка закончится и больше не начнётся.

## Связь с оригиналом

`BGM` в `utils/audio.ts` оригинала устроен так же: `currentAlias`, `current`, кроссфейд через `gsap.to(current, { volume })` и `stop()` после затухания. Экраны оригинала вызывают его в `show`: меню — `bgm.play('common/bgm-main.mp3', { volume: 0.7 })`, игра — `bgm-game` с громкостью 0,5, результат — `bgm-main` с 0,5. Одно отличие: оригинал сначала запускает копию, а потом обнуляет громкость звука. Мы делаем наоборот: громкость обнулена ещё до старта копии, и не нужно гадать, успеет ли браузер сыграть хоть кусочек на полной громкости.

::: deep Под капотом: почему кроссфейд иногда «проваливается»
При линейном кроссфейде в середине перехода обе дорожки звучат на половине громкости. Кажется, что в сумме выйдет как раз одна полная. Но две **разные** мелодии складываются не по амплитуде, а по мощности, а мощность пропорциональна квадрату амплитуды: 0,5² + 0,5² = 0,5. Это примерно на 3 дБ тише, и на длинном переходе ухо слышит провал посередине.

Звукорежиссёры делают кроссфейд **равной мощности**: громкость старой дорожки меняется как `cos`, новой — как `sin` от доли перехода, и сумма квадратов всё время равна 1. На GSAP это одна общая доля `t` от 0 до 1 и `onUpdate`, который выставляет обе громкости — тот же приём, что у тряски в главе 12. Для перехода в одну секунду разница почти не слышна, поэтому мы, как и оригинал, обходимся линейным.
:::
