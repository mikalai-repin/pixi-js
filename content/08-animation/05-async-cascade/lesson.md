Обмен анимирован, а дальше всё по-прежнему происходит за один кадр: тройка исчезает, фишки оказываются внизу, сверху появляются новые. В главе 7 мы обещали «разрезать» каскад на шаги, между которыми проходят кадры. Сейчас сделаем это. И модель (`grid.ts`) при этом не изменится ни на строчку.

## Три анимации фишки

Сначала научим фишку исчезать и падать. В оригинале исчезновение — это прозрачность до нуля за 0,1 секунды, а падение — 0,5 секунды с отскоком. Добавьте в `Piece.ts`:

```ts Piece.ts
import { quadOut, singleBounce, tween } from './tween';
```

```ts Piece.ts
  /** Исчезновение: фишка становится прозрачной */
  async animatePop() {
    await tween(this.ticker, this, { alpha: 0 }, { duration: 0.1, ease: quadOut });
  }

  /** Падение в точку (x, y) с отскоком */
  async animateFall(x: number, y: number) {
    await tween(this.ticker, this, { x, y }, { duration: 0.5, ease: singleBounce });
  }
```

## Каскад как последовательность

Теперь главное. Синхронный `process` выглядел так:

```ts
while (matches.length > 0) {
  this.popMatches(matches);
  this.dropPieces();
  this.refillPieces();
  matches = getMatches(this.grid);
}
```

Если каждый из трёх методов вернёт промис, который выполняется по окончании своей анимации, то достаточно добавить `async` и `await`, и цикл растянется во времени. Между `await` браузер рисует кадры, тикер крутит твины, и игрок видит каждый этап.

Перепишем методы по одному.

**Исчезновение.** Модель меняется сразу, как и раньше. Но фишки уничтожаются только **после** анимации: в шаге 3 мы видели, что уничтожать объект под работающим твином нельзя.

```ts Board.ts {1-3,12,15-17}
  /** Убирает с поля фишки из совпадений: в модели сразу остаётся 0, фишки исчезают и уничтожаются */
  private async popMatches(matches: Position[][]) {
    const popped: Piece[] = [];
    for (const match of matches) {
      for (const position of match) {
        const piece = this.getPiece(position);
        // Клетка может входить сразу в два совпадения (уголком), и фишку уже убрали
        if (!piece) continue;
        if (piece === this.selected) this.select(null);
        setType(this.grid, position, 0);
        this.setPiece(position, null);
        popped.push(piece);
      }
    }
    // Все фишки исчезают одновременно, а уничтожаем их, когда анимация закончилась
    await Promise.all(popped.map((piece) => piece.animatePop()));
    for (const piece of popped) piece.destroy({ children: true });
  }
```

`Promise.all` запускает все анимации одновременно и ждёт, пока закончится самая долгая. Здесь они одинаковые, и все фишки тройки гаснут вместе.

**Падение.** Вместо мгновенной перестановки — `animateFall`:

```ts Board.ts {1-2,4,10-11,13}
  /** Роняет фишки на пустые клетки: модель меняется сразу, фишки падают плавно */
  private async dropPieces() {
    const moves = applyGravity(this.grid);
    const animations: Promise<void>[] = [];
    for (const [from, to] of moves) {
      const piece = this.getPiece(from);
      if (!piece) continue;
      this.setPiece(from, null);
      this.setPiece(to, piece);
      const view = this.getViewPosition(to);
      animations.push(piece.animateFall(view.x, view.y));
    }
    await Promise.all(animations);
  }
```

**Досыпание.** Новые фишки должны падать сверху, из-за края поля. Создаём их в клетке, как раньше, а потом переносим **выше поля** и роняем на место:

```ts Board.ts
  /** Создаёт новые фишки над полем и роняет их в пустые клетки */
  private async refillPieces() {
    const filled = fillUp(this.grid, TYPES);
    const animations: Promise<void>[] = [];
    // Сколько новых фишек уже появилось в каждом столбце: они встают друг над другом
    const perColumn = new Array<number>(COLUMNS).fill(0);
    for (const position of filled) {
      const piece = this.createPiece(position, this.grid[position.row][position.column]);
      perColumn[position.column]++;
      const view = this.getViewPosition(position);
      // Начинаем выше поля: маска слоя фишек их пока скрывает
      piece.y = -BOARD_HEIGHT / 2 - perColumn[position.column] * TILE_SIZE;
      animations.push(piece.animateFall(view.x, view.y));
    }
    await Promise.all(animations);
  }
```

Помните, что `fillUp` возвращает клетки **снизу вверх**? Вот зачем. Первая новая фишка в столбце займёт нижнюю из пустых клеток и стартует сразу над полем. Вторая займёт клетку выше и стартует ещё на клетку выше. Новые фишки столбца выстраиваются в колонну над полем в том же порядке, в каком лягут в клетки. Посчитайте: расстояние до цели у всех фишек колонны одинаковое, поэтому они падают одним блоком.

А маска, которую мы поставили на слой фишек ещё в главе 4, наконец пригодилась по-настоящему: пока фишки выше поля, их не видно, и они «въезжают» в поле из-за края.

**Сам каскад.** Осталось расставить `await`:

```ts Board.ts {1,6-9}
  private async process() {
    let round = 0;
    let matches = getMatches(this.grid);
    while (matches.length > 0) {
      round++;
      await this.popMatches(matches);
      // Старые фишки падают одновременно с новыми. dropPieces успевает изменить модель
      // до своего первого await, поэтому refillPieces уже видит пустые клетки наверху
      await Promise.all([this.dropPieces(), this.refillPieces()]);
      matches = getMatches(this.grid);
    }
    console.log(round > 1 ? `Комбо! Раундов каскада: ${round}` : 'Совпадение убрано');
  }
```

Падение старых фишек и досыпание новых идут **одновременно**, как в оригинале. Но тут есть тонкость. `refillPieces` должен увидеть модель **после** гравитации, иначе он заполнит дыры посреди поля, а не наверху. Это работает, потому что асинхронная функция до первого `await` выполняется синхронно, как обычная. `dropPieces()` вызывается первым и успевает выполнить `applyGravity`, прежде чем начнётся `refillPieces()`.

И последнее: в `onSwipe` каскада теперь нужно дождаться, иначе `processing` сбросится раньше времени:

```ts Board.ts
    if (valid) {
      await this.process();
    } else {
```

## Что получилось

Сделайте ход. Теперь игра выглядит как игра: фишки съезжаются, тройка гаснет, фишки над ней падают с отскоком, а сверху в поле въезжают новые. Если досыпанные фишки дали новую тройку, всё повторяется. Один раунд длится 0,6 секунды (0,1 на исчезновение и 0,5 на падение), а ход с комбо — больше секунды. Нажмите `3`, чтобы рассмотреть каскад в замедлении.

Пока каскад идёт, поле не принимает ходы. Проверка в браузере подтвердила: после восьми ходов подряд модель и вид совпадают, все 63 фишки на своих местах и непрозрачны, а свайпы во время анимации игнорируются.

Загляните в `grid.ts`: он не изменился с главы 7. Вся анимация живёт в виде, а модель по-прежнему меняется мгновенно и всегда правильна.

## Эксперименты

- Поменяйте местами `this.dropPieces()` и `this.refillPieces()` в `Promise.all`. Теперь `fillUp` видит дыры там, где была тройка, и новые фишки падают **сквозь** старые прямо в эти дыры. Игра остаётся правильной (модель согласована), но выглядит нелепо. Порядок вызовов важен, даже когда анимации идут параллельно.
- Временно уберите маску: в конструкторе `Board` замените строку `this.piecesContainer.mask = mask;` на `mask.visible = false;`. Новые фишки становятся видны над полем, пока падают к нему. Верните маску.

  Почему не просто удалить строку? Попробуйте: поле закроет белый прямоугольник. Это сама графика маски. Пока она назначена маской, PixiJS её не рисует, а как обычный дочерний объект она рисуется, как любая другая графика.
- Поменяйте `duration` падения на `1`. Каскад становится медленным и тягучим. Подбор длительностей — важная часть того, насколько «приятно» играть, и в оригинале все они меньше полсекунды.

::: deep Под капотом: AsyncQueue в оригинале
Оригинальный `Match3Process` устроен немного иначе: шаги раунда кладутся в **очередь асинхронных функций** `AsyncQueue` (файл `utils/asyncUtils.ts`). Очередь выполняет функции по одной, дожидаясь каждой. В конце раунда шаг «контрольная точка» проверяет, остались ли совпадения или пустые клетки, и если да, кладёт в очередь ещё один раунд.

По сути это наш цикл `while` с `await`, только разложенный на отдельные объекты. Зачем? Очередь можно **поставить на паузу** между шагами (`queue.pause()`) и **очистить** (`queue.clear()`), например при выходе из игры посреди каскада. Наш `process` так не умеет: если сейчас нажать паузу посреди каскада, анимации доиграют до конца. Настоящую паузу мы сделаем в главе 11.

Ещё одно отличие: в оригинале блокируются не все фишки, а только те, что сейчас анимируются (`Match3Piece.lock()`). Игрок может делать ходы в спокойной части поля, пока в другой идёт каскад. Это сложнее: процесс и действия игрока должны аккуратно делить модель. Мы выбрали простой путь — блокировать всё поле.
:::
