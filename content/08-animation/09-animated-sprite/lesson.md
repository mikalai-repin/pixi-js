Все наши анимации до сих пор меняли **свойства** объекта: позицию, масштаб, поворот, прозрачность. Картинка при этом оставалась той же. Но есть и другой вид анимации, самый старый, как в мультфильмах: **покадровая анимация**. Есть набор картинок-кадров, и они быстро сменяют друг друга. Так анимируют бег персонажа, взрыв, пламя, мерцание монеты.

В PixiJS для этого есть класс `AnimatedSprite`. Применим его к делу: перед началом игры покажем обратный отсчёт 5, 4, 3, 2, 1, а поле пусть до конца отсчёта будет заблокировано.

## Кадры

В атласе `game` есть текстуры `num-stroke-1` … `num-stroke-5`: белые контуры цифр. В оригинале они появляются в последние пять секунд игры. Для нас это пять кадров анимации:

```ts
const textures = [5, 4, 3, 2, 1].map((digit) => Texture.from(`num-stroke-${digit}`));
```

`AnimatedSprite` — это обычный `Sprite`, который умеет сам менять свою текстуру по списку. Всё, что вы знаете о спрайтах (якорь, позиция, тонирование), работает и здесь:

```ts
const countdown = new AnimatedSprite({
  textures,
  anchor: 0.5,
  tint: 0xffd27f,
  // Кадров анимации за один кадр тикера: 1/60 — одна цифра в секунду при 60 FPS
  animationSpeed: 1 / 60,
  loop: false,
});
```

- **`textures`** — массив кадров;
- **`animationSpeed`** — скорость смены кадров, по умолчанию `1`. Единица измерения непривычная: на сколько кадров анимации продвинуться за `deltaTime = 1`, то есть за один кадр при 60 FPS. `1` — новая картинка каждый кадр экрана, 60 картинок в секунду. `0.1` — 6 картинок в секунду. Нам нужна одна цифра в секунду, значит `1 / 60`. Так как сдвиг умножается на `deltaTime`, скорость не зависит от частоты кадров;
- **`loop`** — повторять ли анимацию по кругу. По умолчанию `true`, а отсчёт должен закончиться;
- **`tint`** — цифры белые, красим их в золотой цвет рамки поля.

Анимация сама не запускается: по умолчанию `autoPlay` равен `false`. Запускает её метод `play()`, останавливает `stop()`, а `gotoAndPlay(n)` и `gotoAndStop(n)` переходят к кадру с номером `n`.

## События анимации

У `AnimatedSprite` три колбэка:

- **`onFrameChange(currentFrame)`** — сменился кадр;
- **`onComplete()`** — анимация дошла до конца. Только при `loop: false`;
- **`onLoop()`** — анимация пошла на новый круг. Только при `loop: true`.

`onComplete` — именно то, что нужно, чтобы узнать, когда отсчёт закончился. Завернём его в промис, как делали с твинами, и тогда отсчёт можно будет ждать через `await`.

## Отсчёт

Добавьте в `main.ts` после создания поля и отладочных клавиш, перед кнопкой паузы:

```ts main.ts
import { AnimatedSprite, Application, Assets, Sprite, Texture } from 'pixi.js';
```

```ts main.ts
// --- Обратный отсчёт: пока он идёт, поле заблокировано ---
board.locked = true;
board.alpha = 0.5;
await playCountdown();
board.locked = false;
board.alpha = 1;

/** Цифры 5, 4, 3, 2, 1 в центре экрана, по секунде на каждую. Промис выполняется в конце отсчёта */
function playCountdown() {
  const textures = [5, 4, 3, 2, 1].map((digit) => Texture.from(`num-stroke-${digit}`));
  const countdown = new AnimatedSprite({
    textures,
    anchor: 0.5,
    tint: 0xffd27f,
    // Кадров анимации за один кадр тикера: 1/60 — одна цифра в секунду при 60 FPS
    animationSpeed: 1 / 60,
    loop: false,
  });
  countdown.position.set(app.screen.width / 2, app.screen.height / 2);
  app.stage.addChild(countdown);

  // Каждая новая цифра выпрыгивает из большого размера
  const jump = () => gsap.fromTo(countdown.scale, { x: 1.6, y: 1.6 }, { x: 1, y: 1, duration: 0.4, ease: 'back.out' });
  countdown.onFrameChange = jump;
  jump();

  return new Promise<void>((resolve) => {
    countdown.onComplete = () => {
      gsap.killTweensOf(countdown.scale);
      countdown.destroy();
      resolve();
    };
    countdown.play();
  });
}
```

Разберём новое:

- **`gsap.fromTo(target, from, to)`** — как `gsap.to`, но начальные значения задаются явно. Каждую новую цифру мы сначала делаем в 1,6 раза больше, а потом за 0,4 секунды упруго уменьшаем до нормального размера;
- **`jump()` вручную для первой цифры** — `onFrameChange` вызывается при **смене** кадра, а первая цифра никакой смены не вызывает;
- **`killTweensOf` перед `destroy`** — правило из шага 3: не уничтожать объект под работающим твином. Сейчас последний «прыжок» давно закончился, но код не должен на это полагаться;
- **`board.alpha = 0.5`** — полупрозрачное поле, как на паузе: и видно, что играть пока нельзя, и цифры читаются лучше.

Функция объявлена ниже места вызова. Это нормально: объявления функций в JavaScript поднимаются (hoisting) и доступны во всём модуле.

## Что получилось

После загрузки поверх полупрозрачного поля появляются золотые цифры: 5, 4, 3, 2, 1. Каждая выпрыгивает из большого размера. Через пять секунд отсчёт исчезает, поле становится ярким, и можно играть. Кнопка паузы появляется после отсчёта: её код в `main.ts` идёт после `await playCountdown()`.

Мы проверили: во время отсчёта поле заблокировано, у анимации 5 кадров, поле разблокируется примерно через 5,4 секунды после запуска кода (загрузка и пять цифр), а после отсчёта на сцене остаются только фон, поле и кнопка паузы.

## Эксперименты

- `animationSpeed: 1 / 30` — по две цифры в секунду, и весь отсчёт занимает 2,5 секунды;
- нажмите `3` сразу после запуска: фон замедлился, «прыжки» цифр тоже (это GSAP, его мы замедлили в прошлом шаге), а сами цифры меняются раз в секунду, как прежде. Почему — в блоке «Под капотом»;
- поставьте `loop: true`. Отсчёт пойдёт по кругу бесконечно: `onComplete` при повторе не вызывается, промис не выполнится, и поле не разблокируется никогда. Мы проверили: через 9 секунд поле всё ещё заблокировано.

::: deep Под капотом: AnimatedSprite и тикер
`AnimatedSprite` с настройками по умолчанию (`autoUpdate: true`) при `play()` подписывается не на `app.ticker`, а на общий **`Ticker.shared`**, с приоритетом `HIGH`. Это отдельный тикер, поэтому `app.ticker.speed` и `maxFPS` на него не действуют. Если нужно, чтобы покадровые анимации слушались тикера приложения, создайте спрайт с `autoUpdate: false` и вызывайте его `update(ticker)` сами: `app.ticker.add((ticker) => countdown.update(ticker))`.

Каждый кадр `update` прибавляет к внутреннему счётчику `animationSpeed × deltaTime`, а номер кадра — это целая часть счётчика. Когда номер меняется, спрайт меняет текстуру. Можно задать и разную длительность кадрам: вместо массива текстур передать массив объектов `{ texture, time }`, где `time` — длительность кадра в миллисекундах.

Где брать кадры в настоящих проектах? Обычно их кладут в атлас, а в его JSON добавляют поле `animations` со списками кадров. После загрузки такого атласа готовые массивы текстур лежат в `spritesheet.animations['имя']`. В ресурсах Puzzling Potions покадровых анимаций нет: персонажей (дракона и котёл) оригинал анимирует **скелетной анимацией** Spine, о ней — в главе 14.
:::

## Итоги главы

Поле ожило. Теперь вы знаете:

- **тикер** вызывает функции каждый кадр, а `deltaTime`, `deltaMS` и `elapsedMS` говорят, сколько прошло времени. Скорость всегда считается от времени, а не от кадров;
- `maxFPS`, `minFPS` и `speed` управляют течением времени, и наши отладочные клавиши позволяют рассматривать анимации в замедлении;
- **твин** — это интерполяция между началом и концом с функцией плавности. Его удобно оформлять промисом;
- **функции плавности** (`quadOut`, `backOut`, отскок) превращают механическое движение в живое;
- **каскад** стал асинхронной последовательностью: каждый этап ждёт своей анимации, а модель по-прежнему меняется мгновенно;
- **`onRender`** — функция «жизни» объекта, которая сама отключается, когда объект уходит со сцены;
- **`TilingSprite`** заполняет любую область повторяющимся узором, а `tilePosition` заставляет его плыть;
- **GSAP** делает то же, что наш твин, и гораздо больше. Не забывайте про `killTweensOf` и про то, что у GSAP свой тикер;
- **`AnimatedSprite`** показывает покадровую анимацию.

Но в игре до сих пор нет ни одной надписи: ни счёта, ни таймера, ни «Комбо!». В следующей главе займёмся текстом: `Text`, стили, свои шрифты, `BitmapText` и всплывающие очки.
