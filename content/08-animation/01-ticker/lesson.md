Логика игры готова, но выглядит она как набор мгновенных скачков. Фишки меняются местами за один кадр, тройки исчезают за один кадр, новые зелья появляются ниоткуда. В этой главе мы займёмся **временем**. К её концу фишки будут плавно съезжаться, лопаться, падать с отскоком, а каскад растянется на несколько секунд, как в настоящей игре. Ещё будет плывущий фон и обратный отсчёт перед стартом.

Сначала о том, что изменилось в коде. Юнит-тесты из практикума прошлой главы мы убрали: файл `tests.ts` и его вызов в `main.ts`. Логика сетки в этой главе не изменится ни на строчку, и тесты ей больше не нужны. Всё остальное — ровно решение главы 7.

## Тикер ещё раз

С тикером вы встречались с первой главы: фон переливался, зелье вращалось, рамка выбора пульсирует. Вспомним главное. **Тикер** (`Ticker`) — это объект, который каждый кадр вызывает подписанные на него функции. Кадр начинается, когда браузер готов перерисовать страницу: обычно 60 раз в секунду, на мониторах 120 Гц — 120 раз. У приложения есть свой тикер `app.ticker`, и на него же подписана отрисовка сцены.

Теперь разберём его подробнее, потому что вся анимация в играх строится на нём. Подписка выглядит так:

```ts
ticker.add(fn, context, priority);
```

- **`fn`** — функция. Каждый кадр она получает сам тикер, а у него есть все данные о времени;
- **`context`** — чем будет `this` внутри `fn`. Это нужно, когда в тикер передаётся метод класса: `ticker.add(this.update, this)`. Можно было бы написать стрелочную функцию, но тогда для отписки её пришлось бы где-то хранить;
- **`priority`** — порядок вызова. Его разберём в следующем шаге.

Отписка — `ticker.remove(fn, context)` с теми же аргументами. Если не отписаться, тикер будет вызывать функцию вечно, даже для уничтоженного объекта. Поэтому `LoadScreen` и `Board` отписываются в переопределённом методе `destroy`.

## Три способа измерить время

У тикера три свойства о том, сколько времени прошло с прошлого кадра:

| Свойство | Единицы | Что это |
|---|---|---|
| `deltaTime` | кадры при 60 FPS | При 60 FPS около `1`, при 120 FPS около `0.5`, при 30 FPS около `2` |
| `deltaMS` | миллисекунды | То же время в миллисекундах. Ровно `deltaTime / 0.06` |
| `elapsedMS` | миллисекунды | «Сырое» время между кадрами, без поправок |

`deltaTime` и `deltaMS` — одно и то же время в разных единицах. Выбирайте то, в чём удобнее задавать скорость: «0.03 радиана за кадр» или «1.8 радиана в секунду». А `elapsedMS` отличается от `deltaMS` поправками: тикер умеет ограничивать слишком большие паузы и замедлять время. О поправках поговорим в следующем шаге, а пока они совпадают.

Ещё есть `lastTime` — отметка времени в миллисекундах с момента загрузки страницы. Её удобно подставлять в `Math.sin`, если нужно колебание. Так вы делали покачивание зелья в главе 2.

## Вращающаяся подсветка

В оригинальной Puzzling Potions у выбранной фишки подсветка медленно вращается, а само зелье покачивается. Сделаем так же. Пусть каждая фишка сама подписывается на тикер. Для этого `Piece` будет получать тикер в конструкторе:

```ts Piece.ts {1,3-4}
import { Container, FederatedPointerEvent, Rectangle, Sprite, Texture, Ticker, type DestroyOptions } from 'pixi.js';
// …
/** Скорость вращения подсветки: радиан за кадр при 60 FPS */
const HIGHLIGHT_SPEED = 0.03;
```

```ts Piece.ts {1,6}
  constructor(textureName: string, size: number, private readonly ticker: Ticker) {
    super();
    // … всё, что было
    this.on('pointercancel', this.onPointerUp, this);

    this.ticker.add(this.update, this);
  }
```

Сам метод `update` и отписка:

```ts Piece.ts {4-5,8-13,15-19}
  /** Включает или выключает подсветку */
  setHighlight(enabled: boolean) {
    this.highlight.visible = enabled;
    // Без подсветки зелье стоит ровно
    if (!enabled) this.image.rotation = 0;
  }

  /** Каждый кадр: у выбранной фишки вращается подсветка и покачивается зелье */
  private update(ticker: Ticker) {
    if (!this.highlight.visible) return;
    this.highlight.rotation += HIGHLIGHT_SPEED * ticker.deltaTime;
    this.image.rotation = Math.sin(ticker.lastTime * 0.01) * 0.1;
  }

  /** Уничтоженная фишка не должна оставаться в тикере */
  override destroy(options?: DestroyOptions) {
    this.ticker.remove(this.update, this);
    super.destroy(options);
  }
```

Разберём:

- **`if (!this.highlight.visible) return`** — у невыбранной фишки подсветка скрыта, и делать ничего не нужно. Функция всё равно вызывается каждый кадр, но выходит сразу;
- **вращение** — `rotation` растёт на `0.03 × deltaTime` за кадр. При 60 FPS это 1,8 радиана в секунду, полный оборот примерно за 3,5 секунды;
- **покачивание** — синус от времени даёт колебание от −0.1 до 0.1 радиана (около ±6°). Период — `2π / 0.01 ≈ 628` миллисекунд;
- **`setHighlight(false)`** возвращает зелье в ровное положение. Иначе снятая с выбора фишка так и застыла бы наклонённой.

Осталось передать тикер при создании фишки в `Board.ts`:

```ts Board.ts
    const piece = new Piece(name, TILE_SIZE, this.ticker);
```

::: task
Передайте в `Piece` тикер, подпишите фишку на него и вращайте подсветку выбранной фишки. Не забудьте отписаться в `destroy`.
:::

## Что получилось

Выберите любую фишку. Под увеличенным зельем медленно вращается звезда подсветки, а само зелье покачивается из стороны в сторону. Выберите другую фишку: первая перестанет качаться и встанет ровно.

Мы проверили автоматически: за секунду подсветка поворачивается на 1,8 радиана.

Теперь в тикере 65 слушателей: 63 фишки, пульсация рамки в `Board` и отрисовка сцены. Сделайте пару ходов: фишки уничтожаются и создаются, а слушателей остаётся 65. Это работает отписка в `destroy`. Без неё каждый ход добавлял бы новых слушателей, а старые продолжали бы крутить подсветку уничтоженных фишек. Мы проверили: если убрать отписку, после пяти ходов слушателей уже 109. Проверьте сами: выведите в консоль `app.ticker.count` после нескольких ходов с отпиской и без неё.

## Эксперимент: сколько длится кадр

Добавьте в конец `main.ts` функцию, которая раз в секунду выводит данные тикера:

```ts main.ts
let timer = 0;
app.ticker.add((ticker) => {
  timer += ticker.elapsedMS;
  if (timer < 1000) return;
  timer = 0;
  console.log(
    `deltaTime: ${ticker.deltaTime.toFixed(2)}, deltaMS: ${ticker.deltaMS.toFixed(1)}, ` +
      `elapsedMS: ${ticker.elapsedMS.toFixed(1)}, FPS: ${ticker.FPS.toFixed(0)}`,
  );
});
```

На мониторе 60 Гц вы увидите примерно `deltaTime: 1.00, deltaMS: 16.7, elapsedMS: 16.7, FPS: 60`. На 120 Гц — `0.50`, `8.3`, `8.3` и `120`. `FPS` — это просто `1000 / elapsedMS`, частота кадров, посчитанная по последнему кадру.

После эксперимента уберите этот код: в следующих шагах он будет мешать в консоли.

::: deep Под капотом: откуда берутся кадры
Тикер работает на `requestAnimationFrame` — функции браузера, которая вызывает колбэк перед следующей перерисовкой страницы и передаёт ему отметку времени. На каждом таком вызове тикер:

1. вычитает из текущего времени время прошлого кадра — это `elapsedMS`;
2. применяет поправки и получает `deltaMS`, а из него `deltaTime = deltaMS × 0.06` (0.06 — это 60 кадров на 1000 миллисекунд, `Ticker.targetFPMS`);
3. по очереди вызывает слушателей. Они хранятся в связном списке, отсортированном по приоритету;
4. запрашивает следующий кадр.

Если у тикера нет ни одного слушателя, следующий кадр он не запрашивает и фактически засыпает. А вкладку в фоне браузер вообще перестаёт перерисовывать, и `requestAnimationFrame` не вызывается. Что будет с `deltaTime`, когда вкладка снова станет активной, разберём в следующем шаге.
:::
