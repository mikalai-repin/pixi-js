Каждая фишка подписывается на тикер в конструкторе и отписывается в `destroy`. `Board` делает то же самое для пульсации рамки, `LoadScreen` — для мигающей точки. Это работает, но приходится помнить про отписку. Забыли — и тикер вечно вызывает функцию уничтоженного объекта, как мы видели в шаге 1: после пяти ходов без отписки в тикере было 109 слушателей вместо 65.

У каждого контейнера в PixiJS v8 есть способ проще: свойство **`onRender`**.

## Что такое `onRender`

```ts
container.onRender = (renderer) => {
  // вызывается перед каждой отрисовкой, пока объект в дереве сцены
};
```

Функция в `onRender` вызывается **каждый кадр перед отрисовкой**, но только пока объект находится в дереве сцены. Добавили объект на сцену — функция начала вызываться. Сняли со сцены или уничтожили — перестала. Отписываться не нужно. Чтобы выключить её вручную, присвойте `onRender = null`.

Отличия от `ticker.add`:

| | `ticker.add(fn)` | `container.onRender = fn` |
|---|---|---|
| Когда вызывается | Каждый кадр тикера | Каждый кадр, когда рисуется сцена с этим объектом |
| Объект не на сцене | Всё равно вызывается | Не вызывается |
| Отписка | Вручную, `ticker.remove` | Сама, при снятии со сцены и уничтожении |
| Сколько функций | Сколько угодно | Одна на объект |
| Аргумент | Тикер: `deltaTime`, `deltaMS` | Рендерер, о времени ничего не знает |

Последняя строка важна: в `onRender` нет `deltaTime`. Время придётся брать у тикера, поэтому фишка по-прежнему хранит ссылку на него. В оригинале фишки берут время у глобального `app.ticker`: `this.highlight.rotation += app.ticker.deltaTime * 0.03`.

## Переводим фишку

В `Piece.ts` замените подписку на тикер:

```ts Piece.ts {2}
    // Вызывается перед каждой отрисовкой, пока фишка находится в дереве сцены
    this.onRender = () => this.update();
```

`update` больше не получает тикер аргументом, а берёт его из поля:

```ts Piece.ts {1,3-4}
  private update() {
    if (!this.highlight.visible) return;
    this.highlight.rotation += HIGHLIGHT_SPEED * this.ticker.deltaTime;
    this.image.rotation = Math.sin(this.ticker.lastTime * 0.01) * 0.1;
  }
```

А переопределённый `destroy` можно удалить целиком: отписываться больше не от чего. Уберите и `DestroyOptions` из импорта.

То же самое сделайте в `Board.ts` с пульсацией рамки. Удобнее всего повесить `onRender` на саму рамку `selection`:

```ts Board.ts
    this.selection.onRender = () => this.pulseSelection();
```

```ts Board.ts {1,3}
  private pulseSelection() {
    if (!this.selected) return;
    this.time += this.ticker.deltaMS / 1000;
```

И тоже удалите `destroy` с отпиской и `DestroyOptions` из импорта.

## Что получилось

Внешне ничего не изменилось: подсветка вращается, рамка пульсирует, ходы анимируются. Зато код стал короче и надёжнее: забыть отписку теперь невозможно.

Убедитесь, что слушатели действительно ушли из тикера. Добавьте в `main.ts` после создания поля:

```ts main.ts
console.log('Слушателей тикера:', app.ticker.count);
```

В прошлом шаге там было бы 65: 63 фишки, рамка и отрисовка. Теперь — 1, только отрисовка сцены. Во время хода число ненадолго вырастет: каждый наш твин — это временный слушатель тикера.

## Невидимый — не значит «не на сцене»

Обратите внимание на первую строку `update`: `if (!this.highlight.visible) return`. Она по-прежнему нужна. `onRender` вызывается для всех объектов в дереве сцены, **в том числе невидимых**: с `visible = false`, с `alpha = 0` и внутри невидимого родителя. Мы проверили это экспериментом: функция в `onRender` невидимого контейнера вызывалась 60 раз в секунду, так же как у видимого. А у снятого со сцены — ни разу.

Поэтому дешёвая проверка в начале `onRender` — хорошая привычка: 63 вызова в кадр, которые сразу выходят, ничего не стоят, но тяжёлую работу для невидимых объектов делать незачем.

## Когда что использовать

- **`onRender`** — для «жизни» конкретного объекта: вращение, покачивание, пульсация, движение фона. Всё, что должно происходить, только пока объект на экране. Так в оригинале сделаны фишки, фон, котёл, облака и эффекты.
- **`ticker.add`** — для логики, которая не привязана к одному объекту: игровой таймер, физика, твины, проверки по времени. И для всего, что должно работать, даже когда объекта на сцене нет.

::: deep Под капотом: где вызывается onRender
Присваивание `onRender` регистрирует объект в списке его **рендер-группы** — того корневого контейнера, который рендерер обновляет целиком (обычно это `app.stage`). При добавлении объекта в дерево сцены он попадает в этот список, при снятии — удаляется из него.

Во время отрисовки рендерер для каждой рендер-группы сначала вызывает все функции из её списка, потом обновляет трансформации и собирает команды для видеокарты. Отрисовка сама вызывается из тикера с приоритетом `LOW`. Поэтому порядок в кадре такой:

1. слушатели тикера с приоритетом `NORMAL` (ваши функции и твины);
2. функции `onRender` всех объектов на сцене;
3. обновление трансформаций и отрисовка.

Мы проверили порядок экспериментом: слушатель `ticker.addOnce` сработал раньше `onRender` в том же кадре. Значит, изменения, сделанные в `onRender`, попадают на экран в том же кадре, без задержки.

Одна тонкость: если у самой `app.stage` поставить `visible = false`, рендерер выходит сразу, и `onRender` не вызывается ни у кого.
:::
