Вокруг поля пусто: однотонный тёмный фон. В оригинальной Puzzling Potions за всеми экранами медленно плывёт узор из силуэтов колб. Он почти незаметен, но делает экран живым. Сделаем такой же.

В редакторе появилась вкладка `Background.ts` с заготовкой класса. Больше ничего не менялось.

## Картинка, которая повторяется

В бандле `preload` есть текстура `background`: белый квадрат 280 × 300 с четырьмя светло-серыми колбами. Края у неё однотонно белые, поэтому, если положить две такие картинки рядом, шва не видно. Нужно замостить ею весь экран.

Можно было бы создать сетку спрайтов, но её пришлось бы пересоздавать при смене размера окна, а при движении узора — переставлять спрайты, ушедшие за край. Для этой задачи в PixiJS есть специальный класс — **повторяющийся спрайт** `TilingSprite`. Это прямоугольная область заданного размера, которую текстура заполняет **узором**, повторяясь бесконечно во все стороны.

```ts
const sprite = new TilingSprite({ texture, width: 500, height: 600 });
```

Главное отличие от обычного спрайта: `width` и `height` у `TilingSprite` — **размер области**, а не масштаб картинки. Увеличили `width` — узор не растянулся, а показал больше повторений. Масштаб самого объекта (`scale`) при этом остаётся равным 1.

А чтобы управлять узором внутри области, у `TilingSprite` есть отдельная трансформация **`tileTransform`**:

| Свойство | Что делает |
|---|---|
| `tilePosition` | Сдвиг узора внутри области. Меняете каждый кадр — узор плывёт, а сам спрайт стоит на месте |
| `tileScale` | Масштаб узора: колбы крупнее или мельче |
| `tileRotation`, `tileTransform.rotation` | Поворот узора. Сама область остаётся прямоугольной и неподвижной |

## Класс фона

Сделаем `Background` наследником `TilingSprite`, как оригинальный `TiledBackground`:

```ts Background.ts
  constructor(private readonly ticker: Ticker) {
    // Текстура белая, с чуть более серыми зельями: тонированием красим её в сиреневый
    super({ texture: Texture.from('background'), tint: 0xa58fd0 });
    // Поворачиваем не сам спрайт, а узор внутри него
    this.tileTransform.rotation = DIRECTION;
    this.onRender = () => this.update();
  }
```

- **`tint`** — текстура белая, потому что в оригинале фон приложения белый. У нас он тёмный, поэтому красим узор тонированием из главы 2: белое становится сиреневым, а серые колбы — чуть темнее;
- **поворот узора** — колбы стоят под углом `−π × 0.15`, то есть на 27° против часовой стрелки, как в оригинале;
- **`onRender`** из прошлого шага — фон живёт, пока он на сцене.

Размер области задаём снаружи, потому что фон должен совпадать с экраном:

```ts Background.ts
  /** Растягивает фон на весь экран */
  resize(width: number, height: number) {
    // У TilingSprite ширина и высота — размер области, а не масштаб картинки
    this.width = width;
    this.height = height;
  }
```

И движение:

```ts Background.ts
  /** Каждый кадр сдвигает узор */
  private update() {
    const distance = SPEED * this.ticker.deltaTime;
    // Вектор «вверх», повёрнутый на DIRECTION: узор плывёт вдоль своих столбиков
    this.tilePosition.x += Math.sin(DIRECTION) * distance;
    this.tilePosition.y -= Math.cos(DIRECTION) * distance;
  }
```

Узор должен плыть «вверх» вдоль своих наклонённых столбиков колб, а не строго вверх по экрану. Направление «вверх» — это вектор `(0, −1)`. Повёрнутый на угол `a`, он становится `(sin a, −cos a)`: при `a = 0` получаем `(0, −1)`, а при нашем отрицательном угле `x` тоже становится отрицательным, и узор уходит вверх-влево. Умножаем вектор на путь за кадр — получаем сдвиг. В оригинальном `TiledBackground` та же формула записана через `-this.direction`.

## Фон на сцене

В `main.ts` фон создаётся сразу после загрузки бандла `preload`, где лежит его текстура, и добавляется на сцену **первым**. Порядок детей — это порядок отрисовки, так что всё остальное окажется поверх фона:

```ts main.ts
import { Background } from './Background';
```

```ts main.ts {3-8}
await Assets.loadBundle('preload');

// Фон под всеми остальными объектами: добавляем его на сцену первым
const background = new Background(app.ticker);
background.resize(app.screen.width, app.screen.height);
app.stage.addChild(background);
// Рендерер сообщает о смене размера экрана событием resize
app.renderer.on('resize', (width, height) => background.resize(width, height));
```

С `resizeTo: window` приложение само меняет размер canvas при изменении окна, а рендерер при этом генерирует событие `resize` с новыми шириной и высотой экрана. Подписываемся на него, чтобы фон всегда закрывал экран целиком. Остальные объекты пока остаются на старых местах: полноценную адаптивность сделаем в главе 10.

## Что получилось

Вокруг поля и под экраном загрузки медленно плывёт вверх-влево сиреневый узор из колб. Скорость — 1 пиксель за кадр при 60 FPS, то есть 60 пикселей в секунду: проверка показала, что за секунду узор сдвигается на (−27, −54), а это ровно 60 пикселей по наклонной. Поменяйте размер превью, потянув границу панели: фон подстраивается под новый размер.

Попробуйте отладочные клавиши: `2` (20 FPS) не меняет скорость узора, а `3` замедляет его вместе со всем остальным. Фон берёт время у `app.ticker`.

## Эксперименты

- `this.tileScale.set(0.5)` в конструкторе — колбы вдвое мельче, а повторений вчетверо больше. Попробуйте `2`;
- уберите поворот узора: колбы встанут ровно, а узор поплывёт вверх-влево наискосок, «поперёк» столбиков. Поверните обратно;
- поставьте `this.rotation = DIRECTION` вместо `tileTransform.rotation`: повернётся **вся область**, и в углах экрана появятся пустые треугольники. Вот зачем у `TilingSprite` отдельная трансформация узора.

::: deep Под капотом: как видеокарта повторяет текстуру
У видеокарты есть встроенный режим повторения текстуры (`addressMode: 'repeat'`): если запросить пиксель за пределами картинки, она берёт его с другого края. С ним `TilingSprite` — это просто прямоугольник с «растянутыми» текстурными координатами, и его можно рисовать в общем батче вместе с обычными спрайтами.

Но этот режим работает только для **целой** текстуры. Наша `background` лежит в атласе `preload` рядом с логотипом и кругом, и «повторение» атласа показало бы соседние картинки. Поэтому для текстур из атласа PixiJS включает специальный шейдер, который сам заворачивает координаты внутри прямоугольника кадра. Мы проверили это по исходникам: `TilingSpritePipe` проверяет, занимает ли текстура весь источник (`textureMatrix.isSimple`), и если нет, прерывает батч и рисует фон отдельным вызовом отрисовки.

Для одного фона это неважно. Но если повторяющихся спрайтов много, их текстуры лучше хранить отдельными файлами, а не в атласе.
:::
