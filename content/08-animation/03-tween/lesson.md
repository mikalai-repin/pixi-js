Вращение и пульсация — бесконечные анимации: они идут, пока фишка выбрана. Но в игре нужен и другой вид: «переместить фишку из клетки A в клетку B за 0,2 секунды и сообщить, когда закончилось». Такая анимация с началом и концом называется **твином** (tween, от английского in-between — «промежуточное»). Сегодня напишем свой твин с нуля, а в шаге 8 сравним его с библиотекой GSAP, которой пользуется оригинал.

В редакторе появилась вкладка `tween.ts` с заготовкой. Больше ничего не менялось.

## Интерполяция

Чтобы фишка плавно переехала из `x = 0` в `x = 100`, каждый кадр нужно знать, где она должна быть **сейчас**. Если прошла четверть времени — на четверти пути, если половина — на середине. Значение между двумя точками по доле `t` от 0 до 1 вычисляет **линейная интерполяция**, коротко **lerp** (linear interpolation):

```ts tween.ts
export function lerp(a: number, b: number, t: number) {
  return a + (b - a) * t;
}
```

`lerp(0, 100, 0.25)` — это 25, `lerp(0, 100, 1)` — 100. А `lerp(100, 0, 0.25)` — 75: движение может идти и в обратную сторону.

Значит, твину нужно каждый кадр:

1. посчитать долю прошедшего времени `t = прошло / длительность`;
2. для каждого анимируемого свойства записать `lerp(начало, конец, t)`;
3. когда `t` дошла до 1 — отписаться от тикера и сообщить о конце.

## Твин как промис

«Сообщить о конце» удобнее всего промисом. Тогда анимации можно ждать через `await` и запускать параллельно через `Promise.all`, а код, который должен выполниться **после** анимации, просто идёт следующей строкой.

Посмотрите на сигнатуру в заготовке:

```ts tween.ts
export function tween<T extends object, K extends keyof T>(
  ticker: Ticker,
  target: T,
  to: Record<K, number>,
  { duration, ease = linear }: TweenOptions,
) {
```

- **`target`** — что анимируем, например фишку;
- **`to`** — конечные значения свойств: `{ x: 100, y: 50 }`. TypeScript проверит, что такие свойства у `target` есть. Опечатка `{ z: 100 }` не скомпилируется;
- **`duration`** — длительность в секундах, как в GSAP;
- **`ease`** — функция плавности. Пока это `linear`, то есть `t` без изменений. В следующем шаге здесь начнётся самое интересное.

Реализация:

```ts tween.ts
  // Внутри работаем с объектами как со словарями чисел: типы уже проверила сигнатура
  const values = target as Record<string, number>;
  const end = to as Record<string, number>;
  const start: Record<string, number> = {};
  for (const key in end) start[key] = values[key];

  let elapsed = 0;
  return new Promise<void>((resolve) => {
    const update = () => {
      elapsed += ticker.deltaMS / 1000;
      // Доля прошедшего времени от 0 до 1
      const t = Math.min(elapsed / duration, 1);
      const k = ease(t);
      for (const key in end) values[key] = lerp(start[key], end[key], k);
      if (t === 1) {
        ticker.remove(update);
        resolve();
      }
    };
    ticker.add(update);
  });
}
```

Обратите внимание:

- **начальные значения запоминаются в момент вызова**, а не в конструкторе фишки. Твин стартует оттуда, где объект находится сейчас;
- **время копится из `deltaMS`**, поэтому твин уважает и частоту кадров, и замедление из прошлого шага;
- **`Math.min(…, 1)`** — последний кадр почти никогда не попадает ровно в конец. Если твин длится 200 мс, а кадры идут по 17 мс, после 12 кадров пройдёт 204 мс. Без ограничения `t` стал бы 1,02, и фишка чуть-чуть проскочила бы цель;
- **отписка внутри `update`** безопасна: тикер умеет удалять слушателя прямо во время вызова.

## Анимированный обмен

Теперь используем твин. В `Piece.ts` добавьте метод:

```ts Piece.ts
import { tween } from './tween';
```

```ts Piece.ts
  /** Плавно перемещает фишку в точку (x, y) внутри поля */
  async animateMove(x: number, y: number) {
    await tween(this.ticker, this, { x, y }, { duration: 0.2 });
  }
```

А в `Board.ts` три изменения. Первое: `setPiece` больше **не двигает** фишку, а только записывает её в клетку. Двигать будем отдельно — мгновенно или плавно, в зависимости от ситуации:

```ts Board.ts
  /** Записывает фишку в клетку: в массив pieces и в её row и column. На экране фишку не двигает */
  private setPiece(position: Position, piece: Piece | null) {
    this.pieces[position.row * COLUMNS + position.column] = piece;
    if (!piece) return;
    piece.row = position.row;
    piece.column = position.column;
  }
```

Поэтому в `createPiece` и `dropPieces` после `setPiece` нужна строка, которая ставит фишку на место мгновенно, как раньше:

```ts Board.ts
    piece.position.copyFrom(this.getViewPosition(position)); // в createPiece
    piece.position.copyFrom(this.getViewPosition(to)); // в dropPieces, внутри цикла
```

В `dropPieces` `getPiece` возвращает `Piece | null`, поэтому перед этим добавьте проверку `if (!piece) continue;`.

Второе: `swap` становится асинхронным. Модель меняется сразу, а фишки плавно едут на новые места:

```ts Board.ts {1-2,5,9-12}
  /** Меняет местами две фишки: в модели сразу, на экране — плавно */
  private async swap(a: Position, b: Position) {
    const pieceA = this.getPiece(a);
    const pieceB = this.getPiece(b);
    if (!pieceA || !pieceB) return;
    swapTypes(this.grid, a, b);
    this.setPiece(a, pieceB);
    this.setPiece(b, pieceA);
    // Модель уже изменилась, а фишки на экране её догоняют
    const viewA = this.getViewPosition(a);
    const viewB = this.getViewPosition(b);
    await Promise.all([pieceA.animateMove(viewB.x, viewB.y), pieceB.animateMove(viewA.x, viewA.y)]);
  }
```

Третье: пока фишки едут, игрок не должен делать новые ходы. Иначе он успеет свайпнуть фишку, которая ещё в пути, и вид разойдётся с моделью. Заведите флаг:

```ts Board.ts
  /** Идёт анимация хода: новые ходы и выбор фишек не принимаются */
  private processing = false;
```

И используйте его в `onSwipe` и в обработчике тапа:

```ts Board.ts {1-3,6-11}
  private async onSwipe(piece: Piece, direction: SwipeDirection) {
    // Пока идёт анимация хода, новые ходы не принимаем
    if (this.processing) return;
    // … from, to, проверка края и isValidMove — без изменений

    this.processing = true;
    // Выбранная фишка рисуется поверх остальных — пусть она и едет сверху
    this.select(piece);
    await this.swap(from, to);
    this.process();
    this.processing = false;
  }
```

```ts Board.ts
    piece.onTap = (tapped) => {
      if (!this.processing) this.select(tapped);
    };
```

## Что получилось

Сделайте ход: фишки плавно съезжаются за 0,2 секунды, и только после этого тройка исчезает. Нажмите `3`, чтобы замедлить время, и сделайте ход ещё раз: обмен длится 0,8 секунды, и хорошо видно, что фишки движутся **равномерно** — с одной скоростью от начала до конца. Выглядит механически. Это исправим в следующем шаге.

Неверный ход пока не анимирован: фишки просто не двигаются, как раньше.

## Эксперименты

- Поставьте `duration: 1` и сделайте ход. Попробуйте во время обмена свайпнуть другую фишку: ничего не произойдёт, ходы заблокированы. Мы проверили это и автоматически: свайп во время анимации игнорируется, а после восьми ходов подряд модель и вид совпадают.
- Уберите `await` перед `this.swap(from, to)` и сделайте ход. Тройка исчезает сразу, не дожидаясь обмена: `swap` поменял модель, и `process` тут же убрал совпадения. В консоли появляется ошибка `Cannot set properties of null (setting 'x')`. Это твин: он продолжает двигать фишку, которую `process` уже уничтожил. А потом игра **замирает**: подсветка не вращается, рамка не пульсирует, поле не перерисовывается. Исключение в слушателе прервало обновление тикера, и тикер не запросил следующий кадр. Мы проверили: после такого хода `app.ticker.lastTime` перестаёт меняться, хотя `app.ticker.started` по-прежнему `true`. Верните `await`.

Из второго эксперимента два вывода на всю главу. Первый: **нельзя уничтожать объект, пока его анимирует твин**. Либо дождитесь конца анимации, либо остановите её; как останавливать твины, увидим в шаге про GSAP. Второй: **ошибка в функции тикера останавливает весь игровой цикл**, поэтому код, который выполняется каждый кадр, должен быть особенно аккуратным.

::: deep Под капотом: модель впереди вида
Заметьте, что во время обмена модель уже изменилась, а фишки на экране ещё в пути. Это нормально и даже удобно: модель — источник правды, и любая проверка (например, `getMatches`) работает с итоговым состоянием, не дожидаясь анимации. Вид просто догоняет модель. Именно поэтому мы в главе 7 так старательно отделяли одно от другого.

В оригинальной Puzzling Potions порядок тот же: `Match3Actions.swapPieces` сначала меняет типы в `grid` и `row`/`column` у фишек, а потом ждёт `Promise.all` с двумя анимациями `animateSwap`.
:::
