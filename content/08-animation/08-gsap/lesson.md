Наш твин работает, и вы теперь знаете, как устроена анимация изнутри: доля времени, функция плавности, интерполяция, промис. Но в настоящих проектах твины почти никогда не пишут сами. Нужно ещё много чего: остановить анимацию на полпути, поставить на паузу, запустить с задержкой, повторить, выстроить несколько анимаций в цепочку. Для этого есть библиотеки, и самая известная из них — **GSAP** (GreenSock Animation Platform). Её использует и оригинальная Puzzling Potions.

## Подключение

В превью GSAP уже доступен так же, как `pixi.js`:

```ts
import gsap from 'gsap';
```

В обычном проекте его ставят из npm: `npm install gsap`. Это отдельная библиотека, не связанная с PixiJS. Она умеет анимировать любые числовые свойства любых объектов: CSS-стили, SVG, объекты PixiJS, простые `{ value: 0 }`.

## `gsap.to`

Главная функция — `gsap.to(target, vars)`: анимировать свойства `target` **до** значений из `vars`. В том же объекте `vars` передаются и настройки:

```ts
gsap.to(piece, { x: 100, y: 50, duration: 0.2, ease: 'quad.out' });
```

Сравните с нашим твином:

```ts
tween(this.ticker, piece, { x: 100, y: 50 }, { duration: 0.2, ease: quadOut });
```

Почти то же самое. Отличия:

- **тикер не нужен**: у GSAP свой цикл на `requestAnimationFrame`;
- **функции плавности задаются строкой**: `'quad.out'`, `'back.out'`, `'sine.inOut'`, `'none'` (это `linear`). Можно передать и свою функцию — GSAP примет её так же, как наш твин;
- **значения по умолчанию**: `duration` — 0,5 секунды, `ease` — `'power1.out'` (другое имя для `'quad.out'`);
- **результат** — объект `Tween` с методами `pause`, `resume`, `kill`, `progress` и другими. При этом его можно ждать через `await`, как промис.

## Переписываем фишку

В `Piece.ts` замените импорт твина и тела трёх анимаций:

```ts Piece.ts
import gsap from 'gsap';
import { singleBounce } from './tween';
```

```ts Piece.ts {3,8,13-14}
  /** Плавно перемещает фишку в точку (x, y) внутри поля */
  async animateMove(x: number, y: number) {
    await gsap.to(this, { x, y, duration: 0.2, ease: 'quad.out' });
  }

  /** Исчезновение: фишка становится прозрачной */
  async animatePop() {
    await gsap.to(this, { alpha: 0, duration: 0.1, ease: 'quad.out' });
  }

  /** Падение в точку (x, y) с отскоком */
  async animateFall(x: number, y: number) {
    // GSAP принимает и свою функцию плавности
    await gsap.to(this, { x, y, duration: 0.5, ease: singleBounce });
  }
```

`singleBounce` мы оставили свою. В оригинале эта кривая задана через плагин `CustomEase`, а нам и так хватает функции из шага 4. Файл `tween.ts` пусть остаётся: функция `tween` больше не используется, но как справочник по устройству твина она полезна.

## Остановка: `killTweensOf`

Новая возможность, которой у нашего твина не было, — **остановить** анимацию. Вот где это нужно. Сделаем выбор фишки упругим: пусть она не мгновенно увеличивается до 1,3, а «выпрыгивает» с `back.out`. В `Board.ts`:

```ts Board.ts
import gsap from 'gsap';
```

```ts Board.ts {4-5,12}
  select(piece: Piece | null) {
    if (this.selected) {
      this.selected.setHighlight(false);
      // Анимация увеличения могла ещё не закончиться: останавливаем её, иначе она перезапишет scale
      gsap.killTweensOf(this.selected.scale);
      this.selected.scale.set(1);
    }
    this.selected = piece;
    this.selection.visible = piece !== null;
    if (!piece) return;
    piece.setHighlight(true);
    gsap.to(piece.scale, { x: 1.3, y: 1.3, duration: 0.2, ease: 'back.out' });
    this.piecesContainer.addChild(piece);
  }
```

Анимируем мы `piece.scale` — это точка `ObservablePoint` с полями `x` и `y`, и GSAP спокойно меняет их, как у любого объекта.

Зачем `killTweensOf`? Представьте: игрок выбрал фишку и через 50 мс, пока увеличение ещё идёт, выбрал другую. Первая фишка снимается с выбора, и мы ставим ей `scale.set(1)`. Но твин увеличения ещё работает и в следующем кадре запишет туда 1,1, потом 1,2… и закончит на 1,3. Первая фишка останется большой, хотя уже не выбрана. `gsap.killTweensOf(target)` останавливает все твины этого объекта, и после этого наше `scale.set(1)` уже никто не перезапишет.

`killTweensOf` нужен и перед уничтожением объекта. Помните эксперимент из шага 3, где твин двигал уничтоженную фишку и ошибка остановила тикер? С GSAP последствия другие, но тоже неприятные. Мы проверили: если уничтожить контейнер посреди `gsap.to`, ошибка `Cannot set properties of null (setting 'x')` появляется в консоли **каждый кадр**, пока твин не закончится. Цикл GSAP при этом не останавливается, и остальные твины продолжают работать.

## Замедление для GSAP

И последнее. Нажмите `3` в превью — фон и подсветка замедлились, а обмен фишек нет. У GSAP свой тикер, и `app.ticker.speed` на него не действует. Замедлять его нужно отдельно, через общую шкалу времени всех анимаций GSAP:

```ts main.ts
import gsap from 'gsap';
```

```ts main.ts {5,10,12}
  if (event.key === '1') {
    // Обычный режим
    app.ticker.maxFPS = 0;
    app.ticker.speed = 1;
    gsap.globalTimeline.timeScale(1);
  } else if (event.key === '2') {
    // Не больше 20 кадров в секунду: как на слабом телефоне
    app.ticker.maxFPS = 20;
  } else if (event.key === '3') {
    // Замедление в 4 раза. У GSAP свой тикер, и замедлять его нужно отдельно
    app.ticker.speed = 0.25;
    gsap.globalTimeline.timeScale(0.25);
```

::: task
Перепишите анимации `Piece` на `gsap.to`. Сделайте упругий выбор фишки с `back.out` и `killTweensOf`. Добавьте замедление GSAP в клавиши 1 и 3.
:::

## Что получилось

Игра выглядит как раньше: те же длительности и кривые. Но выбор фишки стал упругим: она чуть-чуть перерастает размер 1,3 и возвращается. Проверка в браузере показала, что после восьми ходов модель и вид по-прежнему совпадают.

Нажмите `3` и сделайте неверный ход: теперь он замедлился вместе со всем остальным. Мы замерили: 0,46 секунды в обычном режиме и 1,64 с замедлением. Без строки с `timeScale` было бы 0,43 секунды в обоих случаях.

## Эксперимент: без `killTweensOf`

Закомментируйте строку с `gsap.killTweensOf` и быстро, двумя щелчками подряд, выберите сначала одну фишку, потом другую. Первая останется увеличенной. Наша проверка щёлкала с интервалом 50 мс: без `killTweensOf` обе фишки остаются с масштабом 1,3, а с ним — только вторая. Верните строку.

## Наш твин против GSAP

| | Наш `tween` | GSAP |
|---|---|---|
| Размер | около 30 строк | около 70 КБ сжатого кода |
| Тикер | Любой переданный, уважает `app.ticker.speed` и `maxFPS` | Свой, `gsap.ticker` |
| Остановка, пауза | Нет | `kill`, `pause`, `resume`, `killTweensOf` |
| Задержки, повторы, цепочки | Нет | `delay`, `repeat`, `yoyo`, `gsap.timeline()` |
| Функции плавности | Четыре свои | Десятки встроенных + свои |

Для учебной игры хватило бы и своего твина. Но всё, что появится дальше (всплывающие очки, попапы, переходы между экранами), удобнее делать на GSAP, как в оригинале.

::: warning
У промиса GSAP есть особенность: если твин убить через `kill` или `killTweensOf`, его промис **никогда не выполнится**. Код после `await gsap.to(…)` так и останется ждать. Мы проверили: промис твина, убитого через 200 мс, не выполнился и через 1,2 секунды. В оригинале для этого есть помощник `resolveAndKillTweens` в `utils/animation.ts`: прежде чем убить твины, он вручную выполняет их промисы. В нашем коде `killTweensOf` останавливает только увеличение при выборе, а его никто не ждёт через `await`, так что проблемы нет.
:::

::: deep Под капотом: тикер GSAP
У GSAP свой цикл на `requestAnimationFrame`: `gsap.ticker`. Каждый кадр он двигает **глобальную шкалу времени** (`gsap.globalTimeline`), а все твины — её дети. Отсюда два следствия.

Во-первых, `gsap.globalTimeline.timeScale(0.25)` замедляет сразу все анимации GSAP. Это аналог `ticker.speed`.

Во-вторых, у GSAP есть своя защита от больших пауз, как `minFPS` у тикера PixiJS: `gsap.ticker.lagSmoothing(500, 33)`. Если между кадрами прошло больше 500 мс, GSAP считает, что прошло всего 33 мс. Вернулись в неактивную вкладку — анимации продолжаются с того же места, а не перескакивают в конец.

Можно ли заставить GSAP работать от тикера PixiJS? Да: отключить его собственный цикл через `gsap.ticker.remove(gsap.updateRoot)` и вызывать `gsap.updateRoot(время)` из `app.ticker`. Так делают, когда нужна строгая синхронизация, например при записи видео кадр за кадром. В нашей игре это ни к чему.
:::
