В оригинальной Puzzling Potions счёт не прыгает с 30 сразу на 60, а быстро «набегает»: 31, 32, 33… Это приятно, но значит, что текст меняется каждый кадр. В первом шаге мы выяснили, что каждое изменение `Text` — это новая картинка. Сколько это стоит, и когда об этом стоит думать?

## Что происходит при смене текста

Когда вы пишете `scoreText.text = 'Очки: 31'`, перед следующей отрисовкой PixiJS:

1. измеряет новую строку;
2. рисует её на canvas 2D с заливкой, обводкой и тенью;
3. загружает получившуюся картинку в видеокарту как текстуру.

Самое дорогое — шаги 2 и 3, и их цена растёт с **площадью** текста. Большая надпись с тенью и размытием дороже маленькой. А вот присвоить ту же самую строку бесплатно: `Text` сравнивает новое значение со старым и, если они равны, ничего не делает.

Насколько это дорого на практике, лучше один раз измерить, чем гадать.

## Замер

Временно добавьте в конец `main.ts`:

```ts main.ts
// Замер: сколько миллисекунд занимает кадр со 100 надписями
const texts: Text[] = [];
for (let i = 0; i < 100; i++) {
  const t = new Text({ text: '0', style: { fill: 0xffffff, fontSize: 20 } });
  t.position.set((i % 10) * 48, 60 + Math.floor(i / 10) * 25);
  texts.push(t);
  app.stage.addChild(t);
}
let frameStart = 0;
let total = 0;
let frames = 0;
let n = 0;
// Самый высокий приоритет — в начале кадра, самый низкий — после отрисовки
app.ticker.add(() => (frameStart = performance.now()), null, UPDATE_PRIORITY.INTERACTION + 1);
app.ticker.add(
  () => {
    total += performance.now() - frameStart;
    if (++frames === 120) {
      console.log(`кадр: ${(total / frames).toFixed(2)} мс`);
      total = frames = 0;
    }
  },
  null,
  UPDATE_PRIORITY.UTILITY,
);
app.ticker.add(() => {
  n++;
  // Закомментируйте эту строку, чтобы сравнить с неподвижным текстом
  texts.forEach((t, i) => (t.text = String(n * 100 + i)));
});
```

Импортируйте `UPDATE_PRIORITY` из `pixi.js`. Код стоит в конце `main.ts`, после `await` отсчёта, поэтому первые цифры появятся в консоли через пару секунд после отсчёта. Первая функция запоминает время в начале кадра, вторая с приоритетом ниже отрисовки считает, сколько прошло, и каждые 120 кадров выводит среднее. Это приоритеты из врезки в шаге 8.2.

Мы запускали этот замер в headless Chrome с программной отрисовкой:

| Что на экране | Время кадра |
|---|---|
| 100 неподвижных `Text` | 0,16 мс |
| 100 `Text`, всем присваивается та же строка | 0,14 мс |
| 100 `Text`, новая строка каждый кадр | 1,41 мс |
| 1 `Text`, новая строка каждый кадр | 0,33 мс |

На вашем компьютере цифры будут другими, но соотношение похожее: обновление всех надписей каждый кадр обходится в разы дороже, чем неподвижные надписи. При 60 FPS на кадр есть 16,7 мс, и 1,4 мс — это заметная часть бюджета. А на слабом телефоне и с большими надписями всё ещё дороже.

Удалите замер после эксперимента.

Выводы:

- **один** счёт, который меняется во время анимации, — это нормально, о нём можно не думать;
- **много** надписей, которые меняются **часто** (таймеры у сотни юнитов, урон над каждым врагом), — повод для `BitmapText` из следующего шага;
- присваивать текст, только когда он действительно поменялся, `Text` умеет сам. Но строку для сравнения всё равно приходится собирать, так что в горячем коде лишние присваивания лучше не делать.

## Набегающий счёт

Теперь сделаем счёт как в оригинале. Число на экране будет догонять настоящий счёт с помощью GSAP: анимируем не текст, а обычный объект с числом, и в `onUpdate` — колбэке, который GSAP вызывает на каждом кадре анимации, — записываем это число в текст.

```ts main.ts
// Число на экране «догоняет» настоящий счёт, как в оригинале
const shownScore = { value: 0 };

function showScore() {
  gsap.killTweensOf(shownScore);
  gsap.to(shownScore, {
    value: score,
    duration: 0.6,
    ease: 'none',
    // Текст меняется каждый кадр, но только когда меняется целое число
    onUpdate: () => {
      scoreText.text = `Очки: ${Math.round(shownScore.value)}`;
    },
  });
  // Счёт «подпрыгивает», когда растёт
  gsap.fromTo(scoreText.scale, { x: 1.3, y: 1.3 }, { x: 1, y: 1, duration: 0.3, ease: 'back.out' });
}

board.onMatch = (matches) => {
  // 10 очков за каждую фишку в совпадении
  for (const match of matches) score += match.length * 10;
  showScore();
};
```

- **`killTweensOf(shownScore)`** — если очки пришли, пока счёт ещё набегает (второй раунд каскада), старый твин останавливается, а новый продолжает с текущего значения до нового счёта;
- **`Math.round`** — `shownScore.value` дробное и меняется каждый кадр, но текст меняется, только когда меняется целое число;
- **«подпрыгивание»** через `gsap.fromTo` вы уже видели в отсчёте.

## Разрешение текста

Сделайте ход и посмотрите на счёт в момент «прыжка». При масштабе 1,3 буквы слегка размыты. Причина в том, что текстура текста нарисована ровно под масштаб 1: одна точка текстуры на один пиксель экрана. При увеличении видеокарта растягивает картинку, как растягивала бы маленький спрайт.

За детальность текстуры отвечает **разрешение** (`resolution`) текста. По умолчанию оно равно разрешению рендерера, у нас это 1. Если поставить 2, PixiJS нарисует текст на canvas вдвое большего размера, а на экране покажет в прежнем размере. Запас детальности спасает при увеличении:

```ts main.ts {3-4}
const scoreText = new Text({
  text: 'Очки: 0',
  // Текстура текста вдвое подробнее экрана: счёт будет увеличиваться и не должен размываться
  resolution: 2,
```

Цена — вчетверо больше пикселей на canvas и в видеопамяти, и вчетверо дороже перерисовка. Для одной надписи это ничего не стоит. Но ставить `resolution: 2` всем текстам подряд не нужно: только тем, что заметно увеличиваются, или если игра работает на экранах высокой плотности.

## Что получилось

После хода счёт быстро набегает: проверка увидела на экране промежуточные значения 3, 7, 10, 14… 30. При каскаде набегание не начинается заново, а продолжается к новому итогу. Надпись подпрыгивает и остаётся чёткой.

## Эксперименты

- Поставьте `scoreText.scale.set(3)` сразу после создания, сначала с `resolution: 2`, потом без неё. Без запаса детальности буквы заметно размыты. Верните масштаб.
- Уберите `Math.round`. На экране побегут числа вроде `Очки: 13.636363636363637`, и текстура будет меняться каждый кадр, даже когда целое число то же.

::: deep Под капотом: размер текстуры текста
Canvas для текста берётся из пула, а его размер — ширина и высота строки, умноженные на `resolution`, плюс запас под обводку и тень. Готовая текстура тоже берётся из общего пула текстур, с размером, округлённым вверх (обычно до степени двойки), и возвращается туда, когда текст меняется или уничтожается. Поэтому частая смена текста не порождает мусора в видеопамяти: старые текстуры используются повторно. Но рисование и загрузку в видеокарту пул не отменяет.

Почему у нас разрешение рендерера равно 1, хотя у многих ноутбуков экран с двойной плотностью? Потому что приложение создано без опции `resolution`: по умолчанию она 1. С `app.init({ resolution: window.devicePixelRatio, autoDensity: true })` вся сцена, включая текст, рисовалась бы с плотностью экрана. Этим займёмся в главе 10 про адаптивность.
:::
