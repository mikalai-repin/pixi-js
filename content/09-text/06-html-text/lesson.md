Подсказка под полем написана одним стилем. А хочется выделить главное: слово «соседние» сделать жирнее, а «три одинаковых в ряд» — другим цветом. У `Text` один стиль на всю надпись, и пришлось бы собирать строку из нескольких текстов, вручную вычисляя, где кончается каждый кусок. Для **форматированного текста** в PixiJS есть два способа. Начнём с самого мощного.

## HTMLText

`HTMLText` рисует настоящий HTML с CSS. Внутри строки можно использовать теги: `<b>`, `<i>`, `<u>`, `<br>`, `<span style="…">` и другие:

```ts main.ts
// HTMLText понимает разметку: жирный шрифт и цвет отдельных слов
const hintText = new HTMLText({
  text: 'Меняйте местами <b>соседние</b> зелья. <span style="color: #c2185b">Три одинаковых в ряд</span> исчезают и приносят очки.',
  style: {
    fontFamily: FONT_FAMILY,
    fontSize: 15,
    // … остальной стиль без изменений
  },
});
```

Стиль — почти тот же, что у `Text`: `fontFamily`, `fontSize`, `fill`, `align`, `wordWrap`. Внутри PixiJS превращает его в CSS для всего блока, а теги внутри строки уточняют стиль отдельных кусков. Не забудьте импортировать `HTMLText` из `pixi.js`.

Заметьте: шрифт Nunito, загруженный через `Assets`, внутри `HTMLText` тоже работает. Почему это не само собой разумеется, расскажет врезка «Под капотом».

## Цена HTMLText

Возможности HTML даются дорого:

- **асинхронность.** `HTMLText` рисуется не сразу. Браузеру нужно собрать SVG-картинку с HTML внутри, загрузить её как изображение и только потом превратить в текстуру. Пока это не закончилось, на месте текста пусто, а после смены текста несколько кадров видна старая версия. В нашем замере надпись появилась на третьем кадре, через 0,4 секунды после создания, а после смены текста старая версия держалась два кадра;
- **скорость.** Каждое изменение — это сборка SVG, разбор HTML и CSS браузером и загрузка картинки. Это намного дороже, чем у `Text`. Счёт или таймер на `HTMLText` делать не стоит;
- **окружение.** Нужен настоящий браузер с DOM: в веб-воркере или на сервере `HTMLText` не работает;
- **шрифты.** Внутри SVG-картинки доступны только системные шрифты и шрифты, которые PixiJS вложит в неё сам, то есть загруженные через `Assets`. Шрифт, подключённый на странице через CSS, внутри `HTMLText` будет заменён запасным.

Поэтому `HTMLText` — для редких, статичных надписей со сложным оформлением: правила игры, описания, тексты с иконками-эмодзи и несколькими стилями.

## Альтернатива: tagStyles у обычного Text

Для простых случаев, как наш, есть способ легче. В PixiJS v8 обычный `Text` понимает **свои** теги, если описать их в стиле свойством `tagStyles`:

```ts
const hintText = new Text({
  text: 'Меняйте местами <strong>соседние</strong> зелья. <accent>Три одинаковых в ряд</accent> исчезают и приносят очки.',
  style: {
    fontFamily: FONT_FAMILY,
    fontSize: 15,
    fill: 0x3b1d70,
    wordWrap: true,
    wordWrapWidth: BOARD_WIDTH,
    align: 'center',
    tagStyles: {
      strong: { fill: 0x000000 },
      accent: { fill: 0xc2185b },
    },
  },
});
```

Имена тегов вы придумываете сами, а каждому тегу соответствует частичный `TextStyle`: цвет, размер, обводка. Это не HTML: никаких атрибутов и CSS, только ваши теги. Зато текст рисуется синхронно, тем же быстрым canvas 2D, что и обычный `Text`.

Наш шрифт в одном файле и одной насыщенности, поэтому жирным `<strong>` здесь сделать нельзя, и мы выделили его цветом. А `HTMLText` с тегом `<b>` нарисовал жирнее, потому что браузер умеет искусственно утолщать шрифт, если нужной насыщенности нет.

::: deep Под капотом: HTML внутри SVG внутри текстуры
Браузер не даёт нарисовать HTML на canvas напрямую. `HTMLText` обходит это так:

1. собирает SVG-документ, внутри которого элемент `<foreignObject>` с вашим HTML и CSS стиля;
2. если в стиле или тегах упомянуты шрифты, загруженные через `Assets`, вкладывает их прямо в SVG как CSS `@font-face` с данными файла. Внешних ссылок SVG-изображение загружать не может, поэтому без этого шага шрифт бы не нашёлся;
3. превращает SVG в изображение (`Image` с data URL) и ждёт его загрузки;
4. рисует изображение на canvas и делает из него текстуру.

Шаги 2 и 3 асинхронные, поэтому `HTMLText` и не может показать текст в том же кадре. А размер надписи (`width`, `height`) известен сразу: его PixiJS измеряет отдельно, синхронно, через скрытый HTML-элемент.
:::
