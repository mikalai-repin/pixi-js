В этой главе на сцене появятся первые объекты: зелья из Puzzling Potions. Мы научимся выводить картинку и полностью управлять тем, где она стоит, какого она размера, как повёрнута и как выглядит. Всё это пригодится в каждой следующей главе.

В редакторе — шаблон из прошлой главы. Переливающийся фон мы убрали, чтобы он не отвлекал.

## Картинку нельзя просто «нарисовать»

В DOM вы пишете `<img src="dragon.png">`, и браузер сам загружает файл и показывает его, когда тот будет готов. В PixiJS так не получится. Чтобы видеокарта могла нарисовать картинку, нужно:

1. скачать файл по сети;
2. раскодировать PNG в массив пикселей;
3. загрузить эти пиксели в память видеокарты.

Результат этих трёх шагов называется **текстурой** (`Texture`): это картинка, которая уже лежит на GPU и готова к отрисовке. Всё, что PixiJS рисует из картинок, рисуется из текстур.

## `Assets.load`

За загрузку отвечает объект **`Assets`**. Его метод `load()` принимает путь к файлу и возвращает `Promise` с готовой текстурой:

```ts main.ts {1,8-9}
import { Application, Assets, Texture } from 'pixi.js';

const app = new Application();
await app.init({ background: '#1e1035', resizeTo: window, antialias: true });
document.body.appendChild(app.canvas);
globalThis.__PIXI_APP__ = app;

const texture = await Assets.load<Texture>('/assets/game/piece-dragon.png');
console.log('Текстура:', texture.width, '×', texture.height);
```

Загрузка асинхронная (файл нужно скачать), поэтому мы ждём её через `await`, как и `app.init()`.

По расширению файла `Assets` сам понимает, что делать: `.png` и `.jpg` превращаются в текстуры, `.json` — в объекты, шрифты регистрируются в браузере. Поэтому `load()` в TypeScript возвращает `any`. Через `<Texture>` мы подсказываем, что ждём именно текстуру, и редактор начинает подсказывать её свойства.

::: task
Загрузите текстуру `/assets/game/piece-dragon.png` и выведите её размер в консоль.
:::

## Что получилось

В консоли появилась строка `Текстура: 150 × 150`. Картинка зелья — квадрат 150 на 150 пикселей. На экране по-прежнему ничего нет: текстура — это только данные, а не объект на сцене. Как и canvas в прошлой главе, её нужно куда-то «поставить». Этим займёмся в следующем шаге.

## Кэш

У `Assets` есть важное свойство: он **кэширует** всё, что загрузил. Если вызвать `Assets.load()` с тем же путём ещё раз, файл не будет скачиваться повторно: вернётся та же самая текстура.

```ts
const a = await Assets.load('/assets/game/piece-dragon.png');
const b = await Assets.load('/assets/game/piece-dragon.png');
console.log(a === b); // true
```

Поэтому не нужно хранить текстуры в своих переменных «на всякий случай»: загрузили один раз — дальше `Assets` вернёт её из кэша мгновенно. Подробнее о кэше, бандлах и манифестах поговорим в главе 5.

::: tip
Все картинки курса лежат в папке `/assets/`, разложенные так же, как в оригинальной игре: `game/` — игровое поле, `common/` — кнопки и иконки, `preload/` — фон и экран загрузки. Например, остальные зелья называются `piece-frog.png`, `piece-newt.png`, `piece-snake.png`, `piece-spider.png` и `piece-yeti.png`.
:::

::: deep Под капотом: Texture и TextureSource
В PixiJS v8 картинка на GPU и «кусок картинки», который рисует спрайт, — это два разных объекта:

- **`TextureSource`** (`texture.source`) — сами пиксели в памяти видеокарты, вся картинка целиком;
- **`Texture`** — прямоугольная область внутри источника, её **фрейм** (`texture.frame`).

Пока у нас одна картинка на один файл, фрейм совпадает со всей картинкой, и разница незаметна. Но в главе 5 мы загрузим **атлас** — один большой PNG, в котором упакованы все зелья сразу. У атласа один `TextureSource` и много `Texture`, по одной на каждое зелье, с разными фреймами. Видеокарте не нужно переключаться между картинками, и рисовать становится быстрее.

Попробуйте вывести в консоль `texture.source.width` и `texture.frame.width`: сейчас они совпадут.
:::
