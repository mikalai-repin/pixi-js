В шаге 4 мы выяснили, что спрайт вращается вокруг якоря. У каждого объекта PixiJS, не только у спрайта, есть похожее свойство — **`pivot`**. Их часто путают, поэтому разберёмся в разнице на живом примере: заставим лягушку летать вокруг дракона по орбите.

## Что такое pivot

**`pivot`** (точка поворота) — точка в **локальных координатах** объекта, которая ставится в `position`. Вокруг неё объект вращается и от неё масштабируется.

Звучит как определение якоря, и это не случайно: результат часто одинаковый. Разница в том, **в чём** точка измеряется:

| | `anchor` | `pivot` |
|---|---|---|
| Единицы | Доли текстуры: `0..1` | Пиксели локальных координат |
| У кого есть | Только у объектов с текстурой (`Sprite`, `Text`…) | У любого объекта, включая `Container` |
| Зависит от размера текстуры | Нет: `0.5` — всегда середина | Да: середина картинки 150 × 150 — это `(75, 75)` |

Для спрайта 150 × 150 эти две записи дают одинаковый результат:

```ts
sprite.anchor.set(0.5);
// то же самое, что
sprite.pivot.set(75, 75);
```

Зачем тогда два свойства? Якорь удобен для картинок: не нужно знать размер. Pivot нужен, когда текстуры нет, например, у контейнера с целым игровым полем внутри. В главе 3 мы будем центрировать поле именно им.

## Pivot за пределами объекта

Самое интересное начинается, когда pivot выносят **за пределы** картинки. Объект всё так же вращается вокруг pivot, но сам при этом оказывается на расстоянии от этой точки и описывает круг — как камень на верёвке.

Создадим лягушку, поставим её в ту же точку, что и дракона, и отодвинем pivot:

```ts main.ts
// Лягушка вращается вокруг дракона
const frogTexture = await Assets.load<Texture>('/assets/game/piece-frog.png');
const frog = new Sprite(frogTexture);
frog.anchor.set(0.5);
frog.setSize(60);
frog.position.copyFrom(dragon.position);
// pivot задаётся в локальных координатах лягушки, до масштабирования
frog.pivot.set(0, 300);
app.stage.addChild(frog);
```

`position.copyFrom(dragon.position)` копирует координаты дракона: лягушка ставится ровно в его центр.

Pivot `(0, 300)` означает «точка на 300 пикселей ниже центра лягушки». Эта точка ставится в центр дракона, поэтому сама лягушка оказывается **выше** дракона.

А на сколько выше? Не на 300, а на **120 пикселей**. Pivot задаётся в локальных координатах, то есть до масштабирования. Лягушка уменьшена до 60 пикселей, её масштаб `60 / 150 = 0.4`, и `300 × 0.4 = 120`.

Осталось её закрутить. Добавьте строку в уже существующую функцию тикера:

```ts main.ts {4}
// Вращение: 0.02 радиана за кадр (при 60 FPS)
app.ticker.add((ticker) => {
  dragon.rotation += 0.02 * ticker.deltaTime;
  frog.rotation -= 0.01 * ticker.deltaTime;
});
```

::: task
Создайте лягушку, вынесите её pivot на `(0, 300)` и вращайте её в тикере в обратную сторону.
:::

## Что получилось

Лягушка летает по кругу вокруг дракона против часовой стрелки, а дракон продолжает вращаться на месте. Обратите внимание: лягушка повёрнута к центру орбиты всегда одной стороной, как Луна к Земле. Это потому, что вращается весь объект целиком вместе с вынесенной точкой.

Поэкспериментируйте:

- `frog.pivot.set(300, 0)`: орбита та же, но лягушка стартует слева от дракона;
- `frog.setSize(120)` без изменения pivot: радиус орбиты удвоится, потому что удвоится масштаб;
- `frog.anchor.set(0)`: лягушка сместится относительно орбиты. Якорь и pivot **складываются**: якорь сдвигает картинку внутри локальных координат, а pivot выбирает, какая точка этих координат встанет в `position`.

::: deep Под капотом: формула трансформации
Чтобы найти, где на экране окажется точка `p` из локальных координат объекта, PixiJS делает (упрощённо) так:

```
экранная точка = position + поворот(масштаб(p − pivot))
```

1. Из точки вычитается pivot: pivot становится началом координат.
2. Результат масштабируется (`scale`).
3. Поворачивается на `rotation`.
4. Сдвигается в `position`.

Отсюда видно всё, что мы наблюдали: pivot попадает ровно в `position` (при `p = pivot` всё обнуляется), вращение идёт вокруг него, а расстояние до pivot умножается на масштаб. Якорь действует ещё раньше: он определяет, в каких локальных координатах лежат пиксели самой текстуры.

Эти четыре операции PixiJS склеивает в одну матрицу и пересчитывает её только при изменении свойств.
:::
