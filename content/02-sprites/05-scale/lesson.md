Зелье размером 150 × 150 пикселей слишком большое для клетки игрового поля. В оригинальной игре клетка — 50 пикселей, у нас будет побольше, но в любом случае картинку нужно уменьшить. В PixiJS для этого есть два способа, и важно понимать, как они связаны.

## Масштаб: `scale`

**Масштаб** (`scale`) — множитель размера относительно исходной текстуры:

```ts
dragon.scale.set(0.5);    // в 2 раза меньше: 75 × 75
dragon.scale.set(2);      // в 2 раза больше: 300 × 300
dragon.scale.set(2, 0.5); // растянуть по ширине, сжать по высоте
```

По умолчанию масштаб равен `1`, то есть спрайт рисуется в размер текстуры.

Отрицательный масштаб **отражает** спрайт: `dragon.scale.x = -1` перевернёт зелье слева направо, как в зеркале. Так в играх разворачивают персонажа, который идёт в другую сторону: отдельная картинка для этого не нужна.

## Размер: `width`, `height` и `setSize`

Часто удобнее сказать «сделай 100 пикселей», чем считать множитель. Для этого есть `width` и `height`:

```ts
dragon.width = 100;
dragon.height = 100;
// или одной строкой:
dragon.setSize(100);       // 100 × 100
dragon.setSize(120, 80);   // 120 × 80
```

## Как они связаны

Главное, что нужно понять: **`width` и `height` — это не отдельные свойства, а другой способ задать масштаб**. Внутри PixiJS хранит только `scale`, а ширина вычисляется из него:

```
width  = ширина текстуры × scale.x
height = высота текстуры × scale.y
```

Когда вы пишете `dragon.width = 100`, PixiJS считает: «текстура 150, нужно 100, значит, `scale.x = 100 / 150 ≈ 0.667`». Проверим это:

```ts main.ts {3,8}
const dragon = new Sprite(texture);
dragon.anchor.set(0.5);
dragon.setSize(100);
dragon.position.set(app.screen.width / 2, app.screen.height / 2);
app.stage.addChild(dragon);

console.log('Масштаб:', dragon.scale.x, dragon.scale.y);
```

::: task
Сделайте зелье размером 100 × 100 пикселей через `setSize` и выведите в консоль его масштаб.
:::

## Что получилось

Зелье уменьшилось, а в консоли появилось `Масштаб: 0.6666666666666666 0.6666666666666666`, то есть ровно 100 / 150.

Поэкспериментируйте:

- после `setSize(100)` добавьте `dragon.scale.set(2)`. Какой станет ширина? (Ответ: 300. Последнее присваивание масштаба перезаписало то, что вычислил `setSize`.)
- добавьте `dragon.scale.x *= -1` и посмотрите на отражённое зелье. Ширина при этом останется положительной: `width` возвращает размер без знака.

::: tip
Спрайт запоминает размер, заданный через `width`/`height`. Если потом поменять ему текстуру на картинку другого размера, PixiJS пересчитает масштаб так, чтобы спрайт остался 100 × 100. А вот если масштаб задан напрямую через `scale`, при смене текстуры сохранится именно масштаб, и размер спрайта изменится вместе с картинкой.

Ещё одна деталь: `width` сохраняет знак масштаба. Отражённое зелье после `dragon.width = 100` останется отражённым.
:::

::: deep Под капотом: размер контейнера
У спрайта «исходный размер» — это размер текстуры. А что такое ширина у контейнера с десятью спрайтами внутри? В PixiJS это ширина **границ** (bounds) всех детей вместе, и `container.width = 300` тоже меняет `scale` контейнера так, чтобы эти границы стали шириной 300.

Отсюда частая ловушка: если записать `width` у пустого контейнера, нужного размера не получится. Ширина пустого контейнера равна нулю, подобрать множитель нельзя, и PixiJS просто сбросит масштаб в `1`. Поэтому размер контейнера задают после того, как в него добавлены дети. О границах подробнее — в главе 3.
:::
