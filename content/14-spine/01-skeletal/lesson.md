Это **необязательная** глава. Она не про PixiJS, а про стороннюю библиотеку, которая с ним работает. Но без неё наша Puzzling Potions так и останется без самого живого, что есть в оригинале: в меню там сидит и покачивается маленький дракон, а в игре булькает котёл. Оба сделаны **скелетной анимацией** в программе Spine. В этой главе вы их оживите.

## Покадровая и скелетная анимация

В главе 8 мы показали обратный отсчёт через `AnimatedSprite`: пять картинок цифр сменяют друг друга. Это **покадровая анимация**: каждый кадр — отдельная готовая картинка. Для пяти цифр это прекрасно. Но представьте дракона, который полторы секунды покачивается, моргает и шевелит ушами. При 30 кадрах в секунду это 45 картинок, и каждая — почти целиком тот же дракон, чуть сдвинутый. Три таких анимации нашего дракона длятся в сумме 5,3 с — 160 кадров. Без масштаба дракон размером примерно 680 × 900 пикселей, то есть 2,4 МБ на видеокарте на каждый кадр и **почти 400 МБ** на все.

**Скелетная анимация** устроена иначе, как кукла на шарнирах:

- художник рисует **части** персонажа по отдельности: голову, туловище, каждое ухо, лапы, хвост. Все они лежат в одном **атласе**;
- в редакторе к частям строится **скелет** — дерево **костей** (bones). Кость — это просто трансформация: позиция, поворот, масштаб. Как у контейнеров PixiJS, кость наследует трансформацию родителя: повернули плечо — за ним повернулась лапа;
- анимация — это **ключи**: «в момент 0,5 с кость головы повёрнута на 10°». Между ключами значения плавно рассчитываются по кривым — то же, что функции плавности из главы 8.

Во время игры **runtime** — библиотека для конкретного движка — читает скелет и ключи, на каждом кадре рассчитывает положение костей и рисует части туда, где им сейчас положено быть. Весь наш дракон со всеми тремя анимациями — это один атлас 1698 × 431 пикселей (около 2,9 МБ на видеокарте) плюс файл скелета.

Плюсы понятны: мало памяти, плавное движение при любой частоте кадров, анимации можно смешивать друг с другом и менять кости из кода. Минус — работа на процессоре каждый кадр и отдельный инструмент для художника. Spine — самый распространённый такой инструмент в 2D-играх, а для PixiJS у его авторов есть официальный runtime **`@esotericsoftware/spine-pixi-v8`**. Он уже подключён к превью курса — той же версии 4.2, что у оригинала.

::: warning Лицензия Spine
Runtime Spine распространяется не под MIT, а по собственной лицензии Spine Runtimes: использовать его в своём продукте можно, если у каждого его пользователя есть лицензия редактора Spine. Учиться на нём и разбирать оригинал можно свободно, но прежде чем выпускать игру со Spine, прочитайте лицензию (она лежит в пакете `@esotericsoftware/spine-core`, файл `LICENSE`).
:::

## Что экспортирует Spine

Из редактора Spine выходят три файла:

| Файл | Что внутри |
|---|---|
| `dragon-skeleton.json` | Скелет: кости, слоты, вложения, анимации с ключами. Бывает и двоичным (`.skel`) — меньше и быстрее читается |
| `dragon-skeleton.atlas` | Текстовое описание атласа: на какой картинке и где лежит каждая часть |
| `dragon-skeleton.png` | Сама картинка атласа |

Они уже собраны AssetPack и лежат в манифесте: дракон — в бандле `common`, котёл — в `preload`. До сих пор мы грузили манифест без них: без runtime Spine загрузчик не знает, что делать с `.atlas`. Переключите манифест на полный:

```ts manifest.ts {3}
 * Это полный манифест: со звуками и Spine-анимациями дракона (бандл common) и котла (бандл preload).
 */
export const MANIFEST_URL = '/assets/packed/manifest.json';
```

Как и `@pixi/sound`, runtime при импорте регистрирует расширения загрузчика: `.atlas` и скелеты в `.json` и `.skel`. Импорт будет в файле дракона, так что отдельно ничего подключать не нужно.

## Дракон

В коде появился файл `Dragon.ts` с пустым классом. Создайте в нём сам скелет:

```ts Dragon.ts
import { Spine } from '@esotericsoftware/spine-pixi-v8';
import { Container } from 'pixi.js';

/** Масштаб скелета: дракон нарисован крупно, без масштаба он ростом около 900 пикселей */
const DRAGON_SCALE = 0.3;

/**
 * Дракон со скелетной анимацией: живёт в меню. Как Dragon в Puzzling Potions.
 * Нужен загруженный бандл common
 */
export class Dragon extends Container {
  /** Сам скелет с анимациями */
  readonly spine: Spine;

  constructor() {
    super();
    // Скелет и атлас — по псевдонимам из манифеста: их загрузил Assets вместе с бандлом common
    this.spine = Spine.from({ skeleton: 'common/dragon-skeleton.json', atlas: 'common/dragon-skeleton.atlas' });
    // Начало координат скелета — между лап дракона: он стоит в точке (0, 0) этого контейнера
    this.spine.scale.set(DRAGON_SCALE);
    this.addChild(this.spine);
    this.playIdle();
  }

  /** Дракон сидит и покачивается — по кругу */
  playIdle() {
    this.spine.state.setAnimation(0, 'dragon-idle', true);
  }
}
```

**`Spine.from`** берёт из кэша `Assets` уже загруженные скелет и атлас по псевдонимам, связывает части скелета с кадрами атласа и создаёт объект `Spine`. Это наследник `Container`: его можно двигать, масштабировать, класть в другие контейнеры, как спрайт.

**`spine.state`** — состояние анимаций (`AnimationState`). **`setAnimation(0, 'dragon-idle', true)`** включает анимацию `dragon-idle` на дорожке 0, по кругу (`true`). О дорожках — в шаге 3.

Кто двигает анимацию дальше на каждом кадре? Сам `Spine`: по умолчанию он подписан на тикер (`autoUpdate: true`) и каждый кадр продвигает анимацию на прошедшее время.

Начало координат у скелета дракона — у его лап. Поэтому позиция дракона в меню — это точка, где он стоит.

## Дракон в меню

В `HomeScreen` дракон добавляется **первым**, раньше логотипа: тогда логотип ляжет поверх его ушей.

```ts HomeScreen.ts {2-4}
    super();
    // Дракон — первым: логотип ляжет поверх его ушей
    this.dragon = new Dragon();
    this.addChild(this.dragon);
    this.logo = new Sprite(Texture.from('logo-game'));
```

Дракону нужно место, поэтому раскладка меню меняется: логотип выше, кнопка и рекорд — у нижнего края, а дракон стоит лапами чуть выше кнопки, и кнопка закрывает его снизу:

```ts HomeScreen.ts
    this.logo.position.set(width / 2, height * 0.18);
    this.subtitle.position.set(width / 2, height * 0.18 + 95);
    // Дракон стоит лапами чуть выше кнопки
    this.dragon.position.set(width / 2, height - 170);
    this.playButton.position.set(width / 2, height - 130);
    this.bestText.position.set(width / 2, height - 70);
```

Не забудьте объявить поле `private readonly dragon: Dragon` и импортировать класс.

::: task
1. Переключите `MANIFEST_URL` на полный `manifest.json`.
2. В `Dragon.ts` создайте скелет через `Spine.from`, уменьшите его до 0,3 и включите `dragon-idle` по кругу.
3. Добавьте дракона в меню первым и расставьте экран заново.
:::

## Что получилось

Между логотипом и кнопкой сидит фиолетовый дракончик и неспешно покачивается: каждые две секунды он повторяет один и тот же цикл. Проверка подтвердила: на дорожке 0 — `dragon-idle` по кругу, масштаб скелета 0,3, а время анимации растёт само (за полсекунды — ровно на 0,5 с).

## Эксперименты

- Включите другую анимацию: `'dragon-bubbles'` (0,93 с) или `'dragon-transition'` (2,4 с). Узнать все имена можно из кода: `this.spine.skeleton.data.animations.map((a) => a.name)`.
- Создайте скелет с `autoUpdate: false` в опциях `Spine.from`. Дракон **пропадёт целиком**: скелет ни разу не рассчитан, и рисовать нечего. Мы проверили: такой дракон не появляется на экране и через 4 секунды. Вызов `this.spine.update(0)` рассчитал бы его один раз — и дракон замер бы в первой позе.
- Поставьте `DRAGON_SCALE = 1` — и увидите, насколько крупно нарисован дракон. Скелетная анимация масштабируется, как любой контейнер.

## Связь с оригиналом

`Dragon` в `ui/Dragon.ts` оригинала создаёт скелет так же — `Spine.from` с теми же псевдонимами — и масштаб 0,3. Только скелет там сдвинут внутри своего контейнера (`spine.x = -30`, `spine.y = 130`), а меню ставит контейнер дракона в центр экрана. Порядок там обратный нашему: логотип добавлен раньше, и дракон рисуется поверх него.

::: deep Под капотом: версии и premultiplied alpha
**Версии.** Файл скелета помнит версию редактора, из которого его экспортировали: у дракона и котла это 4.1.18. Spine требует, чтобы runtime совпадал с редактором по двум первым числам версии: формат меняется между версиями. Оригинал работает на runtime 4.2, и мы проверили, что эти файлы 4.2 читает правильно. Но новейший runtime 4.3 — уже другая история, поэтому версия runtime в курсе зафиксирована.

**Premultiplied alpha.** В атласе дракона есть строка `pma:true`: пиксели картинки хранятся **предумноженными** на прозрачность — цвет полупрозрачного пикселя уже умножен на его альфу, а у полностью прозрачного пикселя цвет — ноль. Так смешивание на видеокарте проще и края при уменьшении не темнеют. Runtime читает эту строку и говорит PixiJS: «эта текстура уже предумножена, не умножай ещё раз» (`alphaMode: 'premultiplied-alpha'`).

Когда мы готовили главу, вокруг дракона была белая рваная кайма. Причина — сборка ресурсов: AssetPack сжал картинку как обычную, и предумноженность сломалась. Мы посчитали пиксели: в исходнике у всех прозрачных пикселей цвет нулевой, а после сжатия в webp цветными стали почти 70 тысяч прозрачных пикселей. Атлас при этом по-прежнему обещал `pma:true`, и видеокарта прибавляла этот цвет к фону. Теперь скрипт сборки курса пересобирает картинку дракона из исходника с обычной прозрачностью и пишет в атлас `pma:false`. Мораль: флаг в атласе и сами пиксели должны говорить одно и то же.
:::
