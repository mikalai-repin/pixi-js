Пока каждый скелет проигрывает одну анимацию по кругу. Но персонаж оживает, когда **реагирует**: дракон удивляется, если навести указатель на «Играть», котёл бурлит сильнее на комбо. Для этого нужно управлять анимациями: переключать, ставить в очередь, смешивать, ускорять. Всем этим заведует **состояние анимаций** — `spine.state`, объект `AnimationState`.

## Дорожки и записи

У состояния анимаций есть **дорожки** (tracks), пронумерованные с нуля. На каждой дорожке в каждый момент играет одна анимация. Несколько дорожек играют одновременно, и более высокая перекрывает те кости, которые она анимирует. Например, дорожка 0 — ходьба, дорожка 1 — взмах рукой: персонаж идёт и машет. Нам хватит одной дорожки.

Каждый вызов `setAnimation` возвращает **запись дорожки** — `TrackEntry`. Это «одно проигрывание»: какая анимация, по кругу ли, сколько прошло времени (`trackTime`), с какой скоростью (`timeScale`). Через запись можно менять проигрывание, пока оно идёт.

Два способа включить анимацию:

- **`setAnimation(track, name, loop)`** — **заменить** то, что играет на дорожке, прямо сейчас;
- **`addAnimation(track, name, loop, delay)`** — поставить **в очередь** той же дорожки: анимация начнётся, когда закончится текущая. `delay: 0` — сразу по окончании текущей (у зацикленной — по окончании текущего круга). Точнее, если включено смешивание (о нём ниже), новая анимация стартует чуть раньше — так, чтобы переход закончился ровно к концу предыдущей.

## Дракон удивляется

Анимация `dragon-bubbles` (0,93 с) — дракон открывает рот. Пусть он делает это **один раз**, когда указатель наводят на «Играть», а потом возвращается к покачиванию:

```ts Dragon.ts
  /** Дракон удивлённо открывает рот — один раз, а потом снова сидит и покачивается */
  playBubbles() {
    this.spine.state.setAnimation(0, 'dragon-bubbles', false);
    // В очередь той же дорожки: начнётся, когда закончится предыдущая анимация
    this.spine.state.addAnimation(0, 'dragon-idle', true, 0);
  }
```

В меню подпишитесь на наведение. `Button` — обычный контейнер с событиями, так что дополнительное событие можно повесить снаружи:

```ts HomeScreen.ts {2-3}
    this.playButton.onPress = () => navigation.showScreen('game');
    // Дракон реагирует, когда указатель наводят на «Играть»
    this.playButton.on('pointerover', () => this.dragon.playBubbles());
```

## Смешивание

Если сейчас переключать анимации, поза будет **перескакивать**: в момент `setAnimation` скелет мгновенно принимает первую позу новой анимации. Чтобы переход был плавным, Spine умеет **смешивать** (mix) анимации: какое-то время обе применяются одновременно, и вес новой растёт от 0 до 1. Длительность смешивания задаётся в общих данных состояния:

```ts Dragon.ts {3}
    this.addChild(this.spine);
    // Смена анимации длится 0,2 с: позы плавно перетекают одна в другую, а не перескакивают
    this.spine.state.data.defaultMix = 0.2;
    this.playIdle();
```

`defaultMix` — для любых пар анимаций; для конкретной пары есть `state.data.setMix('dragon-idle', 'dragon-bubbles', 0.1)`. По умолчанию `defaultMix` равен 0, то есть смешивания нет: мы проверили — без этой строки у новой записи `mixDuration` равен 0.

## Котёл бурлит на комбо

Теперь котёл. На комбо пусть он бурлит быстрее — в столько раз, каков номер раунда, — а потом плавно успокаивается. Скорость проигрывания — `timeScale` записи дорожки:

```ts Cauldron.ts
  /** Котёл бурлит в power раз быстрее, а потом плавно успокаивается */
  boil(power: number) {
    // Текущая запись дорожки 0: одна и та же, пока анимация идёт по кругу
    const entry = this.spine.state.getCurrent(0)!;
    gsap.killTweensOf(entry);
    entry.timeScale = power;
    gsap.to(entry, { timeScale: 1, duration: 1.5, ease: 'quad.out' });
  }
```

`getCurrent(0)` возвращает запись, которая играет на дорожке 0. Зацикленная анимация не создаёт новую запись на каждом круге, поэтому запись одна на всю игру. GSAP анимирует её `timeScale`, как любое числовое свойство.

Котёл должен быть доступен слою эффектов: в `Hud` сделайте поле открытым — `readonly cauldron: Cauldron`. А в `GameEffects.onMatch`, рядом с тряской:

```ts GameEffects.ts {2-3}
    earthquake(this.game.board.pivot, Math.min(round * SHAKE_PER_ROUND, MAX_SHAKE));
    // Котёл бурлит быстрее: на комбо ×2 — вдвое, на ×3 — втрое
    this.game.hud.cauldron.boil(round);
```

Есть и общий `timeScale` у всего состояния — `spine.state.timeScale`: он ускоряет или замедляет все дорожки сразу.

## Что получилось

Наведите указатель на «Играть» — дракон удивлённо округляет рот и через секунду снова покачивается. Переход мягкий, без скачка. В игре на комбо котёл на мгновение начинает бурлить и качаться быстрее и за полторы секунды успокаивается.

Проверка подтвердила: при наведении на дорожке играет `dragon-bubbles` без повтора, а следующей в очереди стоит `dragon-idle`; через 1,3 с играет уже `dragon-idle` по кругу. После `onMatch(3)` `timeScale` записи котла — 3,00, через 2 с — ровно 1.

## Эксперименты

- Замените `addAnimation` на `setAnimation`. Дракон перестанет удивляться: вторая строка **сразу заменяет** первую анимацию. Проверено: после двух `setAnimation` подряд на дорожке играет `dragon-idle`.
- Подпишитесь на события состояния в конструкторе `Dragon`:
  ```ts
  this.spine.state.addListener({ complete: (entry) => console.log('Круг завершён:', entry.animation!.name) });
  ```
  В консоли каждые 2 секунды — «Круг завершён: dragon-idle». Мы замерили: первое сообщение пришло через 2003 мс. Кроме `complete` есть `start`, `interrupt` (анимацию прервала другая), `end`, `dispose` и `event` — **события**, которые аниматор расставляет прямо на шкале анимации в Spine: «шаг», «удар», «выстрел». На них удобно вешать звуки. У наших скелетов событий нет.
- Поставьте `defaultMix = 1` и наводите указатель на кнопку: удивление растягивается в медленное «перетекание».

## Связь с оригиналом

`Dragon` оригинала умеет `playIdle`, `playBubbles` и `playTransition`, но все три включают анимацию **по кругу** через `setAnimation`, без очереди и смешивания. Экран результата оригинала держит `dragon-transition` по кругу. `Cauldron` оригинала скорость анимации не меняет: на комбо в оригинале трясётся весь экран (`earthquake` по `pivot` экрана игры).

::: deep Под капотом: как смешиваются анимации
Анимация в Spine — это набор **таймлайнов**: для каждой анимируемой кости и свойства (поворот, сдвиг, масштаб) — свои ключи. Каждый кадр `state.apply` проходит по дорожкам снизу вверх, и каждый таймлайн записывает в кость своё значение с **весом** (`alpha` записи). При смешивании старая запись остаётся в цепочке (`mixingFrom`), её вес падает, а вес новой растёт: значения костей — взвешенная сумма двух поз. Поэтому смешивание работает и между анимациями, которые аниматор никогда не видел вместе.

Отсюда и цена: пока идёт смешивание, применяются обе анимации, то есть вдвое больше работы. Для двух скелетов на экране это пустяк, но если на экране сотня персонажей, длинные смешивания и много дорожек заметны в профиле — в отличие от покадровой анимации, где всё уже нарисовано заранее.
:::
