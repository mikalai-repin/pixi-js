Не всегда игрок должен иметь возможность трогать поле. Пока идёт анимация обмена или падения, новый свайп испортит всё: фишки поедут одновременно в разные стороны. На паузе поле тоже должно быть неактивным. Нужен способ быстро **заблокировать** все фишки разом и так же быстро разблокировать.

## `interactiveChildren`

В шаге 5 мы познакомились со свойством **`interactiveChildren`**: если поставить его в `false`, PixiJS перестанет проверять попадание по детям контейнера. А раз попадания нет, нет и событий. Одна строка блокирует хоть 63 фишки, хоть тысячу:

```ts
piecesContainer.interactiveChildren = false; // поле заблокировано
piecesContainer.interactiveChildren = true;  // снова доступно
```

Именно так это сделано в оригинале. Корневой класс игры `Match3` блокирует поле одной строкой в `stopPlaying()`, а отдельные фишки блокируются на время своих анимаций в `Match3Piece.lock()`:

```ts
public lock() {
    this.interactiveChildren = false;
    this.dragging = false;
    this.pressing = false;
}
```

Обратите внимание: при блокировке там ещё и **сбрасывается состояние нажатия**. Иначе фишку, которую держали в момент блокировки, после разблокировки ждало бы то самое залипание из шага 6.

## Кнопка паузы

Сделаем паузу. В бандле `common`, который загружается в фоне, есть иконка `icon-pause`. Добавьте в конец файла:

```ts main.ts
// --- Пауза: кнопка из бандла common блокирует поле ---
await Assets.loadBundle('common');

const pauseButton = new Sprite(Texture.from('icon-pause'));
pauseButton.label = 'pauseButton';
pauseButton.anchor.set(1, 0);
pauseButton.position.set(app.screen.width - 16, 16);
pauseButton.eventMode = 'static';
pauseButton.cursor = 'pointer';
app.stage.addChild(pauseButton);

let paused = false;
pauseButton.on('pointertap', () => {
  paused = !paused;
  // Одно свойство отключает события у всех фишек сразу
  piecesContainer.interactiveChildren = !paused;
  board.alpha = paused ? 0.5 : 1;
  console.log(paused ? 'Пауза' : 'Игра продолжается');
});
```

Импортируйте `Sprite` и `Texture`.

`board.alpha = 0.5` — визуальная подсказка: игрок должен видеть, что поле сейчас неактивно. Блокировка без видимого состояния выглядит как зависание.

## Что получилось

Нажмите на паузу: поле потускнеет, и ни нажатия, ни свайпы, ни наведение на фишки больше не работают. Курсор над фишками перестал быть рукой. Нажмите ещё раз: всё вернётся.

## `interactiveChildren` или `eventMode = 'none'`

Тот же результат даёт `piecesContainer.eventMode = 'none'`. Разница:

| | `interactiveChildren = false` | `eventMode = 'none'` |
|---|---|---|
| Дети получают события | Нет | Нет |
| Сам контейнер получает события | Да, если у него `'static'` и есть `hitArea` | Нет |

Для контейнера-слоя, у которого своих обработчиков нет, разницы нет. `interactiveChildren` удобнее, когда у самого контейнера есть свои обработчики, которые должны продолжать работать. Например, можно заблокировать фишки и при этом ловить нажатия на всё поле, чтобы показать подсказку «Сначала снимите паузу».

::: deep Под капотом: блокировка и «скорость» событий
`interactiveChildren = false` не только блокирует, но и **ускоряет** обработку событий. Когда поле заблокировано, PixiJS при движении мыши не обходит 63 фишки, а сразу пропускает весь слой.

В больших сценах этим пользуются постоянно. Фоновый пейзаж из сотен декоративных спрайтов кладут в контейнер с `interactiveChildren = false` или `eventMode = 'none'`, чтобы PixiJS не тратил время на проверку попадания по объектам, которые никогда не будут интерактивными.
:::
