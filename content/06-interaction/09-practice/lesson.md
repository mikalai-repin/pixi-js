Фишка уже сообщает о свайпе и его направлении. Осталось сделать главное действие игры: при свайпе **менять фишку местами с соседней**. Анимации пока не будет, обмен мгновенный: плавное движение добавим в главе 8.

## Задание

::: task
1. Замените вывод свайпа в консоль на функцию `onSwipe(piece, direction)`.
2. В `onSwipe` найдите соседнюю клетку в направлении свайпа. Если она за пределами поля, ничего не делайте.
3. Напишите функцию `swapPieces(a, b)`, которая меняет две фишки местами **во всех трёх местах**, где хранится информация о поле:
   - в модели `grid`;
   - в массиве `pieces`, чтобы `getPiece` находила фишки на новых местах;
   - в самих фишках: их `row`, `column` и позиция на экране.
4. После обмена выбирайте фишку, которую двигали.
:::

## Подсказки

::: hint Подсказка 1: направление в смещение
Удобно завести таблицу, которая переводит направление в смещение клетки:

```ts
const DIRECTIONS: Record<SwipeDirection, { row: number; column: number }> = {
  left: { row: 0, column: -1 },
  right: { row: 0, column: 1 },
  up: { row: -1, column: 0 },
  down: { row: 1, column: 0 },
};
```

Тип `SwipeDirection` импортируйте из `Piece.ts`: `import { Piece, type SwipeDirection } from './Piece';`.
:::

::: hint Подсказка 2: обмен значениями
Чтобы поменять два значения местами, нужна временная переменная. С клеткой фишки так же: сохраните `row` и `column` первой фишки, присвойте ей клетку второй, а второй — сохранённую.
:::

::: hint Подсказка 3: порядок важен
Индекс в массиве `pieces` вычисляется из `row` и `column`. Поэтому сначала обновите `grid` и `pieces`, пока у фишек ещё **старые** клетки, и только потом меняйте сами `row` и `column`.
:::

## Проверьте

- свайп вправо по фишке в центре меняет её с правой соседкой, и фишка остаётся выбранной на новом месте;
- свайп вверх по фишке в верхнем ряду ничего не делает;
- после нескольких обменов нажатие на любую фишку по-прежнему выбирает **её**, а не соседнюю. Если выбирается не та, значит, `pieces` или `row`/`column` не обновились;
- на паузе свайпы не работают.

Мы проверили решение автоматически: после свайпа вправо фишка из клетки `[4, 3]` стоит на месте `[4, 4]`, свайп за край поля ничего не меняет, а на паузе фишки не двигаются.

## Проверьте себя

1. Почему нельзя ограничиться обменом позиций на экране, не трогая `grid` и `pieces`? Что сломается в следующей главе, где мы будем искать тройки?
2. Мы обновляем данные о поле в трёх местах. Какие ошибки это провоцирует? Как устроить код, чтобы место было одно? (Подсказка: в главе 7 появится класс, который будет единственным владельцем этих данных.)
3. Сейчас можно поменять местами любые соседние фишки, даже если это не даёт тройки. Где в коде лучше всего проверять, разрешён ли ход?

## Итоги главы

Теперь вы умеете:

- включать события через `eventMode` и понимаете разницу между режимами;
- подписываться на события указателя и работать с объектом события: глобальные и локальные координаты, цель, всплытие;
- переводить точку на экране в клетку поля;
- делать реакцию на наведение и помнить, что на сенсорных экранах её нет;
- расширять область нажатия через `hitArea`;
- распознавать свайп с порогом и направлением;
- делать жесты надёжными через `pointerupoutside`, `pointercancel` и `globalpointermove`;
- блокировать целые области через `interactiveChildren`.

Это конец первой части курса. У нас есть поле, которое грузится как в настоящей игре, выглядит почти как оригинал и реагирует на игрока. Но правил игры пока нет: фишки меняются местами без всякого смысла. Во второй части мы напишем игру: поиск совпадений, падение фишек, анимации, счёт, экраны, эффекты и звук. И начнём с логики, которая вообще не зависит от PixiJS.
