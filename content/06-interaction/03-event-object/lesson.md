Обработчик события получает аргумент — **объект события** с подробностями: где был указатель, какой кнопкой нажали, мышь это или палец. Самое важное в нём — координаты. Разберёмся с ними и научимся по точке нажатия вычислять клетку поля.

## `FederatedPointerEvent`

Обработчики событий указателя получают объект `FederatedPointerEvent`. Основные поля:

| Поле | Что содержит |
|---|---|
| `global` | Точка в **глобальных** координатах сцены, то есть относительно canvas |
| `getLocalPosition(obj)` | Та же точка в **локальных** координатах `obj` |
| `pointerType` | `'mouse'`, `'touch'` или `'pen'` |
| `button` | Какая кнопка мыши: `0` — левая, `1` — средняя, `2` — правая |
| `target` | Объект, по которому попали (самый глубокий в дереве) |
| `currentTarget` | Объект, чей обработчик сейчас выполняется |

Координаты в `global` — это те же глобальные координаты, что мы разбирали в главе 3. А `getLocalPosition(board)` делает то же, что `board.toLocal(event.global)`.

## Из точки в клетку

В главе 3 мы написали `getViewPosition`: клетка → позиция. Нам понадобится и обратное преобразование: позиция внутри `board` → клетка. Это просто обратная арифметика. Левый край поля — в `-BOARD_WIDTH / 2`. Сдвигаем точку так, чтобы край оказался в нуле, и делим на размер клетки:

```ts main.ts
/** Обратное преобразование: позиция внутри board → клетка сетки */
function getGridPosition(x: number, y: number) {
  return {
    row: Math.floor((y + BOARD_HEIGHT / 2) / TILE_SIZE),
    column: Math.floor((x + BOARD_WIDTH / 2) / TILE_SIZE),
  };
}
```

`Math.floor` отбрасывает дробную часть: точка в 70 пикселях от края — это клетка `1`, а не `1.4`.

Теперь выведем в обработчике всю цепочку преобразований:

```ts main.ts
    piece.on('pointertap', (event) => {
      select(piece);
      const local = event.getLocalPosition(board);
      const cell = getGridPosition(local.x, local.y);
      console.log(
        `Экран (${Math.round(event.global.x)}, ${Math.round(event.global.y)})`,
        `→ поле (${Math.round(local.x)}, ${Math.round(local.y)})`,
        `→ клетка [${cell.row}, ${cell.column}]`,
      );
    });
```

Добавьте функцию `getGridPosition` и выводите при нажатии координаты на экране, на поле и клетку, по которой попали.

## Что получилось

Нажмите на фишку в третьей строке, втором столбце. В консоли:

```
Экран (150, 200) → поле (-100, -100) → клетка [2, 1]
```

Клетка из координат совпадает с клеткой в `label` фишки. Значит, преобразования туда и обратно согласованы.

Попробуйте ещё:

- нажмите на одну и ту же фишку в разных её местах: экранные координаты меняются, а клетка — нет;
- поставьте `board.scale.set(0.7)` и снова понажимайте. Экранные координаты стали другими, а координаты на поле и клетки остались верными: `getLocalPosition` учитывает масштаб. Верните масштаб `1`.

## Зачем это, если фишка и так знает свою клетку

Фишке, по которой нажали, клетку можно было бы просто записать в поле. Это мы и сделаем в шаге 6. Но перевод «точка → клетка» нужен там, где объекта под указателем ещё нет: например, когда игрок нажал на пустую клетку, из которой только что исчезла фишка. Ещё один вариант архитектуры — вообще не вешать обработчики на каждую фишку, а поймать нажатие на всём поле и вычислить клетку по координатам. Оба подхода рабочие. Оригинальная игра вешает обработчики на фишки.

::: deep Под капотом: target, currentTarget и всплытие
У самой фишки нет картинки: это контейнер. Как PixiJS понимает, что указатель над ней? Он проверяет её **детей**: картинку и подсветку. Если указатель попал в границы одного из них, значит, попал и в фишку.

При этом целью события (`target`) становится не спрайт, а **фишка**. У спрайтов `eventMode` по умолчанию `'passive'`: они помогают проверить попадание, но сами событий не получают. Целью становится самый глубокий **интерактивный** объект под указателем, то есть объект со `'static'` или `'dynamic'`. Мы проверили это экспериментом: `event.target === piece`.

Дальше событие **всплывает** (bubbling), как в DOM: от цели к родителю, от родителя к его родителю и так далее до `stage`. Обработчики вызываются у всех интерактивных предков по пути, а `currentTarget` в каждом из них указывает на объект, чей обработчик выполняется сейчас. Проверьте: включите `board.eventMode = 'static'` и подпишитесь `board.on('pointertap', (e) => console.log('поле', e.target.label))`. Поле получит событие **после** фишки, и `e.target` будет фишкой, по которой нажали.

Остановить всплытие можно через `event.stopPropagation()`: тогда предки события не получат. Это пригодится, например, для кнопки поверх поля, нажатие на которую не должно доходить до поля.
:::
