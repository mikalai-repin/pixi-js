Курсор-рука уже подсказывает, что фишку можно нажать. Добавим ещё одну подсказку: фишка под курсором будет чуть увеличиваться. Такая реакция на наведение (hover) делает интерфейс «живым»: игрок чувствует, что игра его слышит, ещё до нажатия.

## Пары событий наведения

| Событие | Когда приходит |
|---|---|
| `pointerover` | Указатель вошёл в объект **или в любого его потомка** |
| `pointerout` | Указатель вышел из объекта или из потомка |
| `pointerenter` | Указатель вошёл в объект. **Не всплывает** |
| `pointerleave` | Указатель вышел из объекта. **Не всплывает** |

Разница между парами тонкая и такая же, как в DOM. `over`/`out` всплывают: если подписаться на них у поля, вы получите событие при каждом переходе с фишки на фишку. `enter`/`leave` не всплывают и приходят только самому объекту. Для одной фишки подходит любая пара. Возьмём `over`/`out`, как в большинстве примеров PixiJS.

## Увеличение при наведении

Добавьте в цикл создания фишек две подписки:

```ts main.ts
    piece.on('pointerover', () => {
      if (piece !== selected) piece.scale.set(1.1);
    });
    piece.on('pointerout', () => {
      if (piece !== selected) piece.scale.set(1);
    });
```

Проверка `piece !== selected` нужна, чтобы наведение не сбивало увеличение выбранной фишки: она и так увеличена в 1,3 раза.

::: task
Увеличивайте фишку под курсором в 1,1 раза и возвращайте обычный размер, когда курсор уходит. Выбранную фишку не трогайте.
:::

## Что получилось

Поводите мышью по полю: фишки под курсором слегка вырастают. Выбранная фишка не реагирует на наведение.

А теперь поводите **медленно** вдоль строки и посмотрите на моменты перехода между соседними фишками. Каждый раз на долю секунды ни одна фишка не увеличена: курсор проходит через **зазор** между фишками, где нет ни одного объекта. Попробуйте нажать ровно в зазор: ничего не выберется. Это неудобство исправим в следующем шаге.

::: warning
На телефонах и планшетах наведения нет: палец не «висит» над экраном. На сенсорном экране `pointerover` придёт только в момент касания, вместе с `pointerdown`. Поэтому никогда не прячьте важное за наведением: всё, что нужно для игры, должно работать по нажатию. Наведение — только приятное дополнение для мыши.
:::

::: deep Под капотом: как PixiJS отслеживает наведение
Браузер сообщает только о том, что мышь сдвинулась над canvas. PixiJS на каждое такое событие заново выясняет, какой объект оказался под указателем, и сравнивает с тем, что было под указателем в прошлый раз. Если объект сменился, старому отправляется `pointerout`, новому — `pointerover`.

Отсюда ограничение, о котором шла речь в шаге 1. Если указатель неподвижен, а фишка **сама** уехала из-под него (например, упала вниз), `'static'`-объект не получит `pointerout`, пока мышь не шевельнётся. Объекты с `'dynamic'` проверяются ещё и каждый кадр, поэтому получат.
:::
