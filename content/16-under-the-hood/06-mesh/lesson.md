Всё, что мы рисовали, PixiJS превращал в треугольники сам: спрайт — два треугольника, круг `Graphics` — веер треугольников, и всё это рисовалось его собственными **шейдерами**. В этом шаге вы зададите треугольники сами и напишете шейдер, который заставит зелье колыхаться, как флаг на ветру.

## Новая лаборатория

`main.ts` снова начинается с чистого листа: мир с островами нам больше не нужен. В старте уже есть приложение, панель статистики и картинка зелья, загруженная **отдельным файлом**, а не кадром атласа (почему — ниже). И функция `createGridGeometry`, которая строит сетку.

## Геометрия

**Меш** (`Mesh`) — объект отображения, у которого вы сами задаёте **геометрию**: из каких треугольников он состоит. Геометрия меша (`MeshGeometry`) — это три массива:

- **`positions`** — координаты вершин, парами `x, y`, в пикселях;
- **`uvs`** — для каждой вершины точка текстуры, которую она показывает. Это **UV-координаты**: `u` — доля ширины текстуры, `v` — доля высоты, обе от 0 до 1. Вершина с UV (0, 0) показывает левый верхний угол картинки, (1, 1) — правый нижний;
- **`indices`** — **индексы**: номера вершин, по три на треугольник.

Индексы нужны, чтобы не повторять вершины: в сетке каждая внутренняя вершина принадлежит шести треугольникам, а хранится один раз.

`createGridGeometry` делит картинку на `SEGMENTS` × `SEGMENTS` клеток. Вершин в сетке (10 + 1)² = 121, в каждой клетке два треугольника, всего 200 треугольников и 600 индексов:

```ts main.ts
      // Номера четырёх углов клетки в массиве вершин
      const topLeft = row * (segments + 1) + column;
      const topRight = topLeft + 1;
      const bottomLeft = topLeft + segments + 1;
      const bottomRight = bottomLeft + 1;
      indices.push(topLeft, topRight, bottomLeft, topRight, bottomRight, bottomLeft);
```

Массивы передаются **типизированными** (`Float32Array`, `Uint32Array`): именно в таком виде данные уходят в видеопамять, без преобразования.

## Меш с обычным шейдером

Сначала создадим меш с текстурой — PixiJS нарисует его своим шейдером:

```ts
const potion = new Mesh({ geometry, texture });
potion.position.set(app.screen.width / 2, app.screen.height / 2);
potion.scale.set(2);
app.stage.addChild(potion);
```

Получилось обычное зелье, просто нарисованное двумястами треугольниками. Если сетка вам кажется лишней — так и есть: одна клетка (два треугольника) нарисовала бы его так же. Сетка понадобится, когда вершины начнут двигаться.

## Шейдер

**Шейдер** — программа, которая выполняется прямо на видеокарте, параллельно для множества данных. Их два вида:

- **вершинный шейдер** (vertex shader) запускается для **каждой вершины** и решает, где она окажется на экране;
- **фрагментный шейдер** (fragment shader) запускается для **каждого пикселя** внутри треугольников и решает, какого он цвета.

Пишутся шейдеры на своих языках: для WebGL — **GLSL**, для WebGPU — **WGSL**. Рендерер возьмёт ту программу, на которой рисует сам, поэтому в `wave.ts` каждая программа записана дважды. Разберём GLSL-версию вершинного шейдера:

```glsl
in vec2 aPosition;
in vec2 aUV;
out vec2 vUV;

uniform mat3 uProjectionMatrix;
uniform mat3 uWorldTransformMatrix;
uniform mat3 uTransformMatrix;
uniform float uTime;

void main() {
  vec2 position = aPosition;
  // Волна: вершина сдвигается вбок тем сильнее, чем ниже она стоит
  position.x += sin(position.y * 0.05 + uTime * 4.0) * 12.0 * aUV.y;
  // Те же преобразования, что делает PixiJS для любого объекта: локальные → мировые → экран
  mat3 mvp = uProjectionMatrix * uWorldTransformMatrix * uTransformMatrix;
  gl_Position = vec4((mvp * vec3(position, 1.0)).xy, 0.0, 1.0);
  vUV = aUV;
}
```

- `in` — **атрибуты**: значения, свои у каждой вершины. `aPosition` и `aUV` — так `MeshGeometry` называет свои массивы `positions` и `uvs`.
- `uniform` — параметры, общие для всего вызова отрисовки. Три матрицы передаёт PixiJS: трансформация меша (`uTransformMatrix`), трансформация его рендер-группы (`uWorldTransformMatrix`) и перевод в координаты экрана (`uProjectionMatrix`). Это те же матрицы 3 × 3, что в главе 3. `uTime` — наш параметр.
- Волна: синус от высоты вершины и времени. `aUV.y` — от 0 наверху до 1 внизу: верх зелья неподвижен, низ колышется сильнее всего.
- `out vec2 vUV` — значение, которое уйдёт во фрагментный шейдер. Для пикселя между вершинами видеокарта **смешивает** значения трёх вершин треугольника пропорционально расстоянию до них. Так каждый пиксель получает свою точку текстуры.

Фрагментный шейдер совсем короткий: прочитать цвет текстуры в точке `vUV`.

```glsl
in vec2 vUV;
out vec4 finalColor;

uniform sampler2D uTexture;

void main() {
  finalColor = texture(uTexture, vUV);
}
```

WGSL-версия делает то же самое, но устроена строже. Все параметры разложены по **группам привязки**: группу 0 (глобальные матрицы) и группу 1 (матрица объекта) заполняет PixiJS, а группа 2 — наша: текстура, сэмплер (как читать текстуру: сглаживание, повтор) и параметры волны.

## Ресурсы шейдера

`Shader.from` собирает обе программы и **ресурсы** — то, что шейдер получает извне:

```ts wave.ts
    resources: {
      uTexture: texture.source,
      uSampler: texture.source.style,
      waveUniforms: { uTime: { value: 0, type: 'f32' } },
    },
```

Ресурсы находятся по **именам**: `uTexture` в обоих шейдерах получит источник текстуры, `uSampler` — его настройки чтения. Объект `{ uTime: { value, type } }` PixiJS превратит в **группу uniform**: тип `f32` — 32-битное дробное число. Менять uniform можно в любой момент, новое значение уйдёт на видеокарту перед следующей отрисовкой:

```ts main.ts
app.ticker.add((ticker) => {
  shader.resources.waveUniforms.uniforms.uTime += ticker.deltaMS / 1000;
});
```

Обратите внимание: геометрия при этом не меняется. Каждый кадр наш код передаёт видеокарте **одно число**, а 121 вершину сдвигает сама видеокарта.

::: task
1. Создайте меш из `geometry` и `texture`, поставьте его в центр экрана и увеличьте вдвое. Убедитесь, что зелье видно.
2. Создайте шейдер `createWaveShader(texture)` из `wave.ts` и передайте меш ему: `new Mesh({ geometry, shader })`.
3. В слушателе тикера увеличивайте `uTime` на прошедшие секунды.
:::

## Что получилось

Низ зелья колышется волной, верх неподвижен. Панель показывает один вызов отрисовки: меш со своим шейдером рисуется отдельно, батч ему недоступен.

## Эксперименты

- Поставьте `SEGMENTS = 1`. Волна исчезнет: зелье будет просто наклоняться то влево, то вправо. Вершин теперь четыре, и обе нижние сдвигаются одинаково. Шейдер двигает только **вершины**, а между ними треугольник остаётся плоским. Вот зачем нужна сетка.
- Во фрагментном шейдере GLSL замените строку на `finalColor = vec4(vUV, 0.0, 1.0);`, а в WGSL — на `return vec4<f32>(uv, 0.0, 1.0);`. Вместо зелья появится цветной квадрат: левый верхний угол чёрный, вправо нарастает красный (`u`), вниз — зелёный (`v`). Так выглядят UV-координаты. Мы проверили на WebGL и WebGPU: картинки одинаковые. Если поправить только один шейдер, изменение увидит только один рендерер.
- Поставьте в `app.init` `preference: 'canvas'`. Зелье исчезнет, причём без единого предупреждения: у Canvas-рендерера нет конвейера `mesh`.

::: warning Почему не кадр атласа
Шейдер получает `texture.source` — **весь** источник текстуры. Для отдельного файла это и есть картинка зелья. А у кадра атласа источник — весь атлас: мы попробовали, и на меше оказался весь атлас с десятками картинок. Обычный шейдер меша учитывает, где кадр лежит в атласе; в своём шейдере это пришлось бы делать самим.
:::

## Связь с оригиналом

Своих шейдеров в Puzzling Potions нет. Но меши в нём есть, и вы их уже видели: дракон и котёл из главы 14 нарисованы сетками Spine — треугольниками с UV-координатами, вершины которых двигают кости. В самой PixiJS на той же идее построены `NineSliceSprite` (сетка из девяти частей) и `MeshRope` (лента вдоль линии): это меши с готовой геометрией.

::: deep Под капотом: путь вершины
Видеокарта обрабатывает вызов отрисовки конвейером:

1. **Вершинный шейдер** — для каждой вершины. На выходе положение на экране и данные для пикселей.
2. **Растеризация** — видеокарта выясняет, какие пиксели экрана покрывает каждый треугольник. Треугольники за краем экрана здесь отбрасываются.
3. **Интерполяция** — для каждого пикселя смешиваются выходы трёх вершин (`vUV`).
4. **Фрагментный шейдер** — для каждого пикселя.
5. **Смешивание** — цвет пикселя соединяется с тем, что уже нарисовано (глава 12).

Пикселей на экране сотни тысяч, а вершин в меше — сотни. Поэтому всё, что можно посчитать в вершинном шейдере, выгоднее считать там.

GLSL-код мы написали без строки `#version` и без объявления точности, и всё равно он компилируется. Перед компиляцией PixiJS дописывает в начало шейдеров **точность** (`precision`): в вершинном — `highp`, во фрагментном — `mediump`. А раз версии нет, видеокарта читает шейдер как самый старый GLSL ES 1.00 из WebGL 1, и PixiJS добавляет макросы `#define`, которые превращают наши `in` и `out` в `attribute` и `varying`, `texture` — в `texture2D`, а `finalColor` — в `gl_FragColor`. Поэтому один и тот же код работает и в WebGL 1, и в WebGL 2. Если начать оба шейдера со строки `#version 300 es`, PixiJS оставит их как есть, и вам станут доступны возможности GLSL ES 3.00. В старых примерах вы встретите `attribute`, `varying` и `gl_FragColor` прямо в коде — это тот самый синтаксис WebGL 1.

Меш без своего шейдера может попасть в батч, но только если вершин не больше 100: в нашей сетке их 121, и даже с обычным шейдером он рисовался отдельным вызовом (`potion.batched` — `false`). Своё условие у `Graphics`: в батч идут фигуры меньше чем из 200 вершин.
:::
