## Как работает фильтр

Фильтр — это шейдер, но работает он не с вершинами объекта, а с **уже нарисованной картинкой**:

1. Рендерер считает **область фильтра** — границы объекта плюс отступ `padding` (или `filterArea`, если она задана, — глава 12).
2. Берёт из пула временную текстуру и рисует объект **в неё**, а не на экран.
3. Рисует на экран прямоугольник размером с область, и для каждого его пикселя запускает фрагментный шейдер фильтра. Шейдер читает временную текстуру и решает, какого цвета пиксель.

Поэтому фильтр всегда стоит как минимум двух вызовов отрисовки и смены цели отрисовки — вы видели это в шаге 16.2 на свечении фишки.

Вершинный шейдер у фильтров почти всегда один и тот же: растянуть прямоугольник на область фильтра и передать фрагментному шейдеру координаты во временной текстуре. В `GreyFilter.ts` он переписан из исходников PixiJS как есть, на GLSL и на WGSL; менять его не нужно. В пакете `pixi.js` есть и готовая строка `defaultFilterVert`, но в собранных типах, которые подключены к редактору курса, её нет, поэтому мы держим копию у себя. Всё интересное — во фрагментном шейдере.

## Координаты внутри фильтра

Фрагментный шейдер получает `vTextureCoord` — точку во временной текстуре. Это **не** координаты от 0 до 1 по объекту: временная текстура из пула обычно больше области (её стороны округлены вверх), и область занимает её левую верхнюю часть. Чтобы понять, где пиксель находится внутри области, нужны два глобальных uniform, которые PixiJS передаёт каждому фильтру:

- `uInputSize.xy` — размер временной текстуры в пикселях. `vTextureCoord * uInputSize.xy` — положение пикселя от левого верхнего угла области, в пикселях;
- `uOutputFrame.zw` — ширина и высота области. Её центр — `uOutputFrame.zw * 0.5`.

Вот весь фрагментный шейдер на GLSL:

```glsl GreyFilter.ts
void main() {
  vec4 color = texture(uTexture, vTextureCoord);
  // Яркость пикселя: зелёный глаз видит лучше всего, синий хуже всего
  vec3 grey = vec3(dot(color.rgb, vec3(0.299, 0.587, 0.114)));
  // Где мы внутри области фильтра, в пикселях, и как далеко от её центра (0 — центр, 1 — угол)
  vec2 pixel = vTextureCoord * uInputSize.xy;
  vec2 center = uOutputFrame.zw * 0.5;
  float distanceToCenter = length(pixel - center) / length(center);
  // Внутри круга радиусом progress — серый, снаружи — цвет, между ними — мягкая граница
  float radius = uProgress * (1.0 + EDGE);
  float amount = 1.0 - smoothstep(radius - EDGE, radius, distanceToCenter);
  finalColor = vec4(mix(color.rgb, grey, amount), color.a);
}
```

- **Серый.** Яркость — взвешенная сумма каналов: `dot` умножает каналы на веса и складывает. Цвета в текстуре хранятся с предумноженной альфой (глава 12), но для серого это не важно: сумма умножается на альфу так же, как каждый канал.
- **Расстояние** от центра делим на расстояние до угла: в центре 0, в углах 1.
- **`smoothstep(a, b, x)`** плавно переходит от 0 к 1, когда `x` растёт от `a` до `b`. Внутри круга `amount` = 1 (серый), снаружи 0 (цвет), а на полосе шириной `EDGE` между ними — плавный переход. Радиус растёт чуть дальше 1, чтобы в конце размытая граница ушла за углы.
- **`mix(a, b, t)`** — смесь двух значений: при `t` = 0 получается `a`, при 1 — `b`.

WGSL-версия делает то же самое.

## Точность

Обратите внимание на объявления:

```glsl GreyFilter.ts
// highp: в вершинном шейдере эти uniform объявлены с высокой точностью, и здесь точность должна совпадать
uniform highp vec4 uInputSize;
uniform highp vec4 uOutputFrame;
```

В шаге 16.6 мы узнали, что PixiJS дописывает фрагментному шейдеру точность `mediump`, а вершинному — `highp`. Uniform с одним именем в обоих шейдерах должен иметь одну точность. `uInputSize` и `uOutputFrame` использует стандартный вершинный шейдер, поэтому во фрагментном их нужно объявить как `highp`.

## Класс фильтра

```ts GreyFilter.ts
export class GreyFilter extends Filter {
  constructor() {
    super({
      glProgram: GlProgram.from({ vertex, fragment, name: 'grey-filter' }),
      gpuProgram: GpuProgram.from({
        vertex: { source, entryPoint: 'mainVertex' },
        fragment: { source, entryPoint: 'mainFragment' },
      }),
      // Группа uniform: имя совпадает с greyUniforms в WGSL, uProgress — с uniform в обоих шейдерах
      resources: {
        greyUniforms: { uProgress: { value: 0, type: 'f32' } },
      },
    });
  }

  /** Насколько далеко от центра разошлась серость: 0 — нисколько, 1 — до самых углов */
  get progress() {
    return this.resources.greyUniforms.uniforms.uProgress;
  }

  set progress(value: number) {
    this.resources.greyUniforms.uniforms.uProgress = value;
  }
}
```

`GlProgram.from` и `GpuProgram.from` кэшируют программы по тексту шейдера: сколько бы фильтров `GreyFilter` вы ни создали, компилироваться программа будет один раз. А свойство `progress` нужно, чтобы GSAP мог анимировать uniform как обычное число.

## Подключаем

В `GameScreen.onTimeUp` замените цветовую матрицу нашим фильтром:

```ts GameScreen.ts {1-4}
    // Поле выцветает от центра к краям: ходить больше нельзя
    const grey = new GreyFilter();
    this.board.filters = [grey];
    gsap.fromTo(grey, { progress: 0 }, { progress: 1, duration: 1.2, ease: 'quad.in' });
```

Плавность `quad.in` — медленно в начале и быстро в конце: пятно сначала неторопливо расплывается в центре, а потом быстро захватывает края.

::: task
В `onTimeUp` замените `ColorMatrixFilter` на `GreyFilter` и анимируйте его `progress` от 0 до 1 за 1,2 секунды. Уберите ставший ненужным импорт `ColorMatrixFilter`.
:::

## Что получилось

Ждать минуту до конца раунда долго: на время проверки поставьте `GAME_TIME = 5000`. Когда время выйдет, серость расползётся от центра поля к углам с мягким краем. Не забудьте вернуть `GAME_TIME`.

## Эксперименты

- Поставьте `EDGE = 0.0` в обоих шейдерах: граница станет резкой, как у круга `Graphics`.
- Уберите `highp` у двух uniform в GLSL. Поле в конце игры **исчезнет целиком**, а в консоли появятся «Could not initialize shader» и «Precisions of uniform 'uInputSize' differ between VERTEX and FRAGMENT shaders», а следом — десятки предупреждений WebGL. Фильтр, шейдер которого не собрался, рисует пустоту. Именно на эту ловушку мы наткнулись, когда писали фильтр. Верните `highp`.
- Повесьте фильтр не на поле, а на весь экран: `this.filters = [grey]`. Центр пятна переедет в центр экрана, а сереть будет всё, включая счёт и надпись «Время вышло!».
- Поставьте `preference: 'webgpu'` в `main.ts`: на WebGPU работает WGSL-версия, и эффект выглядит так же.

## Связь с оригиналом

Сам оригинал своих фильтров не пишет, но пользуется `BlurFilter` из PixiJS и фильтрами из pixi-filters. Загляните в исходники любого из них (`node_modules/pixi.js/lib/filters/defaults/` или репозиторий pixi-filters): `GlProgram` + `GpuProgram` + группа uniform в `resources` — ровно то, что мы написали. Ничего волшебного в библиотечных фильтрах нет.

::: deep Под капотом: что ещё передаётся фильтру
Кроме `uInputSize` и `uOutputFrame`, у каждого фильтра есть ещё четыре глобальных uniform (их видно в WGSL-структуре `GlobalFilterUniforms`):

- `uInputPixel` — размер одного пикселя временной текстуры в долях (`1 / ширина`, `1 / высота`). Нужен фильтрам, которые читают соседние пиксели, как размытие;
- `uInputClamp` — граница области во временной текстуре. Фильтр, который сдвигает пиксели (волна, искажение), не должен читать за её пределами, где лежит мусор;
- `uGlobalFrame` — где область фильтра находится на экране;
- `uOutputTexture` — размер цели, в которую рисует фильтр.

Если фильтров у объекта несколько, PixiJS прогоняет картинку через них по очереди, перебрасывая её между двумя временными текстурами, и только последний рисует на экран. У `Filter` есть и свои параметры: `padding` (запас вокруг объекта для эффектов, выходящих за края, как свечение), `resolution` (во сколько раз меньше пикселей во временной текстуре — у размытия этим экономят), `antialias` и `blendMode`.
:::
