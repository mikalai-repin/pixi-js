На экране превью помещается примерно пятидесятая часть мира. Остальные зелья никто не видит, но PixiJS обрабатывает их все. Сегодня мы научим его не тратить на них время. Это называется **отсечение** (culling).

## Что изменилось в лаборатории

В старте шага две перемены.

Во-первых, зелья теперь **вращаются**: в слушателе тикера каждое из 20 000 зелий поворачивается каждый кадр. Так ведут себя настоящие игровые миры: в них что-то всё время шевелится. Из прошлого шага вы знаете, что рендер-группа здесь уже не спасёт: меняется содержимое, а не сама группа. Панель у нас показывает **4–5,5 мс** на кадр.

Во-вторых, мир разбит на **куски**: 64 контейнера по 500 × 500 пикселей, сетка 8 × 8. Каждое зелье лежит в том куске, куда попала его точка, и хранит позицию относительно куска. Зачем куски — станет ясно ниже. На панели появилась строка «видно кусков: 64 из 64».

## Отсечение в PixiJS 8

Видеокарта и сама не закрашивает пиксели за краем экрана: треугольники обрезаются по краю, и это почти бесплатно. Но до видеокарты работу делает процессор: пересчитывает трансформации, упаковывает вершины, собирает инструкции. Отсечение экономит именно её.

В PixiJS 8 отсечение состоит из трёх частей:

- свойство **`cullable`** говорит: «этот объект можно не рисовать, если он за пределами экрана». По умолчанию `false`;
- класс **`Culler`** проходит по дереву и каждому объекту с `cullable = true` выставляет флаг **`culled`**: границы объекта не пересекают область экрана — значит, `true`. Объект с `culled = true` не рисуется, и его дети не проверяются;
- **`CullerPlugin`** — плагин приложения, который перед каждым кадром вызывает `Culler.shared.cull(app.stage, app.renderer.screen)`.

Сам по себе `cullable` ничего не делает: если никто не вызывает `Culler`, объекты рисуются все. В статьях про PixiJS 7 вы встретите `cullable` без всякого `Culler` — в старой версии рендерер отсекал сам.

## Подключаем плагин

Плагины приложения — это **расширения** (подробно — в шаге 16.8). Регистрируются они до `app.init`: при инициализации приложение запускает все известные ему плагины.

```ts main.ts {1-3}
// Плагин отсечения: перед каждым кадром помечает объекты за пределами экрана как culled.
// Плагины приложения подключаются до init: при init приложение их и запускает
extensions.add(CullerPlugin);
const app = new Application();
```

## Что отсекать

Отсекать каждое зелье — плохая идея: чтобы понять, видно ли зелье, `Culler` считает его границы, а 20 000 расчётов границ каждый кадр стоят дороже, чем мы сэкономим. Поэтому мы и разбили мир на куски. Отсекать будем кусками:

```ts main.ts {3-7}
    const chunk = new Container();
    chunk.position.set(column * CHUNK_SIZE, row * CHUNK_SIZE);
    // Кусок проверяется целиком, по заранее известному прямоугольнику: границы 300 зелий не считаются
    chunk.cullable = true;
    chunk.cullArea = new Rectangle(-CHUNK_MARGIN, -CHUNK_MARGIN, CHUNK_SIZE + CHUNK_MARGIN * 2, CHUNK_SIZE + CHUNK_MARGIN * 2);
    // Внутрь куска отсечение не заглядывает
    chunk.cullableChildren = false;
```

- **`cullArea`** — прямоугольник в локальных координатах объекта, который `Culler` проверяет **вместо** настоящих границ. Мы знаем размер куска заранее, поэтому считать границы его зелий незачем. Запас `CHUNK_MARGIN` нужен потому, что зелье у края куска выступает за него на полкартинки.
- **`cullableChildren = false`** — не спускаться к детям видимого куска. Иначе `Culler` проверил бы ещё и каждое его зелье.

И последнее. Флаг `culled` можно читать и в своём коде. Зачем вращать зелья, которых никто не видит?

```ts main.ts {3-4}
  for (const chunk of chunks) {
    // Невидимые куски не вращаем: их всё равно никто не видит
    if (chunk.culled) continue;
    for (const potion of chunk.children) potion.rotation += SPIN_SPEED * ticker.deltaMS / 1000;
  }
```

::: task
1. Зарегистрируйте `CullerPlugin` до `app.init`.
2. Каждому куску задайте `cullable`, `cullArea` и `cullableChildren`, как в коде выше.
3. В слушателе тикера пропускайте куски с `culled === true`.
:::

## Что получилось

Панель: «видно кусков: 4 из 64» (иногда 6 или 9 — когда край экрана проходит по границам кусков), время кадра — около **1 мс** вместо 4–5,5. Картинка не изменилась: мы просто перестали делать работу, результат которой никто не видит.

## Эксперименты

Мы прогнали каждый вариант на своём компьютере. Время кадра:

| Вариант | Кадр |
|---|---|
| Без отсечения (старт шага) | 4–5,5 мс |
| Куски с `cullArea`, невидимые не вращаем (решение) | около 1 мс |
| То же, но вращаем все куски: уберите `if (chunk.culled) continue` | около 5,4 мс |
| Куски без `cullArea`: удалите строку с `cullArea` | около 3,5 мс |
| Отсекаем каждое зелье: у кусков убрать все три свойства, зельям `potion.cullable = true` | 6–8 мс |

Что из этого следует:

- **Отсечение не отменяет трансформации.** Без `if (chunk.culled) continue` зелья невидимых кусков вращаются, PixiJS пересчитывает их матрицы, и выигрыш почти пропадает. Самая большая экономия — когда **ваш код** не трогает невидимое.
- **Границы стоят дорого.** Без `cullArea` `Culler` каждый кадр считает границы 64 кусков по всем их зельям. Заодно вы заметите, что «видно кусков» иногда меньше, чем раньше: кусок без единого зелья (между островами) имеет пустые границы и честно отсекается.
- **Отсечение по одному объекту может быть хуже, чем никакое.** 20 000 проверок в кадр — это больше работы, чем просто нарисовать всё.

## Связь с оригиналом

В Puzzling Potions отсечения нет: поле целиком помещается на экран, отсекать нечего. В нашей игре его тоже нет. Отсечение нужно там, где мир больше экрана: платформеры, карты, длинные прокручиваемые списки.

::: deep Под капотом: когда Culler узнаёт о трансформациях
`CullerPlugin` вызывает `Culler.shared.cull` перед `renderer.render`, а трансформации объектов рендерер пересчитывает **внутри** `render`. Поэтому `Culler` проверяет объекты по их положению **из прошлого кадра**. Мы проверили: спрайт, который в этом кадре переехал из-за края на экран, получает `culled = true` и появляется только в следующем кадре. Пока камера сдвигается на несколько пикселей за кадр, это незаметно, тем более с запасом в `cullArea`. Если нужно точно, передайте при инициализации `culler: { updateTransform: true }`: тогда `Culler` сам пересчитает трансформации перед проверкой — это дороже.

Осторожно с документацией: в описании этого параметра сказано, что по умолчанию он `true`. Код PixiJS 8.22 по умолчанию работает так, будто он `false`, — трансформации не пересчитываются. Наш замер выше сделан именно с поведением по умолчанию.

Ещё одна деталь: смена `culled` у объекта отмечает его рендер-группу как изменившую структуру. Когда кусок появляется или исчезает с экрана, набор инструкций мира пересобирается. Пока камера над одними и теми же кусками, пересборки нет. Это ещё один довод за крупные куски: границу куска камера пересекает редко.

Своё отсечение можно сделать и без плагина: вызовите `Culler.shared.cull(container, rectangle)` когда и для чего угодно — например, только для слоя мира, а интерфейс не трогать.
:::
