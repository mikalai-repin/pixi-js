Наша Puzzling Potions — игра на время: шестьдесят секунд, набрать как можно больше. В большинстве известных match-3 правило другое: у уровня **ограничено число ходов**, и думать над ходом можно сколько угодно. За три шага вы добавите такой режим рядом с прежним: в этом — ходы вместо таймера, в следующем — цели уровня, затем — карта уровней со звёздами.

## Что изменилось в старте

Добавлен файл `levels.ts`. В нём пока только данные и выбор уровня:

```ts levels.ts
export interface Level {
  /** Сколько ходов есть у игрока */
  moves: number;
}

export const LEVELS: Level[] = [{ moves: 20 }, { moves: 16 }, { moves: 12 }];

let currentLevel: number | null = null;

export function selectLevel(index: number | null) { … }
export function getLevelIndex() { … }
export function getLevel() { … }
```

Зачем модульная переменная? Экраны создаёт навигация — `new ctor()`, без аргументов (глава 11). Передать экрану игры «играй уровень 2» через конструктор нельзя. Поэтому выбор кладётся в модуль, который читают оба экрана, — точно так же, как счёт в `stats.ts` передаётся от экрана игры экрану результата. `null` означает обычную игру на время.

## Задание

::: task
1. **Меню.** Под драконом две кнопки рядом: «Играть» — прежняя игра на время, «Уровни» — игра на ходы, пока всегда первый уровень. Обе помещаются на самом узком экране (375 логических пикселей), и на обе дракон реагирует пузырями.
2. **Ходы в котле.** В игре на ходы котёл вместо таймера показывает, сколько ходов осталось, а под числом — подпись «ходы». Время не идёт. Число подпрыгивает при каждом ходе, а на последних трёх ходах краснеет.
3. **Тратятся только удачные ходы.** Обмен без совпадения (фишки съезжаются и возвращаются) хода не стоит.
4. **Конец.** После последнего хода поле закрывается, но начатый каскад доигрывает до конца. Только потом появляется «Ходы кончились!», поле выцветает, и через секунду открывается экран результата.
5. Игра на время работает, как раньше.
:::

## Подсказки

::: hint Подсказка 1: кто за что отвечает
Ничего не нужно менять в `Board.ts`: поле уже сообщает о каждом ходе колбэком `onMove(valid)` — его слушает слой эффектов, чтобы сыграть звук. Правила игры живут в `GameScreen`: он решает, что считать ходом и когда игра кончилась. А `Hud` только показывает то, что ему передали. Значит, менять — `GameScreen`, `Hud` (новый метод) и `HomeScreen` (кнопка).
:::

::: hint Подсказка 2: когда тратить ход
В `onSwipe` поле сначала ставит `processing = true`, потом вызывает `onMove(valid)` и только затем запускает анимацию. Так что внутри `onMove` ход уже идёт, и `isProcessing` честно говорит `true`. Тратьте ход там, когда `valid` — правда. Нажатие на спецфишку `onMove` не вызывает: взрыв бомбы ход не тратит. Это решение дизайна, а не случайность, — можете поменять, если хотите.
:::

::: hint Подсказка 3: почему нельзя закончить игру сразу после последнего хода
Ход только начался: фишки ещё едут, каскад может принести ещё три раунда очков. Если сразу показать результат, игрок их не увидит, а экран результата прочтёт неполный счёт. У игры на время та же проблема, и она уже решена: `onTimeUp` закрывает поле, а `update` каждый кадр ждёт `!board.isProcessing` и только тогда вызывает `finish`. Сделайте то же самое: после последнего хода закройте поле (`board.locked = true`), а в `update` проверяйте «ходов 0 и каскад закончился». Удобно переименовать `onTimeUp` в `endGame(text)` и `timeUp` в `gameOver` — одна концовка с разной надписью.
:::

::: hint Подсказка 4: число в котле
Таймер — это `BitmapText` со шрифтом `TimerFont`. В его текстуру заранее нарисованы цифры и двоеточие (глава 9); другой символ тоже показался бы — его глиф дорисовался бы при первом использовании, — но числу ходов хватает и готовых. Подпись «ходы» — обычный `Label`; положите её в котёл через `cauldron.addContent`, и она будет качаться вместе с числом. Твин подпрыгивания числа не должен пережить интерфейс: добавьте `gsap.killTweensOf(this.timerText.scale)` в `Hud.destroy`.
:::

::: hint Подсказка 5: две кнопки в меню
`Button` принимает `width`. Две кнопки по 170 пикселей и зазор 12 — это 352 пикселя: на экране шириной 375 остаётся по 11 с каждой стороны. Центры кнопок — `width / 2 ∓ (170 / 2 + 6)`.
:::

## Проверьте

Нажмите «Уровни»: после отсчёта в котле 20 и подпись «ходы». Сделайте обмен без совпадения — число не меняется. Удачный ход — число подпрыгивает и уменьшается. Сыграйте до конца (или временно поставьте `{ moves: 3 }` в `LEVELS`): после последнего хода фишки досыпаются, и только потом появляется надпись и серое пятно.

Так проверяет эталон автотест: в уровне на 3 хода неудачный обмен оставляет в котле «3»; после третьего удачного хода там «0», и поле закрыто; когда каскад заканчивается, появляется «Ходы кончились!», а затем экран результата. «Играть» по-прежнему запускает таймер «1:00».

::: tip Известное упрощение
Экран результата пока не отличает режимы: счёт игры на ходы попадает в рекорд, и вы можете увидеть «Новый рекорд!». В следующем шаге у уровня появятся цели, а у результата — свой текст, и рекорд останется за игрой на время.
:::

## Связь с оригиналом

В Puzzling Potions режима на ходы нет, но есть режимы `easy`, `normal`, `hard` — они меняют число видов зелий (`match3GetBlocks`). Выбранный режим экран игры берёт так же, как мы, — из модуля: `userSettings.getGameMode()` в `GameScreen.prepare`. А ещё любой параметр можно задать в адресе страницы: `?mode=hard&duration=10` — так разработчики проверяют редкие ситуации, не играя по минуте. В скачанном проекте (кнопка «Скачать») можно сделать так же: `new URLSearchParams(location.search).get('moves')` в `getLevel` подставит число ходов прямо из адреса. В превью курса адрес не задать — там это не сработает.
