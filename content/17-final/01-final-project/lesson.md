Шестнадцать глав назад на экране было пустое окно. Теперь у вас есть полная игра: экраны, анимации, эффекты, звук, скелетная анимация — и понимание того, что PixiJS делает с ними под капотом. Пора проверить, сможете ли вы **без пошаговых инструкций**.

В этой главе нет новых API. Есть задачи — как в практикумах, только крупнее: критерии готовности, подсказки от общей к конкретной и эталонное решение, с которым стоит сравнить своё **после** того, как вы закончили.

## Как работать

Задания здесь намеренно крупные. Несколько советов, которые помогут не утонуть:

- **Сначала план.** Прочитайте задание целиком и запишите в комментарии, какие файлы придётся менять и в каком порядке. Почти всегда правило игры живёт в одном месте, а показывают его в другом — как модель `grid.ts` и вид `Board.ts`.
- **Маленькие шаги.** После каждой правки запускайте код. Ошибка в трёх новых строках находится за минуту, в тридцати — за час.
- **Подсказки — по одной.** Первая подсказка говорит, *где* искать, последняя — почти *что* писать. Открывайте следующую, только если застряли.
- **Решение — для сравнения.** Кнопка «Решение» сохраняет ваш код, его можно вернуть. Сравнивать полезно, даже если всё работает: часто эталон решает ту же задачу иначе, и разница чему-то учит.
- **Проверка производительности.** Панель статистики из главы 16 (`showStats` в `debug.ts`) в этой главе выключена — это единственное, что изменилось в старте. Если захотите проверить, не стало ли кадров больше, раскомментируйте одну строку в `main.ts`.

```ts main.ts {2}
// Панель статистики из главы 16. Включайте, когда проверяете производительность
// showStats(app);
```

## Скачать проект

Финальный проект захочется продолжить и показать — уже вне курса. Для этого у редактора появилась кнопка **«Скачать»**. Она собирает архив — готовый проект [Vite](https://vite.dev):

- `src/` — все вкладки редактора в их текущем виде, с вашими правками;
- `public/assets/` — ресурсы, на которые ссылается код (папки `/assets/...`), и `CREDITS.md` с авторами и лицензиями;
- `package.json` с теми библиотеками, которые код импортирует, — тех же версий, что в курсе; `index.html`, `tsconfig.json` и `README.md`.

Распакуйте архив и выполните в его папке:

```bash
npm install
npm run dev      # игра на http://localhost:5173
npm run build    # продакшен-сборка в dist/
```

Мы проверили это на игре из главы 16: архив весит 3,2 МБ, `npm install` и `npm run build` проходят без ошибок, собранная игра запускается в `vite preview`. Всё, о чём шла речь в шаге 15.7 — флаг `erasableSyntaxOnly`, объявление `__PIXI_APP__`, ресурсы в `public/`, — архив уже учитывает.

::: warning Лицензии
Код игр из open-games и их ресурсы распространяются под MIT, шрифт Nunito — под SIL Open Font License; авторы перечислены в `CREDITS.md`. А у Spine Runtimes (глава 14) лицензия не MIT: если ваша игра использует `@esotericsoftware/spine-pixi-v8`, прочитайте её, прежде чем публиковать игру. `README.md` в архиве напомнит об этом.
:::
