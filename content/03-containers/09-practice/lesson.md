Сейчас тип каждой фишки известен только в момент создания: мы выбрали случайное зелье, сделали спрайт и забыли, что выбрали. Узнать позже, где на поле драконы, можно только по `label`. В игре так нельзя: чтобы искать тройки, нужно быстро отвечать на вопрос «какое зелье в клетке (3, 5)?».

В оригинале это решено разделением на **модель** и **вид**:

- **grid** (сетка) — модель, двумерный массив чисел. `grid[row][column]` — тип зелья в клетке;
- **board** (поле) — вид, спрайты, которые рисуют сетку на экране.

Вся игровая логика (поиск совпадений, падение, проверка ходов) работает с сеткой, а вид только отображает её. Подробно эту идею разберём в главе 7, а сейчас сделаем первый шаг.

::: task
1. Перед созданием фишек заполните **модель**: массив `grid: number[][]` размером `ROWS × COLUMNS`, где каждое число — случайный индекс в `PIECES`.
2. Создавайте фишки **по модели**: тип фишки в клетке берите из `grid[row][column]`, а не случайно.
3. Напишите функцию `getPiece(row, column)`, которая возвращает фишку в клетке.
4. Пройдите по модели и:
   - подсветите все фишки-драконы;
   - посчитайте, сколько на поле фишек каждого типа, и выведите это в консоль.
5. Центральную фишку получайте через `getPiece(4, 3)`. Подсветку ей включать больше не нужно: она уже подсвечена, если это дракон.
:::

::: hint Подсказка 1: как заполнить двумерный массив
Двумерный массив — это массив строк, где каждая строка — массив чисел. Создайте пустой `grid`, в цикле по строкам создайте массив `cells`, заполните его в цикле по столбцам и добавьте в `grid` через `push`.
:::

::: hint Подсказка 2: как найти фишку по клетке
Фишки добавляются в `pieces` построчно, как и раньше. Значит, индекс фишки в клетке `(row, column)` — `row * COLUMNS + column`. Это и есть тело функции `getPiece`.
:::

::: hint Подсказка 3: как посчитать типы
Заведите массив счётчиков `counts` длиной `PIECES.length`, заполненный нулями: `PIECES.map(() => 0)`. Проходя по сетке, увеличивайте `counts[grid[row][column]]`. В конце выведите пары «имя — количество».
:::

## Итоги главы

Теперь вы знаете:

- контейнер группирует объекты, и его трансформации действуют на всех потомков;
- у каждого объекта есть локальные и глобальные координаты, а `toGlobal`/`toLocal` переводят между ними;
- порядок детей — это порядок отрисовки, а `addChild` выносит объект наверх;
- границы описывают то, что нарисовано, в локальных или глобальных координатах;
- составные объекты удобно делать наследниками `Container`.

И у нас есть основа игры: поле 9 × 7, центрированное через `getViewPosition`, фишки-объекты и модель `grid`. Не хватает красивой подложки: прямоугольник из `Texture.WHITE` — временное решение. В следующей главе научимся рисовать фигуры кодом и сделаем полку под зелья и рамку поля.
