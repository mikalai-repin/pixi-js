Когда игрок выбирает фишку, она должна оказаться **поверх** соседей: увеличиться и не прятаться за ними. Пока фишки не перекрываются, порядок незаметен. Но стоит одной из них увеличиться, и сразу видно, кто кого перекрывает.

## Правило художника

PixiJS рисует детей контейнера **по порядку**: от первого в массиве `children` к последнему. Каждый следующий рисуется поверх предыдущих, как художник кладёт мазки краски поверх уже высохших. Поэтому:

- `children[0]` — самый нижний;
- последний в `children` — самый верхний.

`addChild` добавляет объект **в конец** списка, то есть наверх. Фишки добавлялись построчно, поэтому каждая следующая лежит поверх предыдущей: фишка справа поверх фишки слева, а нижний ряд поверх верхнего.

## Увеличиваем фишку

Чтобы найти фишку по клетке, будем складывать их в массив. Объявите его перед циклом и добавляйте в него каждую фишку:

```ts main.ts
const pieces: Sprite[] = [];
```

```ts main.ts {3}
    piece.position.copyFrom(getViewPosition(row, column));
    board.addChild(piece);
    pieces.push(piece);
```

Фишки добавляются построчно, поэтому фишка в клетке `(row, column)` лежит в массиве под индексом `row * COLUMNS + column`. Центр поля — строка 4, столбец 3, индекс `4 × 7 + 3 = 31`. Увеличим её:

```ts main.ts
// Выбранная фишка в центре поля: увеличиваем и выносим поверх соседей
const selected = pieces[4 * COLUMNS + 3];
selected.scale.set(selected.scale.x * 1.6);
```

Запустите. Фишка выросла, но фишки правее и ниже **перекрывают** её: они были добавлены позже и лежат выше в списке.

## Выносим наверх

Самый простой способ поднять объект наверх — **добавить его ещё раз**:

```ts main.ts {4}
const selected = pieces[4 * COLUMNS + 3];
selected.scale.set(selected.scale.x * 1.6);
board.addChild(selected);
```

Повторный `addChild` не создаёт копию: объект удаляется со старого места и добавляется в конец, то есть наверх. Ровно так сделано в оригинале. В `Match3Board.ts` есть метод:

```ts
public bringToFront(piece: Match3Piece) {
    this.piecesContainer.addChild(piece);
}
```

Его вызывают перед анимацией обмена, чтобы движущаяся фишка проезжала поверх соседей.

::: task
Соберите фишки в массив `pieces`, увеличьте центральную в 1,6 раза и вынесите её наверх.
:::

## Что получилось

Центральная фишка крупнее остальных и целиком лежит поверх соседей.

## Другие способы управлять порядком

| Метод | Что делает |
|---|---|
| `addChild(obj)` | В конец (наверх). Если объект уже был в контейнере, переносит |
| `addChildAt(obj, index)` | На позицию `index`. `addChildAt(obj, 0)` — в самый низ |
| `removeChild(obj)` | Убирает из контейнера (объект продолжает существовать) |
| `setChildIndex(obj, index)` | Переставляет на позицию `index` |
| `getChildIndex(obj)` | Возвращает текущую позицию |

## zIndex

Иногда порядок удобнее задать числом, чем следить за позицией в массиве. Для этого есть `zIndex`: включите у контейнера `sortableChildren`, и PixiJS сам отсортирует детей по `zIndex` (меньше — ниже):

```ts
board.sortableChildren = true;
selected.zIndex = 1; // у остальных zIndex = 0 по умолчанию
```

Сортировка не бесплатна: при каждом изменении `zIndex` PixiJS пересортирует детей перед отрисовкой. Для 63 фишек это незаметно, а вот для тысяч частиц может стать ощутимо. Поэтому в оригинале используют `addChild`, а `zIndex` — только там, где порядок меняется сам собой. Например, в `GameEffects.ts` каждый кадр выставляется `child.zIndex = child.scale.x`: летящие фишки, которые «ближе» (крупнее), рисуются поверх дальних.

Попробуйте заменить `board.addChild(selected)` на вариант с `sortableChildren` и `zIndex`: результат будет тот же.
