---
title: Локальные и глобальные координаты
api: [getGlobalPosition, toGlobal, toLocal]
---

Раз дочерний объект не знает о трансформациях родителя, у него появляются **две разные позиции**: где он стоит внутри родителя и где он оказался на экране. Это различие будет преследовать нас всю игру, поэтому разберёмся с ним сразу.

## Две системы координат

- **Локальные координаты** — относительно родителя. `frog.x = 60` значит «на 60 пикселей правее точки `(0, 0)` контейнера `board`, в масштабе `board`».
- **Глобальные координаты** — относительно сцены, то есть экрана. Где лягушка оказалась в итоге, после всех сдвигов и масштабов предков.

Пока объект лежит прямо в `stage` без трансформаций, обе системы совпадают. Как только появляется вложенность, они расходятся.

## Перевод между системами

У каждого объекта есть три метода:

| Метод | Что делает |
|---|---|
| `obj.getGlobalPosition()` | Где на экране находится `position` объекта |
| `obj.toGlobal(point)` | Переводит точку **из** локальных координат `obj` **в** глобальные |
| `obj.toLocal(point)` | Переводит точку **из** глобальных координат **в** локальные координаты `obj` |

Выведем координаты лягушки обоими способами и узнаем, где левый верхний угол экрана с точки зрения `board`:

```ts main.ts
console.log('Лягушка в локальных координатах:', frog.x, frog.y);
const frogGlobal = frog.getGlobalPosition();
console.log('Лягушка в глобальных координатах:', frogGlobal.x, frogGlobal.y);

const corner = board.toLocal({ x: 0, y: 0 });
console.log('Угол экрана в координатах board:', corner.x, corner.y);
```

::: task
Добавьте эти строки в конец файла.
:::

## Что получилось

Пусть превью шириной 508 и высотой 596 пикселей (у вас числа могут отличаться). Тогда:

- `board` стоит в центре: `(254, 298)`, масштаб `2`;
- лягушка в локальных координатах: `60, 0`;
- в глобальных: `374, 298`. Это `254 + 60 × 2` по X, а по Y — просто центр;
- угол экрана в координатах `board`: `-127, -149`. Это `(0 − 254) / 2` и `(0 − 298) / 2`. Чтобы попасть из центра поля в угол экрана, нужно пройти 127 «пикселей поля» влево и 149 вверх.

Проверьте числа своего превью по тем же формулам.

## Где это понадобится

Перевод координат нужен постоянно, как только объекты начинают взаимодействовать через границы контейнеров:

- **клик мышью** приходит в глобальных координатах экрана. Чтобы понять, в какую клетку поля попал игрок, точку переводят в локальные координаты поля (глава 6);
- **полёт фишки в котёл**: в оригинале лопнувшая фишка летит из поля в котёл, который лежит в другом контейнере. В `GameEffects.ts` стоит строка `this.toLocal(data.piece.getGlobalPosition())`: взять мировую позицию фишки и перевести её в координаты слоя эффектов (глава 12).

::: tip
У `toLocal` есть второй параметр `from`: из чьих координат переводить. `board.toLocal(point, otherContainer)` переводит точку из локальных координат `otherContainer` прямо в координаты `board`, минуя глобальные вручную.
:::

::: deep Под капотом: матрицы и их обращение
`toGlobal` умножает точку на мировую матрицу объекта (`worldTransform`). `toLocal` делает обратное: умножает на **обратную** матрицу. Обратная матрица «отменяет» трансформацию: если прямая сдвигает на +254 и увеличивает в 2 раза, обратная делит на 2 и сдвигает на −127.

Матрица трансформации в 2D — это 6 чисел:

```
| a  c  tx |
| b  d  ty |
| 0  0  1  |
```

`a`, `b`, `c`, `d` кодируют масштаб, поворот и наклон, а `tx`, `ty` — сдвиг. Посмотрите на мировую матрицу лягушки:

```ts
const matrix = frog.getGlobalTransform();
console.log(matrix.a, matrix.tx);
```

`a` будет `2 × 50 / 150 ≈ 0.667`: масштаб `board`, умноженный на масштаб лягушки, а `tx` — её глобальный X.

Почему не `frog.worldTransform`? Это **кэш**: PixiJS обновляет его во время отрисовки кадра, чтобы не пересчитывать матрицы при каждом изменении свойства. Сразу после создания объектов, до первого кадра, в нём ещё старые значения. `getGlobalTransform()`, `toGlobal()` и `toLocal()` вычисляют матрицу заново и поэтому всегда точны.
:::
