---
title: Из клетки в пиксели
api: [position.copyFrom]

Поле растёт из центра экрана вправо и вниз. Можно было бы сдвинуть сам `board` влево и вверх на половину поля. Но есть способ лучше, и именно его использует оригинальная игра: сделать так, чтобы **центр поля совпадал с точкой `(0, 0)` контейнера**. Тогда, чтобы поставить поле в любое место экрана, достаточно задать `board.position`.

## Смещение на половину поля

Сейчас центр первой фишки (`row = 0, column = 0`) стоит в `(0, 0)`, а центр последней (`row = 8, column = 6`) — в `(300, 400)`. Середина между ними — `(150, 200)`. Если вычесть эту середину из позиции каждой фишки, всё поле сдвинется так, что его центр окажется в `(0, 0)`.

Середина — это половина расстояния от первой фишки до последней:

```
offsetX = (COLUMNS − 1) × TILE_SIZE / 2 = 6 × 50 / 2 = 150
offsetY = (ROWS − 1) × TILE_SIZE / 2    = 8 × 50 / 2 = 200
```

Почему `COLUMNS − 1`, а не `COLUMNS`? Потому что считаем расстояние между **центрами** крайних фишек, а промежутков между семью столбцами шесть.

## Функция-переводчик

Вынесем перевод в отдельную функцию. Она понадобится постоянно: при создании фишек, при обмене, при падении. Добавьте её после констант:

```ts main.ts
/** Клетка сетки (строка, столбец) → позиция внутри board. Центр поля — в точке (0, 0) */
function getViewPosition(row: number, column: number) {
  const offsetX = ((COLUMNS - 1) * TILE_SIZE) / 2;
  const offsetY = ((ROWS - 1) * TILE_SIZE) / 2;
  return {
    x: column * TILE_SIZE - offsetX,
    y: row * TILE_SIZE - offsetY,
  };
}
```

И используйте её в цикле вместо ручного умножения:

```ts main.ts
piece.position.copyFrom(getViewPosition(row, column));
```

`copyFrom` копирует `x` и `y` из любого объекта, у которого они есть. Это короче, чем доставать их по отдельности.

Добавьте функцию `getViewPosition` и ставьте фишки через неё.

## Что получилось

Поле стоит ровно в центре экрана: `board.position` указывает в центр, а центр поля совпадает с `(0, 0)` внутри `board`.

Это та же функция, что в оригинале. Сравните с `Match3Board.ts`:

```ts
public getViewPositionByGridPosition(position: Match3Position) {
    const offsetX = ((this.columns - 1) * this.tileSize) / 2;
    const offsetY = ((this.rows - 1) * this.tileSize) / 2;
    const x = position.column * this.tileSize - offsetX;
    const y = position.row * this.tileSize - offsetY;
    return { x, y };
}
```

Разница только в том, что в оригинале клетка передаётся одним объектом `{ row, column }`, а не двумя числами.

Поэкспериментируйте:

- `board.angle = 10`: поле поворачивается вокруг своего центра, потому что центр — это `(0, 0)` контейнера;
- `board.scale.set(0.5)`: поле уменьшается к центру и остаётся в центре экрана. Если бы `(0, 0)` было в углу поля, оно бы «уезжало» в этот угол.

::: deep Почему не pivot?
Того же результата можно добиться через `pivot`: оставить старые позиции фишек и написать `board.pivot.set(150, 200)`. Это работает, но у варианта со смещением в самих позициях есть преимущество: `(0, 0)` поля — центр — заложен в координатах каждой фишки. Любой код, который работает с позициями фишек (анимации, эффекты, поиск фишки под курсором), не должен помнить о pivot, а `board.pivot` остаётся свободным для других задач, например для тряски экрана в главе 12.
:::
