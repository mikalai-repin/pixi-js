Линии сетки работают, но в оригинальной игре клетки выглядят иначе: под каждой фишкой — своя полупрозрачная плашка со скруглёнными углами. Таких плашек 63, и все одинаковые. Нарисовать 63 одинаковых `Graphics` можно, но PixiJS предлагает способ лучше.

## Контекст — это сама фигура

В шаге 1 мы выяснили, что `Graphics` не хранит фигуры сам: они лежат в его **контексте** (`GraphicsContext`). Контекст — это список инструкций рисования и вычисленные по ним треугольники. А сам `Graphics` — объект сцены, который этот контекст показывает в нужном месте.

Ключевая возможность: **один контекст можно передать многим `Graphics`**. Все они будут рисовать одно и то же, но каждый — со своей позицией, масштабом и прозрачностью. Это как одна текстура и много спрайтов из главы 2.

```ts
const context = new GraphicsContext().circle(0, 0, 10).fill(0xffffff);

const a = new Graphics(context); // одна и та же фигура…
const b = new Graphics(context); // …в двух местах сцены
b.x = 50;
```

## Плашки клеток

Создадим контекст плашки один раз, а потом 63 лёгких `Graphics` по нему. Линии сетки больше не нужны: плашки обозначают клетки нагляднее. Удалите код `lines` и добавьте вместо него:

```ts main.ts
// Подложки клеток: одна геометрия на все 63 клетки
const CELL_SIZE = TILE_SIZE - 4;
const cellContext = new GraphicsContext()
  .roundRect(-CELL_SIZE / 2, -CELL_SIZE / 2, CELL_SIZE, CELL_SIZE, 8)
  .fill({ color: 0xffffff, alpha: 0.07 });

const cells = new Container();
cells.label = 'cells';
for (let row = 0; row < ROWS; row++) {
  for (let column = 0; column < COLUMNS; column++) {
    const cell = new Graphics(cellContext);
    cell.position.copyFrom(getViewPosition(row, column));
    cells.addChild(cell);
  }
}
board.addChildAt(cells, 1);
```

Здесь пригодилось всё из прошлой главы: плашка нарисована вокруг `(0, 0)`, стоит в клетке через `getViewPosition`, а все плашки лежат в отдельном контейнере `cells` сразу над подложкой.

Не забудьте импортировать `GraphicsContext`.

::: task
Замените линии сетки на плашки клеток, нарисованные из одного общего `GraphicsContext`.
:::

## Что получилось

Под каждой фишкой — едва заметная скруглённая плашка, как в оригинальной игре. Поле стало выглядеть «собранным» и аккуратным.

Поэкспериментируйте:

- поменяйте в контексте `alpha: 0.07` на `0.3`: изменятся **все** 63 плашки сразу, потому что у них одна фигура на всех;
- сделайте одну плашку другого цвета: `cells.children[10].tint = 0xffd27f`. Получится, потому что `tint` — свойство объекта, а не контекста. А вот поменять форму одной плашки, не задев остальные, нельзя: для этого ей нужен свой контекст.

::: warning
Если вызвать у такого `Graphics` метод рисования, например `cell.circle(0, 0, 5)`, фигура добавится **в общий контекст** и появится во всех 63 клетках. У `Graphics`, созданного из общего контекста, рисовать нельзя, только показывать.
:::

::: deep Под капотом: почему общий контекст выгоднее
Каждый контекст хранит свои треугольники и свои данные на видеокарте. 63 отдельных `Graphics` — это 63 одинаковые триангуляции и 63 копии одинаковых данных. Общий контекст — одна триангуляция и одна копия, а у каждого `Graphics` своя только матрица трансформации.

Для 63 плашек выигрыш небольшой. Но приём масштабируется: так рисуют тысячи одинаковых декоративных элементов, пули в шутерах, клетки большой карты. Это прямой аналог правила «одна текстура — много спрайтов».
:::
