До сих пор всё на экране было картинками. Но многое в игре удобнее **нарисовать кодом**: подложки, рамки, полоски прогресса, кольцо таймера, кнопки. Картинка для каждого такого элемента — лишний файл, и её не растянешь без искажений. В PixiJS для рисования кодом есть класс **`Graphics`**.

В этой главе мы заменим временную подложку из `Texture.WHITE` на нарисованную, добавим рамку, клетки и маску поля, а в практикуме нарисуем кнопку паузы и таймер.

В стартовом коде — поле из прошлой главы. Подсчёт фишек и подсветку драконов из практикума мы убрали, а размеры поля вынесли в константы `BOARD_WIDTH` и `BOARD_HEIGHT`: подложку теперь удобнее строить по ним, а не по границам.

## Модель рисования в v8: сначала фигура, потом заливка

В `Graphics` рисуют так же, как кистью в редакторе: сначала описывают **фигуру** (путь), потом говорят, чем её **закрасить**:

```ts
const graphics = new Graphics()
  .rect(0, 0, 100, 50)        // 1. фигура: прямоугольник
  .fill({ color: 0xff0000 }); // 2. заливка: красным
```

Методы возвращают сам `Graphics`, поэтому их можно вызывать **цепочкой**. Фигур в одном `Graphics` может быть сколько угодно: каждая следующая рисуется поверх предыдущих.

::: warning
В старых статьях и в коде для PixiJS v7 вы встретите обратный порядок: `beginFill(0xff0000)`, `drawRect(...)`, `endFill()`. В v8 эти методы оставлены только для совместимости и выводят предупреждения. Правильно: **сначала фигура (`rect`), потом `fill`**.
:::

## Параметры прямоугольника

`rect(x, y, width, height)` рисует прямоугольник с левым верхним углом в `(x, y)` в **локальных координатах** самого `Graphics`. Это важно: фигура рисуется внутри объекта, а сам объект можно двигать, вращать и масштабировать, как любой контейнер.

`fill` принимает цвет или объект с цветом и прозрачностью:

```ts
.fill(0xff0000)                         // просто цвет
.fill({ color: 0x000000, alpha: 0.3 })  // цвет и прозрачность заливки
```

## Подложка поля

Центр поля — в `(0, 0)` контейнера `board`. Значит, левый верхний угол поля — в `(-BOARD_WIDTH / 2, -BOARD_HEIGHT / 2)`, а с отступом — ещё на `PADDING` левее и выше. Замените подложку из `Texture.WHITE` на `Graphics`:

```ts main.ts
// Подложка под полем
const PADDING = 10;
const background = new Graphics()
  .rect(-BOARD_WIDTH / 2 - PADDING, -BOARD_HEIGHT / 2 - PADDING, BOARD_WIDTH + PADDING * 2, BOARD_HEIGHT + PADDING * 2)
  .fill({ color: 0x000000, alpha: 0.3 });
background.label = 'background';
board.addChildAt(background, 0);
```

Не забудьте добавить `Graphics` в импорт из `pixi.js`, а `Sprite`, который больше не нужен в `main.ts`, убрать.

::: task
Замените подложку из `Texture.WHITE` на прямоугольник `Graphics` того же размера и цвета.
:::

## Что получилось

Внешне ничего не изменилось, и это правильно: мы нарисовали ровно ту же подложку другим способом. Но теперь это настоящая фигура, и у неё можно скруглить углы, добавить обводку и градиент. Этим займёмся в следующих шагах.

Поэкспериментируйте:

- поменяйте цвет на `0xffd27f` и `alpha` на `1`;
- добавьте вторую фигуру в ту же цепочку: `.rect(-20, -20, 40, 40).fill(0xff0000)` после первого `fill`. Красный квадрат появится в центре поля, но **под** фишками: весь `background` лежит ниже них.

::: deep Под капотом: Graphics — тоже контейнер
`Graphics` наследуется от `Container`, поэтому у него есть `position`, `scale`, `rotation`, `alpha`, `tint` и всё остальное. Фигуры, которые вы описали методами `rect`, `fill` и другими, хранятся не в самом `Graphics`, а в его **контексте** (`graphics.context`, класс `GraphicsContext`). Контекст — это список инструкций: «прямоугольник, залить таким-то цветом, круг, обвести».

При первой отрисовке PixiJS превращает инструкции в треугольники и отправляет их на видеокарту. Пока инструкции не меняются, треугольники используются повторно, и неподвижный `Graphics` почти так же дёшев, как спрайт. В шаге 7 мы воспользуемся тем, что один контекст можно разделить между многими `Graphics`.
:::
