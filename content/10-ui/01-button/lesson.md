Игра начинается сама, как только загрузилась: игрок ещё не понял, что происходит, а отсчёт уже идёт. В настоящих играх сначала есть кнопка «Играть». В этой главе займёмся интерфейсом: кнопками, панелями, раскладкой под любой экран и библиотекой `@pixi/ui`. А начнём с самой обычной кнопки, сделанной своими руками.

Сначала о том, что изменилось в коде. Бандл `common` с кнопками и иконками теперь грузится вместе с `game`, под тем же экраном загрузки:

```ts main.ts
await Assets.loadBundle(['game', 'common'], (progress) => loadScreen.setProgress(progress));
```

`loadBundle` принимает и массив бандлов, а прогресс считает по всем сразу. Строка `await Assets.loadBundle('common')` перед кнопкой паузы больше не нужна, и её убрали.

## Из чего сделана кнопка

В атласе `common` есть три картинки одной кнопки: `button-large`, `button-large-hover` и `button-large-press`. Это три **состояния**:

- **обычное** — кнопка ждёт;
- **наведение** — над кнопкой указатель мыши. Кнопка становится светлее и как бы говорит: «меня можно нажать»;
- **нажатие** — кнопку нажали и ещё не отпустили. Бортик внизу становится тоньше, будто кнопка утопилась.

Значит, кнопка — это спрайт, у которого мы меняем текстуру в зависимости от того, что делает указатель. События указателя вы знаете из главы 6. Новых здесь нет, есть только новая комбинация:

| Событие | Что значит для кнопки |
|---|---|
| `pointerover` | Указатель зашёл на кнопку — наведение |
| `pointerout` | Указатель ушёл — наведения больше нет |
| `pointerdown` | Нажали — состояние «нажатие» |
| `pointerup` | Отпустили над кнопкой — нажатие кончилось |
| `pointerupoutside` | Отпустили, уведя указатель с кнопки — нажатие тоже кончилось |
| `pointertap` | Нажали и отпустили над кнопкой — это и есть «нажатие кнопки» |

Последняя строка важна. Кнопка срабатывает не на `pointerdown`, а на `pointertap`: игрок может нажать, передумать, увести палец с кнопки и отпустить. Тогда ничего не произойдёт. Так ведут себя все кнопки в операционных системах, и игрок этого ждёт.

## Кнопка «Играть»

Добавьте в `main.ts` перед обратным отсчётом:

```ts main.ts
// --- Кнопка «Играть»: спрайт с тремя состояниями ---
// До начала игры поле заблокировано и полупрозрачно
board.locked = true;
board.alpha = 0.5;

const playTextures = {
  default: Texture.from('button-large'),
  hover: Texture.from('button-large-hover'),
  pressed: Texture.from('button-large-press'),
};

const playButton = new Container();
playButton.label = 'playButton';
playButton.position.copyFrom(board.position);
playButton.eventMode = 'static';
playButton.cursor = 'pointer';
app.stage.addChild(playButton);

const playBackground = new Sprite(playTextures.default);
playBackground.anchor.set(0.5);
const playLabel = new Label('Играть', { fontSize: 36 });
playButton.addChild(playBackground, playLabel);
```

Строки `board.locked = true` и `board.alpha = 0.5` переехали сюда из блока отсчёта: поле заблокировано с самого начала, а не только во время отсчёта.

Почему кнопка — это `Container`, а не сам спрайт? Потому что к спрайту нельзя добавить надпись. В PixiJS v8 дочерние объекты бывают только у `Container`. Если всё же вызвать `sprite.addChild(...)`, PixiJS выведет предупреждение об устаревании: это ещё работает, но перестанет. Поэтому кнопка — контейнер, в котором лежат фон и надпись. События тоже ловит контейнер: события дочерних объектов всплывают к нему.

Теперь состояния:

```ts main.ts
let playHovered = false;
let playPressed = false;

/** Показывает состояние кнопки: обычное, под указателем или нажатое */
function updatePlayButton() {
  playBackground.texture = playPressed ? playTextures.pressed : playHovered ? playTextures.hover : playTextures.default;
  // Нижние пикселей двадцать текстуры — бортик. У нажатой кнопки он тоньше, и надпись опускается
  playLabel.y = playPressed ? -4 : -10;
}
updatePlayButton();

playButton.on('pointerover', () => {
  playHovered = true;
  updatePlayButton();
});
playButton.on('pointerout', () => {
  playHovered = false;
  updatePlayButton();
});
playButton.on('pointerdown', () => {
  playPressed = true;
  updatePlayButton();
});
// Отпустили над кнопкой или за её пределами — нажатие кончилось в любом случае
playButton.on('pointerup', () => {
  playPressed = false;
  updatePlayButton();
});
playButton.on('pointerupoutside', () => {
  playPressed = false;
  updatePlayButton();
});
```

- **два флага вместо одного состояния** — наведение и нажатие независимы. Можно нажать, увести указатель с кнопки (наведения нет, нажатие есть) и вернуть его обратно. Из двух флагов одно состояние для показа выбирает `updatePlayButton`. Нажатие важнее наведения, поэтому оно проверяется первым;
- **смена текстуры** — `playBackground.texture = …`. Спрайт просто начинает рисовать другую картинку. Все три текстуры уже лежат в видеокарте как части одного атласа, так что смена ничего не стоит;
- **сдвиг надписи** — у картинки кнопки внизу толстый бортик. Визуальный центр кнопки выше центра текстуры, поэтому надпись поднята на 10 пикселей. У нажатой кнопки бортик тоньше, и надпись опускается вслед за «утопленной» поверхностью.

И последнее — дождаться нажатия:

```ts main.ts
// Ждём настоящего нажатия: pointertap — нажали и отпустили над кнопкой
await new Promise((resolve) => playButton.once('pointertap', resolve));
playButton.destroy({ children: true });
```

`once` — как `on`, но обработчик срабатывает один раз и сам отписывается. Обработчик здесь — функция `resolve` промиса. Значит, `await` ждёт, пока игрок не нажмёт кнопку. Весь остальной код — отсчёт, разблокировка поля, кнопка паузы — пойдёт после этого.

Перед отсчётом покажите поверх заблокированного поля кнопку «Играть» с тремя состояниями. Отсчёт должен начинаться только после нажатия.

## Что получилось

После загрузки поле полупрозрачное, а в центре — оранжевая кнопка «Играть». Наведите на неё мышь: она посветлеет. Нажмите и не отпускайте: бортик стал тоньше, надпись опустилась. Отпустите — кнопка исчезает, и начинается отсчёт. Мы проверили: до нажатия поле заблокировано, а при наведении и нажатии фон кнопки меняется на `button-large-hover` и `button-large-press`.

## Эксперименты

- Нажмите на кнопку, уведите указатель за её пределы и отпустите. Кнопка вернётся в обычное состояние, а игра не начнётся: `pointertap` не случился.
- Замените `'pointertap'` на `'pointerdown'`. Игра начинается в момент нажатия, и передумать уже нельзя. Верните `pointertap`.
- Уберите обработчик `pointerupoutside` и повторите первый эксперимент. Кнопка «застрянет» нажатой: о том, что палец отпустили за её пределами, она так и не узнала.

::: deep Под капотом: hover на сенсорном экране
На телефоне нет указателя, который висит над кнопкой без нажатия. Но события `pointerover` и `pointerout` там тоже приходят: палец «заходит» на кнопку в момент касания и «уходит» после того, как его убрали. Поэтому на телефоне состояние наведения видно лишь мгновение перед нажатием. Мы проверили это эмуляцией касания в Chrome: кнопка получила подряд `pointerover`, `pointerdown`, `pointerup`, `pointertap` и `pointerout` и после касания вернулась в обычное состояние. Каждое событие меняет только свой флаг, поэтому порядок событий не может запутать кнопку.

В оригинальной Puzzling Potions кнопки сделаны на `FancyButton` из библиотеки `@pixi/ui`. Она внутри устроена так же: следит за наведением и нажатием и показывает нужный вид. До неё мы дойдём в шаге 6, когда будет понятно, что именно она делает за нас.
:::
