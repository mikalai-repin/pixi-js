Случайная сетка почти всегда содержит готовые тройки. Если оставить их, игра начнётся с того, что фишки исчезнут сами, без участия игрока. Нужно заполнять сетку так, чтобы совпадений не было с самого начала.

## Идея

Сетка заполняется по порядку: слева направо, сверху вниз. Значит, в момент, когда мы выбираем тип для клетки, **слева и сверху от неё всё уже заполнено, а справа и снизу — пусто**. Тройка с новой клеткой может получиться только двумя способами:

```
по горизонтали:  [A][A][?]        по вертикали:  [A]
                                                 [A]
                                                 [?]
```

Если новый тип совпадает с двумя клетками слева или с двумя клетками сверху, он даст тройку. Тогда выберем другой тип. Справа и снизу проверять не нужно: там ещё ничего нет, а когда очередь дойдёт до тех клеток, они сами проверят нашу.

## Проверка одной клетки

Добавьте в `grid.ts` функцию, которая отвечает на вопрос «даст ли этот тип тройку»:

```ts grid.ts
/**
 * Даст ли тип тройку с двумя уже заполненными клетками слева или сверху.
 * Сетка заполняется слева направо и сверху вниз, поэтому справа и снизу ещё пусто
 */
function completesMatch(grid: Grid, position: Position, type: PieceType) {
  const { row, column } = position;
  const horizontal = type === grid[row]?.[column - 1] && type === grid[row]?.[column - 2];
  const vertical = type === grid[row - 1]?.[column] && type === grid[row - 2]?.[column];
  return horizontal || vertical;
}
```

Оператор `?.` защищает от выхода за край. Для клетки в первом столбце `grid[row][-1]` — это `undefined`, и сравнение просто даст `false`. А для первой строки `grid[-1]` — тоже `undefined`, и `?.` не даст упасть на попытке взять из него `[column]`.

## Случайный тип с исключениями

Если тип не подошёл, нужно выбрать другой, причём не тот же самый снова. Расширьте `getRandomType` списком исключений:

```ts grid.ts
/** Случайный тип из списка, кроме исключённых */
export function getRandomType(types: PieceType[], excluded: PieceType[] = []) {
  const allowed = types.filter((type) => !excluded.includes(type));
  return allowed[Math.floor(Math.random() * allowed.length)];
}
```

## Новый `createGrid`

Теперь при заполнении каждой клетки выбираем тип, пока он даёт тройку, и запоминаем отвергнутые:

```ts grid.ts
/** Создаёт сетку rows × columns из случайных типов так, чтобы в ней не было готовых совпадений */
export function createGrid(rows: number, columns: number, types: PieceType[]): Grid {
  const grid: Grid = [];
  for (let row = 0; row < rows; row++) {
    grid[row] = [];
    for (let column = 0; column < columns; column++) {
      // Типы, которые уже пробовали для этой клетки и которые дают тройку
      const excluded: PieceType[] = [];
      let type = getRandomType(types);
      while (completesMatch(grid, { row, column }, type)) {
        excluded.push(type);
        type = getRandomType(types, excluded);
      }
      grid[row][column] = type;
    }
  }
  return grid;
}
```

::: task
Перепишите `createGrid` так, чтобы в новой сетке не было готовых совпадений.
:::

## Что получилось

Перезапустите код несколько раз и посмотрите на сетку в консоли: трёх одинаковых чисел подряд больше нет ни в строках, ни в столбцах. На поле — ни одной готовой тройки.

## Может ли цикл стать бесконечным?

Хороший вопрос, который стоит задавать себе про любой `while`. Для одной клетки запрещены максимум **два** типа: один из-за горизонтали, один из-за вертикали. У нас шесть типов, значит, хотя бы четыре всегда подходят, и цикл закончится за пару итераций. Но если бы типов было всего два, а оба запрещены, `allowed` оказался бы пустым, и мы получили бы `undefined`. В оригинале самый маленький набор — три типа (режим `test`), этого всегда достаточно.

Это та же логика, что в оригинальной `match3CreateGrid`. Сравните: там функция проверки называется `matchPreviousTypes`, а смысл тот же.

::: deep Под капотом: «нет троек» — не значит «есть ходы»
Наш алгоритм гарантирует, что на старте нет готовых совпадений. Но он **не гарантирует**, что есть хотя бы один ход, который даст совпадение. Теоретически может получиться поле, на котором игрок не может сделать ни одного разрешённого хода.

На поле 9 × 7 из шести типов это почти невероятно, поэтому оригинальная игра такую ситуацию не обрабатывает. В коммерческих match-3 обычно есть проверка «есть ли возможные ходы», и если их нет, поле перемешивается. Это хорошее упражнение после главы: функция `hasPossibleMoves(grid)` перебирает все пары соседних клеток и для каждой проверяет, даст ли обмен совпадение. В шаге 4 мы напишем ровно такую проверку для одного хода.
:::
