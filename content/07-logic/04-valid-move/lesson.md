Сейчас поменять местами можно любые две соседние фишки. В match-3 так нельзя: ход разрешён, только если после него появляется совпадение. Иначе игрок мог бы бесконечно передвигать фишки, пока случайно не соберёт тройку. Научим поле отклонять бессмысленные ходы.

## Пробный обмен на копии

Как узнать, даст ли ход совпадение, **не делая** его? Сделать его понарошку: скопировать модель, поменять фишки в копии и поискать совпадения там. Сама модель и фишки на экране при этом не меняются.

Вот где окупается отдельная модель. Копия — это 63 числа:

```ts grid.ts
/** Копия сетки: её можно менять, не трогая оригинал */
export function cloneGrid(grid: Grid): Grid {
  return grid.map((cells) => cells.slice());
}
```

`slice()` копирует каждую строку. Просто `grid.slice()` скопировал бы только внешний массив, а строки остались бы общими. Изменения в «копии» тогда испортили бы оригинал.

## Только совпадения с участием хода

Есть тонкость. После пробного обмена на поле может найтись совпадение, которое **не связано** с ходом, например оставшееся с прошлого раза. Нас интересуют только совпадения, в которые входит хотя бы одна из двух переставленных клеток. Добавьте в `getMatches` необязательный фильтр:

```ts grid.ts
/**
 * Все совпадения в сетке: группы из matchSize и более одинаковых фишек подряд
 * по горизонтали или вертикали. Пустые клетки (0) совпадений не образуют.
 * Если передан filter, возвращаются только совпадения, в которые входит хотя бы одна из этих клеток.
 */
export function getMatches(grid: Grid, filter?: Position[], matchSize = 3): Position[][] {
  const all = [...getLineMatches(grid, matchSize, 'horizontal'), ...getLineMatches(grid, matchSize, 'vertical')];
  if (!filter) return all;
  return all.filter((match) => match.some((position) => filter.some((f) => samePosition(position, f))));
}
```

`match.some(...)` — «есть ли в совпадении хоть одна клетка», `filter.some(...)` — «которая совпадает хоть с одной клеткой фильтра». Здесь пригодилась `samePosition` из прошлого шага: объекты `{ row, column }` нельзя сравнивать через `===`, ведь это разные объекты с одинаковыми полями.

## Проверка в `Board`

Добавьте в класс метод:

```ts Board.ts
  /** Ход разрешён, только если после обмена появится совпадение с участием одной из двух клеток */
  private isValidMove(from: Position, to: Position) {
    const preview = cloneGrid(this.grid);
    swapTypes(preview, from, to);
    return getMatches(preview, [from, to]).length > 0;
  }
```

И проверяйте ход в `onSwipe` перед обменом:

```ts Board.ts
    if (!this.isValidMove(from, to)) {
      console.log('Ход не создаёт совпадений');
      return;
    }
```

Добавьте `cloneGrid` в импорт из `./grid`.

::: task
Разрешайте обмен, только если он создаёт совпадение с участием одной из двух переставленных клеток.
:::

## Что получилось

Попробуйте поменять две случайные фишки: скорее всего, ничего не произойдёт, а в консоли появится `Ход не создаёт совпадений`. А ход, который собирает тройку, проходит, и совпадение подсвечивается.

Мы проверили это автоматически: тест находит на поле неразрешённый ход, делает свайп и убеждается, что сетка не изменилась. Потом находит разрешённый и убеждается, что после него на поле ровно одно совпадение.

## Как это в оригинале

В оригинальной `Match3Actions.validateMove` всё устроено так же: `match3CloneGrid`, `match3SwapPieces` на копии и `match3GetMatches(tempGrid, [from, to])`. Но есть отличие в поведении. В оригинале при неверном ходе фишки **всё равно** меняются местами с анимацией, а потом едут обратно. Игрок видит, что ход принят, но не сработал. Это хорошая обратная связь, и мы сделаем так же в главе 8, когда у нас появятся анимации. Сейчас, без анимации, обмен «туда и обратно» был бы незаметен.

::: tip
Отклонённый ход без всякой реакции на экране выглядит как баг: игрок не понимает, почему ничего не произошло. Помните об этом, пока у нас нет анимаций: консоль — временная замена обратной связи.
:::
