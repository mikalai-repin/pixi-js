После гравитации все дыры собрались вверху столбцов. Осталось их заполнить: в настоящей игре сверху «сыплются» новые фишки. В модели это значит записать в пустые клетки новые типы, а на экране — создать для них фишки.

## Новые типы без готовых троек

Можно было бы просто записать в каждую пустую клетку случайный тип. Но тогда новые фишки часто будут сразу образовывать тройки между собой. Оригинальная игра поступает хитрее: создаёт **целую новую сетку** тем же алгоритмом без совпадений из шага 2 и берёт типы для пустых клеток из неё.

Добавьте в `grid.ts`:

```ts grid.ts
/**
 * Заполняет пустые клетки новыми случайными типами.
 * Возвращает новые клетки снизу вверх: так их удобнее «ронять» в главе 8
 */
export function fillUp(grid: Grid, types: PieceType[]): Position[] {
  // Берём типы из свежей сетки без совпадений, чтобы досыпанные фишки не давали тройки сами по себе
  const source = createGrid(grid.length, grid[0].length, types);
  const filled: Position[] = [];
  for (let row = 0; row < grid.length; row++) {
    for (let column = 0; column < grid[0].length; column++) {
      if (grid[row][column] === 0) {
        grid[row][column] = source[row][column];
        filled.push({ row, column });
      }
    }
  }
  return filled.reverse();
}
```

Обратите внимание на формулировку в комментарии: досыпанные фишки не дают троек **сами по себе**, между собой. А вот с фишками, которые уже лежали на поле, тройки получиться могут. Это не ошибка, а важная часть игры: так возникают **каскады**, и о них — в следующем шаге.

Список новых клеток разворачивается через `reverse()`, чтобы шёл снизу вверх. Сейчас это неважно, но в главе 8 новые фишки будут падать сверху одна за другой, и порядок пригодится. В оригинальной `match3FillUp` тоже стоит `newPositions.reverse()`.

## Создаём фишки

В `Board.ts` добавьте метод, который заполняет модель и создаёт фишку для каждой новой клетки:

```ts Board.ts
  /** Создаёт новые фишки в пустых клетках */
  private refillPieces() {
    const filled = fillUp(this.grid, TYPES);
    for (const position of filled) this.createPiece(position, this.grid[position.row][position.column]);
    return filled.length;
  }
```

`createPiece` уже умеет всё: создаёт фишку нужного типа, подписывает на нажатия и свайпы, кладёт в слой фишек и ставит в клетку. Мы написали её для начального заполнения поля, а теперь она пригодилась и для досыпания.

Вызовите метод в `onSwipe` после гравитации:

```ts Board.ts
    this.dropPieces();
    this.refillPieces();
```

Добавьте `fillUp` в импорт из `./grid`.

## Что получилось

Теперь ход выглядит законченным: тройка исчезает, фишки над ней опускаются, сверху появляются новые. Поле всегда полное: 63 фишки, ни одной дыры. Всё происходит мгновенно, за один кадр, поэтому глазу сложно уследить за тем, что произошло. Анимации исправят это в главе 8.

Сыграйте несколько ходов. Иногда после хода на поле **остаются** совпадения: новые фишки легли рядом со старыми так, что образовали тройку. Их никто не убирает. Это последнее, чего не хватает логике.

::: tip
Мы проверили, что после каждого хода модель и вид полностью согласованы: для каждой из 63 клеток фишка на экране существует, стоит в правильном месте, знает свою клетку и показывает зелье того типа, что записан в модели. Если вы будете менять логику поля, такая проверка — лучший способ быстро найти ошибку рассинхронизации. Её можно запустить из консоли браузера через `__PIXI_APP__`.
:::
