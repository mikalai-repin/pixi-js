В начале главы мы говорили, что отдельную модель можно тестировать без браузера, без canvas и без картинок. Пора это доказать. Напишем **юнит-тесты** для двух самых хитрых функций: `getMatches` и `applyGravity`.

В редакторе появилась вкладка `tests.ts`. В ней — крошечный тестовый каркас и один пример теста. А в `main.ts` тесты запускаются сразу после создания приложения, ещё до загрузки ресурсов: логике сетки ресурсы не нужны.

## Каркас

```ts tests.ts
function test(name: string, fn: () => void) { … }
function expectEqual(actual: unknown, expected: unknown) { … }
```

- `test` запускает функцию и пишет в консоль `✓ имя`, если она выполнилась без ошибок, или `✗ имя: причина`, если выбросила исключение;
- `expectEqual` сравнивает два значения через `JSON.stringify` и выбрасывает исключение, если они различаются. Для чисел, массивов и простых объектов вроде `{ row, column }` этого достаточно.

В настоящих проектах для этого используют библиотеки вроде Vitest или Jest. У них то же самое `test` и `expect`, только с удобными сообщениями, запуском из терминала и отчётами. Принцип ровно тот же.

## Пример

```ts tests.ts
  test('нет совпадений — пустой список', () => {
    const grid: Grid = [
      [1, 2, 1],
      [2, 1, 2],
    ];
    expectEqual(getMatches(grid), []);
  });
```

Тест — это маленькая сетка, вызов функции и сравнение с ожидаемым результатом. Сетки в тестах лучше делать маленькими: 1–3 строки, ровно столько, чтобы проверить один случай.

## Задание

::: task
Напишите тесты (по одному на пункт):

**`getMatches`:**
1. три одинаковых по горизонтали — одно совпадение, и это именно эти три клетки;
2. три одинаковых по вертикали — одно совпадение из трёх клеток;
3. четыре в ряд — **одно** совпадение из **четырёх** клеток;
4. «уголок» (тройка по горизонтали и тройка по вертикали с общей клеткой) — два совпадения;
5. три пустые клетки (`0`) подряд — не совпадение.

**`applyGravity`:**
6. одна фишка над двумя пустыми клетками падает на дно, и функция возвращает одно перемещение;
7. столбец с несколькими дырами — все фишки оседают вниз в том же порядке;
8. полный столбец без дыр — перемещений нет.
:::

## Подсказки

::: hint Подсказка 1: столбец как сетка
Для тестов гравитации удобна сетка из **одного столбца**: `[[3], [0], [0]]` — это три строки по одной клетке. Ожидаемый результат после гравитации — `[[0], [0], [3]]`.
:::

::: hint Подсказка 2: что сравнивать
`applyGravity` меняет сетку **на месте** и возвращает список перемещений. В тесте можно проверить и то, и другое: `expectEqual(grid, …)` и `expectEqual(moves, …)`.
:::

::: hint Подсказка 3: проверка теста
Хороший тест должен **падать**, если код сломан. Убедитесь в этом: временно уберите в `getLineMatches` проверку серии после внутреннего цикла. Какие тесты упадут? А если убрать `type &&` из условия?
:::

## Проверьте

В консоли должно быть девять строк с `✓` и итог `Тестов пройдено: 9, упало: 0`. Мы проверили эталонное решение: все девять тестов проходят.

Затем сделайте эксперименты из третьей подсказки. Сломайте код в двух местах по очереди и посмотрите, какие тесты это поймают. Если ни один тест не упал, когда код сломан, значит, этот случай тестами не покрыт.

## Итоги главы

Теперь у нас есть полная логика match-3:

- **модель** `grid` отделена от **вида** `board` и не зависит от PixiJS;
- сетка создаётся без готовых троек;
- `getMatches` находит серии по строкам и столбцам, с фильтром по клеткам;
- ход разрешён, только если создаёт совпадение, и это проверяется на копии модели;
- совпадения убираются, фишки падают, пустые клетки досыпаются;
- каскад повторяется до стабильного состояния;
- логику можно проверять тестами.

Игра работает, но выглядит как набор мгновенных скачков. В следующей главе мы займёмся временем: тикер, плавное движение, функции плавности, анимированный обмен, падение с отскоком и каскад, растянутый во времени.
