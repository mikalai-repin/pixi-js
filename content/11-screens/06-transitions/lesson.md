Экраны сменяют друг друга мгновенно: только что было меню — и вот уже поле. Работает, но выглядит как сбой. **Переход** — короткая анимация между экранами — подсказывает игроку, что происходит, и делает игру цельной. Навигация уже умеет ждать `hide` старого экрана и `show` нового. Осталось написать эти методы.

В редакторе появилась вкладка `MaskTransition.ts` с заготовкой — к ней вернёмся во второй половине шага.

## Появление меню

Хорошая анимация появления не показывает всё сразу, а выводит элементы по очереди. Добавьте в `HomeScreen`:

```ts HomeScreen.ts
  /** Логотип опускается сверху, кнопка выпрыгивает */
  async show() {
    gsap.from(this.logo, { y: -200, duration: 0.6, ease: 'back.out' });
    gsap.from(this.subtitle, { alpha: 0, duration: 0.4, delay: 0.3 });
    await gsap.from(this.playButton.scale, { x: 0, y: 0, duration: 0.4, delay: 0.4, ease: 'back.out' });
  }

  /** Экран гаснет целиком */
  async hide() {
    await gsap.to(this, { alpha: 0, duration: 0.25 });
  }
```

- **`gsap.from`** анимирует **от** указанного значения **к текущему**. Текущие позиции уже расставил `resize`: навигация вызывает его до `show`. Поэтому `from` не нужно знать, где элемент должен оказаться;
- **`delay`** — сдвиг начала. Три анимации запускаются одновременно, но начинаются по очереди;
- **`await` только у последней** — она заканчивается позже всех. Когда `show` вернёт управление, навигация разблокирует экран;
- **`hide`** гасит экран целиком: экран — контейнер, и его `alpha` действует на всё содержимое.

Не забудьте `import gsap from 'gsap'`.

## Уход с экрана игры

```ts GameScreen.ts
  /** Исчезновение: поле уменьшается и гаснет */
  async hide() {
    gsap.to(this.board.scale, { x: 0, y: 0, duration: 0.4, ease: 'back.in' });
    await gsap.to(this, { alpha: 0, duration: 0.4 });
  }
```

`back.in` — зеркало `back.out`: поле сначала чуть подрастает, а потом резко уменьшается. В оригинале уход с экрана игры богаче: поле взрывается, а надпись «Время вышло» разрастается на весь экран. Взрывы мы научимся делать в главе 12.

## Маска-переход

К результату оригинал переходит эффектнее: новый экран появляется **внутри силуэта котла**, который растёт и вращается, пока не закроет весь экран. Это класс `MaskTransition`. В нём работает приём, который мы ещё не использовали: **маска-спрайт**.

В главе 4 маской была `Graphics`: видно всё, что внутри фигуры. Маской может быть и **спрайт**. Тогда видимость определяет **прозрачность** его текстуры: где текстура непрозрачна, содержимое видно, где прозрачна — нет. Картинка `white-cauldron` — белый силуэт котла на прозрачном фоне. Если сделать её маской экрана, экран будет виден в форме котла.

Допишите `play` в `MaskTransition.ts`:

```ts MaskTransition.ts
  /** Открывает target: маска растёт от нуля до размера, который накрывает весь экран */
  async play(target: Container) {
    this.mask.scale.set(0);
    this.mask.rotation = -0.5;
    // Маска должна быть в дереве сцены: кладём её в тот же контейнер
    target.addChild(this.mask);
    target.mask = this.mask;
    gsap.to(this.mask, { rotation: 0.5, duration: 0.7, ease: 'sine.in' });
    await gsap.to(this.mask.scale, { x: 30, y: 30, duration: 0.7, ease: 'quint.in' });
    target.mask = null;
    target.removeChild(this.mask);
  }
```

- **маска в дереве сцены** — ловушка из главы 4: маска, которой нет на сцене, ничего не показывает. Кладём её прямо в экран;
- **масштаб 30** — картинка котла 72 × 63 пикселя, при масштабе 30 это больше 2000 пикселей: котёл с запасом закрывает экран любого размера;
- **`quint.in`** — пятая степень: долго растёт медленно, а в конце стремительно. Котёл «вырастает» из точки;
- **маска снимается** в конце: держать её незачем, а у маски есть цена (врезка «Под капотом»).

Позицию маски — центр экрана — задаёт `resize` перехода. Экран результата вызывает его из своего `resize` и запускает переход первым делом в `show`:

```ts ResultScreen.ts
    // Экран открывается «расширяющимся котлом»
    await this.transition.play(this);
```

Это уже есть в `ResultScreen`: поле `transition`, вызовы `resize` и `play`. Добавьте экрану результата и `hide` — такой же, как у меню.

## Что получилось

Меню появляется по частям: логотип падает сверху с лёгким отскоком, проявляется подзаголовок, выпрыгивает кнопка. «Играть» — и меню гаснет. В конце игры поле подрастает и схлопывается, экран гаснет, а результат появляется из растущего вращающегося котла. Мы сняли кадры перехода прямо из тикера: в середине перехода экран результата виден только внутри силуэта котла.

## Эксперименты

- Замените в конструкторе `MaskTransition` текстуру `'white-cauldron'` на `'star'`. Экран результата будет появляться из растущей звезды: маской может быть любая картинка с прозрачностью.
- Уберите `target.addChild(this.mask)`. Экран результата пропадёт на всё время перехода: маска вне сцены.
- Поставьте длительность перехода 2 секунды, чтобы рассмотреть его.

::: deep Под капотом: как работает маска-спрайт
Маска из `Graphics` в WebGL обычно делается через **буфер трафарета** (stencil): видеокарта отмечает пиксели внутри фигуры и рисует содержимое только там. Это быстро, но умеет только «да» или «нет».

Маска-спрайт так не может: у неё полупрозрачные края. PixiJS рисует содержимое во временную текстуру, а потом выводит её на экран через специальный фильтр, который умножает каждый пиксель на прозрачность маски в той же точке. Отсюда цена: дополнительная текстура размером с область маски и лишний проход отрисовки. Для перехода длиной 0,7 секунды это не важно, а держать такую маску постоянно на большом экране не стоит. Поэтому переход снимает маску сразу, как только она стала не нужна.
:::
