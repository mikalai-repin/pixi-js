Таймер доходит до нуля и останавливается, а играть можно дальше. Пора закончить игру по-настоящему: когда время вышло, показать результат со звёздами и дать выбор — сыграть ещё раз или вернуться в меню. Так замкнётся полный цикл: меню → игра → результат.

В редакторе появились две вкладки:

- **`stats.ts`** — результаты игры. Функция `saveScore` запоминает последний счёт, `getLastScore` возвращает его, а `getGrade` переводит счёт в звёзды: 200 очков — одна, 600 — две, 1200 — три. Экран игры записывает сюда счёт, а экран результата читает. В оригинале для этого есть модуль `userStats`, который ещё и сохраняет рекорды; рекорд мы сделаем в практикуме;
- **`ResultScreen.ts`** — экран результата: панель `result-base` из бандла `result`, заголовок, три «слота» под звёзды, счёт и кнопки «Ещё раз» и «Меню». Не хватает только метода `show`.

## Время вышло — но не сразу конец

Когда таймер дошёл до нуля, игру нельзя оборвать на полуслове. Если в этот момент идёт каскад, фишки падают, совпадения исчезают, очки начисляются. Оригинальная игра дожидается конца каскада, и только потом показывает результат. Это честно: очки за последний ход засчитываются.

Значит, у поля нужно уметь спросить: идёт ли ещё ход? Флаг `processing` в `Board` уже есть, но он закрытый. Откройте его для чтения геттером:

```ts Board.ts
  /** Идёт ли сейчас ход: обмен или каскад с анимациями */
  get isProcessing() {
    return this.processing;
  }
```

## Конец игры в GameScreen

Добавьте в класс два флага:

```ts GameScreen.ts
  /** Время вышло: ждём конца каскада, чтобы перейти к результату */
  private timeUp = false;
  private finished = false;
```

`update` теперь знает о конце игры:

```ts GameScreen.ts
  /** Каждый кадр: время игры, а когда оно вышло — ждём конца каскада */
  update(ticker: Ticker) {
    if (this.timeUp) {
      if (!this.board.isProcessing) this.finish();
      return;
    }
    // Время идёт, только пока поле доступно: на отсчёте и паузе таймер стоит
    if (this.board.locked) return;
    this.remaining = Math.max(0, this.remaining - ticker.deltaMS);
    this.hud.setTime(this.remaining);
    if (this.remaining === 0) this.onTimeUp();
  }
```

Когда время вышло, `update` каждый кадр проверяет, закончился ли каскад. Это простой и надёжный способ дождаться события, у которого нет своего колбэка: опрашивать состояние в игровом цикле.

```ts GameScreen.ts
  /** Время вышло: ходы больше не принимаются, но начатый каскад доигрывает */
  private onTimeUp() {
    this.timeUp = true;
    this.board.locked = true;
    this.hud.buttonsVisible = false;
    const message = new Label('Время вышло!', { fontSize: 48, fill: 0xffd27f });
    message.position.copyFrom(this.board.position);
    this.addChild(message);
    gsap.from(message.scale, { x: 0, y: 0, duration: 0.4, ease: 'back.out' });
  }

  /** Каскад закончился: сохраняем счёт и через секунду показываем результат */
  private async finish() {
    if (this.finished) return;
    this.finished = true;
    saveScore(this.score);
    await gsap.to({}, { duration: 1 });
    navigation.showScreen('result');
  }
```

- **`board.locked = true`** — блокировка ввода: новых ходов не будет, но каскад, уже начатый в `Board`, доиграет. `locked` выключает события, а не анимации;
- **`gsap.from`** — как `gsap.fromTo`, только конечное значение — текущее. Надпись «выпрыгивает» из нулевого размера в свой обычный;
- **`finished`** — `update` вызывается каждый кадр, а `finish` ждёт целую секунду. Без флага за эту секунду он запустился бы ещё шестьдесят раз;
- **`gsap.to({}, { duration: 1 })`** — пустой твин как таймер на секунду. В отличие от `setTimeout`, он идёт по времени GSAP и, например, остановится вместе с остальными анимациями, когда в следующем шаге появится пауза.

Импортируйте `navigation`, `saveScore` и не забудьте зарегистрировать новый экран в `main.ts`: `navigation.register('result', ResultScreen)`.

## Показ результата

Осталось оживить экран результата. Добавьте в `ResultScreen` метод:

```ts ResultScreen.ts
  /** Звёзды выпрыгивают по одной, счёт набегает, кнопки появляются в конце */
  async show() {
    const score = getLastScore();
    const grade = getGrade(score);
    this.buttons.visible = false;
    for (let i = 0; i < grade; i++) {
      const star = this.stars[i];
      star.visible = true;
      await gsap.from(star.scale, { x: 0, y: 0, duration: 0.35, ease: 'back.out' });
    }
    const shown = { value: 0 };
    await gsap.to(shown, {
      value: score,
      duration: 1,
      ease: 'quad.out',
      onUpdate: () => {
        this.scoreText.text = String(Math.round(shown.value));
      },
    });
    this.buttons.visible = true;
    await gsap.from(this.buttons, { alpha: 0, duration: 0.3 });
  }
```

`await` внутри цикла делает анимацию последовательной: вторая звезда выпрыгивает, только когда закончилась первая. А пока `show` не закончился, навигация держит экран заблокированным, и нажать на кнопки до их появления нельзя.

::: task
Откройте у поля признак `isProcessing`. Когда время вышло, покажите «Время вышло!», дождитесь конца каскада, сохраните счёт и откройте экран результата. Напишите `show` экрана результата и зарегистрируйте его в `main.ts`.
:::

## Что получилось

Через минуту игры поле замирает, и над ним выпрыгивает «Время вышло!». Если шёл каскад, он доигрывает. Через секунду появляется экран результата: звёзды выпрыгивают по одной, счёт набегает от нуля, внизу кнопки «Ещё раз» и «Меню».

Ждать минуту при проверке долго, поэтому наш автотест укоротил игру до девяти секунд. В каждом прогоне результат открывался через секунду после конца каскада, «Ещё раз» запускал новую игру, а у тикера после смены экранов оставалось два слушателя: старый экран игры корректно отписался.

## Эксперименты

- Поставьте `GAME_TIME = 10_000`, чтобы быстрее проверить. Не забудьте вернуть 60 секунд.
- Уберите проверку `if (this.finished) return`. Пока `finish` ждёт свою секунду, `update` запускает его снова на каждом кадре, и навигация получает десятки просьб показать результат. Мы проверили: за 14 секунд экран результата создавался заново 21 раз, и звёзды со счётом каждый раз начинали анимацию сначала. Верните проверку.
- Поменяйте пороги в `GRADE_SCORES`, например на `[50, 100, 150]`, и наберите три звезды.

::: deep Под капотом: кто уничтожает старый экран
Кнопка «Ещё раз» вызывает `navigation.showScreen('game')`. Навигация прячет экран результата, отписывает его от тикера и вызывает `destroy({ children: true })`. Вместе с экраном уничтожаются все его дети: панель, звёзды, кнопки. А экран игры, который был до результата, уже уничтожен тем же способом: вместе с полем, фишками и интерфейсом, а `Hud` в своём `destroy` удалил растровый шрифт таймера. Поэтому каждая новая игра начинается с чистого листа.

Есть и подводный камень. Если бы экран игры уничтожили, пока на нём шли анимации GSAP (например, взлетало «+30»), твины продолжили бы писать в уничтоженные объекты. Нас спасает секундная пауза в `finish`: за это время все надписи успевают долететь и уничтожиться сами.
:::
