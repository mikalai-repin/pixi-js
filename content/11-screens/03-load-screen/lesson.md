Экран загрузки до сих пор живёт в `main.ts` отдельно от навигации: `main.ts` сам создаёт его, грузит бандлы `game` и `common`, обновляет полоску и уничтожает экран. А бандл `home` для меню навигация грузит молча, без всякого экрана. Если сеть медленная, игрок нажмёт «Играть» и будет смотреть на застывшее меню.

Сделаем, как в настоящих играх: **навигация сама показывает экран загрузки**, если ресурсов следующего экрана ещё нет.

## Экран загрузки — тоже экран

`LoadScreen` уже реализует `AppScreen`: у него есть `update` для пульсирующей точки, `resize` и `hide`, в котором он плавно гаснет. И ещё метод `setProgress(progress)`, которого нет в интерфейсе экрана. Значит, навигации нужен не просто класс экрана, а класс экрана **с методом `setProgress`**. Это можно выразить типом:

```ts navigation.ts
  /** Экран загрузки: показывается, пока грузятся бандлы следующего экрана */
  loadScreen?: new () => AppScreen & { setProgress(progress: number): void };
  /** Бандлы, которые уже загружены */
  private readonly loadedBundles = new Set<string>();
```

`AppScreen & { setProgress(...) }` — пересечение типов: «и экран, и умеет показывать прогресс». Почему навигация не импортирует `LoadScreen` сама? По той же причине, что и экраны в прошлом шаге: навигация — общий механизм и не должна знать конкретные экраны. Какой экран загрузки использовать, решает `main.ts`.

## Загрузка с экраном

Замените в `showScreen` строку с `Assets.loadBundle` на блок:

```ts navigation.ts
    // Ресурсы нового экрана: если их ещё нет, на время загрузки показываем экран загрузки
    const bundles = ctor.assetBundles ?? [];
    const missing = bundles.filter((name) => !this.loadedBundles.has(name));
    if (missing.length > 0) {
      if (this.currentScreen) await this.removeScreen(this.currentScreen);
      this.currentScreen = undefined;
      const loadScreen = this.loadScreen ? new this.loadScreen() : undefined;
      if (loadScreen) await this.addScreen(loadScreen);
      await Assets.loadBundle(missing, (progress) => loadScreen?.setProgress(progress));
      missing.forEach((name) => this.loadedBundles.add(name));
      if (loadScreen) await this.removeScreen(loadScreen);
    }
```

1. **какие бандлы ещё не загружены** — навигация ведёт свой список `loadedBundles`. У `Assets` нет простого вопроса «загружен ли бандл», поэтому так делает и оригинал;
2. если чего-то не хватает, **старый экран уходит** сразу, а на его место встаёт экран загрузки. Он проходит через тот же `addScreen`: получает размер, подписывается на тикер;
3. **`loadBundle` с колбэком прогресса** — полоска растёт по мере загрузки, как в главе 5;
4. экран загрузки **уходит**: `removeScreen` дождётся его `hide`, то есть плавного угасания.

Дальше `showScreen` работает как раньше: старого экрана уже нет, и создаётся новый.

## Загрузка заранее

Хорошо бы, чтобы экран загрузки был виден только при запуске игры. Пока игрок смотрит на меню, остальные бандлы можно спокойно загрузить. В главе 5 для этого был `Assets.backgroundLoadBundle`. Но о бандлах, загруженных так, наша навигация не узнает, и при переходе в игру на мгновение покажет экран загрузки. Поэтому добавим в навигацию свой метод:

```ts navigation.ts
  /** Тихо загружает бандлы заранее, пока игрок занят текущим экраном */
  async preload(bundles: string[]) {
    await Assets.loadBundle(bundles);
    bundles.forEach((name) => this.loadedBundles.add(name));
  }
```

Если игрок нажмёт «Играть» раньше, чем загрузка закончится, ничего страшного: `showScreen` увидит, что бандла ещё нет, покажет экран загрузки и вызовет `loadBundle` для того же бандла. `Assets` не начнёт загрузку заново, а вернёт промис уже идущей. Полоска просто начнётся не с нуля.

## main.ts становится ещё короче

Удалите из `main.ts` весь блок с экраном загрузки и `loadBundle(['game', 'common'])`. Вместо него:

```ts main.ts
// --- Экраны: дальше всем управляет навигация ---
// Экраны регистрируются здесь, в одном месте: сами экраны друг друга не импортируют
navigation.register('home', HomeScreen);
navigation.register('game', GameScreen);
app.renderer.on('resize', (width, height) => navigation.resize(width, height));
navigation.resize(app.screen.width, app.screen.height);
// Пока грузятся бандлы следующего экрана, навигация покажет экран загрузки
navigation.loadScreen = LoadScreen;
await navigation.showScreen('home');
// Пока игрок в меню, заранее грузим остальное: тогда экран загрузки больше не понадобится
navigation.preload(['game', 'result']);
```

`preload` вызывается без `await`: дожидаться его не нужно, пусть грузится, пока игрок в меню. Бандл `preload` с логотипом и точкой для экрана загрузки по-прежнему грузится в начале `main.ts`: без него экрану загрузки нечего показать.

::: task
Научите навигацию показывать экран загрузки, пока грузятся бандлы следующего экрана, и добавьте метод `preload`. Уберите ручную загрузку из `main.ts`.
:::

## Что получилось

При запуске на месте меню сначала виден экран загрузки: логотип PixiJS, мигающая точка и полоска. Пока грузятся бандлы `home` и `common`, полоска растёт, потом экран гаснет и появляется меню. А «Играть» открывает игру сразу: пока вы смотрели на меню, `game` уже загрузился. Мы проверили оба пути: без `preload` после нажатия «Играть» навигация показывает экран загрузки, а с ним сразу открывается игра.

## Эксперименты

- Уберите строку `navigation.preload(...)` и нажмите «Играть». Перед игрой мелькнёт экран загрузки: бандл `game` грузится только сейчас.
- Включите в DevTools браузера замедление сети (вкладка Network, режим «Slow 4G») и перезапустите превью. Полоска загрузки станет хорошо видна. Не забудьте выключить замедление.

::: deep Под капотом: что делает Assets с одним и тем же бандлом
У `Assets` внутри кэш промисов: для каждого файла он помнит промис его загрузки. Первый `loadBundle` создаёт промисы и начинает загрузку. Второй вызов для тех же файлов — пока загрузка идёт или уже закончилась — получает **те же** промисы. Поэтому загрузить бандл дважды одновременно невозможно, и `preload` с `showScreen` спокойно работают с одним бандлом.

Фоновая загрузка `backgroundLoadBundle` устроена иначе: она грузит файлы по одному, с низким приоритетом, чтобы не мешать основной загрузке. Наш `preload` грузит обычным способом, и для четырёх небольших атласов это неважно. Но в большой игре с десятками мегабайт ресурсов фоновая загрузка бережнее к сети, и тогда навигации пришлось бы узнавать о готовности бандлов иначе.
:::
