Вся игра до сих пор живёт на одном экране: панель «Играть» поверх поля, а когда время выходит, не происходит ничего. Настоящая игра состоит из **экранов**: загрузка, главное меню, сама игра, результат. Поверх экранов открываются **попапы**: пауза, настройки. В этой главе разделим игру на экраны, научимся переключаться между ними с анимацией и закончим игру по таймеру.

## Что изменилось в коде

Перед главой мы основательно переложили код. Нового в нём нет, но файлов стало больше:

| Файл | Что в нём |
|---|---|
| `GameScreen.ts` | **Вся игра из `main.ts`**: поле, интерфейс, подсказка, панель настроек, очки, время, стартовая панель. Позиции из функции `layout` теперь в методе `resize` |
| `app.ts` | Само приложение: `export const app = new Application()`. Экранам нужны его тикер и размер, и теперь любой файл может его импортировать. А инициализирует его по-прежнему `main.ts` |
| `main.ts` | Только запуск: `app.init`, ресайз, загрузка, фон и экран загрузки |
| `LoadScreen.ts` | Больше не получает тикер в конструкторе: у него появился метод `update(ticker)`, и вызывать его будет тот, кто показывает экран |
| `Piece.ts` | Функция плавности `singleBounce` переехала сюда, а файл `tween.ts` удалён: со времён GSAP он был нужен только ради неё |
| `Hud.ts` | В `destroy` удаляет растровый шрифт таймера: скоро интерфейс будет создаваться заново в каждой игре |

`GameScreen` пока не умеет ничего показывать, и `main.ts` его не создаёт. В превью только фон. Это и есть задание шага.

## Что общего у экранов

Меню, игра и результат совсем разные, но у всех одни и те же моменты жизни:

1. экран **создают** и добавляют на сцену;
2. ему сообщают **размер экрана**, чтобы он расставил элементы, а потом сообщают каждый раз, когда размер меняется;
3. его **показывают**: у меню логотип падает сверху, у игры идёт отсчёт. Это занимает время;
4. пока экран виден, он может хотеть делать что-то **каждый кадр**, как игра с таймером;
5. его **прячут**: экран гаснет или уезжает;
6. его **уничтожают**.

Это **жизненный цикл экрана**. Если описать его общим интерфейсом, управлять любым экраном можно одинаково, не зная, что внутри. В оригинальной Puzzling Potions это интерфейс `AppScreen` в `utils/navigation.ts`. Напишем такой же в `navigation.ts`:

```ts navigation.ts
import type { Container, Ticker } from 'pixi.js';

/**
 * Экран игры: меню, игра, результат, попап. Все методы необязательные —
 * у каждого экрана свой набор. Вызывать их будет навигация. Как AppScreen в Puzzling Potions
 */
export interface AppScreen extends Container {
  /** Экран уже на сцене, но ещё не показан: расставить начальное состояние */
  prepare?(): void;
  /** Анимация появления. Навигация дождётся её конца */
  show?(): Promise<void>;
  /** Анимация исчезновения. После неё экран уничтожат */
  hide?(): Promise<void>;
  /** Каждый кадр, пока экран на сцене */
  update?(ticker: Ticker): void;
  /** Изменился размер экрана */
  resize?(width: number, height: number): void;
}
```

- **`extends Container`** — экран — это контейнер. Его можно добавить на сцену, сделать прозрачным, замаскировать;
- **все методы необязательные** — экрану результата не нужен `update`, экрану загрузки не нужен `show`. Вызывающая сторона проверит, есть ли метод: `screen.update?.(ticker)`;
- **`show` и `hide` асинхронные** — анимации появления и исчезновения длятся, и тот, кто переключает экраны, должен уметь их дождаться.

## Игра как экран

Теперь `GameScreen` должен реализовать этот интерфейс. Метод `resize` у него уже есть. Добавьте в класс два метода:

```ts GameScreen.ts
  /** Появление экрана: ждём «Играть», затем отсчёт, затем игра */
  async show() {
    await this.waitForPlay();
    await playCountdown(this, this.board.x, this.board.y);
    this.board.locked = false;
    this.board.alpha = 1;
    this.hud.buttonsVisible = true;
  }

  /** Каждый кадр: время игры */
  update(ticker: Ticker) {
    // Время идёт, только пока поле доступно: на старте, отсчёте и паузе таймер стоит
    if (this.board.locked || this.remaining === 0) return;
    this.remaining = Math.max(0, this.remaining - ticker.deltaMS);
    this.hud.setTime(this.remaining);
  }
```

Это тот же код, что был в `main.ts`. Только раньше время уменьшал анонимный слушатель `app.ticker.add(...)`, а теперь — метод экрана. Подписывать его на тикер будет не сам экран, а тот, кто его показывает. `waitForPlay` — стартовая панель из главы 10, уже лежит в классе.

Заметьте `implements AppScreen` в объявлении класса: TypeScript проверит, что методы совпадают с интерфейсом по сигнатурам.

## Запускаем экран

Пока навигации нет, проведём экран по жизненному циклу вручную. В конец `main.ts`:

```ts main.ts
// --- Экран игры: main.ts только создаёт его и проводит по жизненному циклу ---
const game = new GameScreen();
app.stage.addChild(game);
game.resize(app.screen.width, app.screen.height);
app.renderer.on('resize', (width, height) => game.resize(width, height));
app.ticker.add(game.update, game);
await game.show();
```

::: task
Опишите интерфейс `AppScreen` в `navigation.ts`, добавьте в `GameScreen` методы `show` и `update`, а в `main.ts` создайте экран игры и проведите его по жизненному циклу.
:::

## Что получилось

Игра выглядит и работает ровно как в конце главы 10: панель «Играть», отсчёт, поле, таймер, пауза и настройки. Но устроена иначе: `main.ts` стал коротким, а игра — самостоятельным классом. Проверка подтвердила: после нажатия «Играть» отсчёт длится около пяти секунд, а слушателей у тикера всего два — отрисовка сцены и `update` экрана игры.

## Эксперименты

- Закомментируйте строку `app.ticker.add(game.update, game)`. Таймер застынет на 1:00: экран больше не получает кадров. Верните строку.
- Поменяйте тип аргумента: `update(ticker: number)`. TypeScript сразу сообщит, что свойство `update` в `GameScreen` несовместимо с таким же свойством в `AppScreen`. Это работа `implements`: интерфейс проверяет каждый метод, который экран решил реализовать. Верните `Ticker`.

::: deep Под капотом: почему app в отдельном файле
Экранам нужен `app`: тикер, рендерер, размер экрана. Первая мысль — экспортировать его из `main.ts`, как делает оригинал: `export const app = new Application()`. Но `main.ts` сам импортирует экраны, и получился бы **цикл**: `main.ts` → `GameScreen.ts` → `main.ts`. Кроме того, в `main.ts` есть `await` на верхнем уровне, и модули, которые его импортируют, ждали бы, пока он выполнится до конца.

Отдельный модуль `app.ts` без зависимостей разрывает цикл: его импортируют и `main.ts`, и экраны, а он не импортирует никого. Создать объект можно сразу, а `init` вызывает `main.ts`. Экраны обращаются к `app` только из методов, к этому моменту приложение давно инициализировано.
:::
