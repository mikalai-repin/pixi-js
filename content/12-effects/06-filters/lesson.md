Всё, что мы делали до сих пор, — это новые объекты на сцене: кольца, копии, искры. Но бывают эффекты, которые меняют **уже нарисованную картинку**: размыть экран под попапом, обесцветить поле, когда время вышло. Для этого в PixiJS есть **фильтры**.

## Что такое фильтр

Фильтр — это обработка картинки объекта после отрисовки. Когда у контейнера есть фильтр, PixiJS рисует контейнер со всеми детьми не сразу на экран, а во **временную текстуру**. Потом запускает на видеокарте небольшую программу — **шейдер**, которая для каждого пикселя результата решает, какого он цвета, читая пиксели временной текстуры. Размытие усредняет соседние пиксели, обесцвечивание смешивает каналы цвета. Готовая картинка выводится на экран.

Фильтры задаются массивом, они применяются по очереди:

```ts
container.filters = [new BlurFilter({ strength: 6 })];
container.filters = []; // убрать все
```

## Размытие под попапом

Попап паузы затемняет экран, но под затемнением всё так же резко видны фишки, таймер, подсказка. Оригинальная Puzzling Potions размывает экран под попапом: внимание сразу переходит на панель. Сделаем так же. Размытие — **`BlurFilter`**:

```ts GameScreen.ts
/** Сила размытия экрана под попапом */
const BLUR_STRENGTH = 6;
```

```ts GameScreen.ts
  /** Размытие экрана под попапом: один фильтр на всю игру */
  private readonly blurFilter = new BlurFilter({ strength: 0 });
```

Имя `blur` занято: так называется метод экрана из главы 11, который вызывается при уходе вкладки в фон.

Опции `BlurFilter`:

- **`strength`** — сила размытия, примерно радиус в пикселях. По умолчанию 8;
- **`quality`** — число проходов. Размытие делается по горизонтали и по вертикали отдельно, и каждое — несколько раз подряд: так результат мягче. По умолчанию 4, то есть 4 прохода по горизонтали и 4 по вертикали;
- **`kernelSize`** — сколько соседних пикселей читает один проход: 5, 7, 9… По умолчанию 5.

На паузе фильтр включается, а сила плавно растёт от нуля:

```ts GameScreen.ts {5-7}
  pause() {
    this.paused = true;
    this.pausedTweens = gsap.exportRoot();
    this.pausedTweens.pause();
    // Экран под попапом размывается. Твин создан после exportRoot, поэтому он идёт
    addFilter(this, this.blurFilter);
    gsap.fromTo(this.blurFilter, { strength: 0 }, { strength: BLUR_STRENGTH, duration: 0.3 });
  }
```

```ts GameScreen.ts {3-4}
  resume() {
    this.paused = false;
    gsap.killTweensOf(this.blurFilter);
    removeFilter(this, this.blurFilter);
    this.pausedTweens?.resume();
```

GSAP анимирует `strength` как любое другое свойство: у фильтра это сеттер, который передаёт новую силу проходам размытия и пересчитывает отступ.

## Почему не push

Что за `addFilter`? Почему не `this.filters.push(this.blurFilter)`? Попробуйте — получите ошибку «Cannot add property 1, object is not extensible». Сеттер `filters` копирует переданный массив и **замораживает** копию (`Object.freeze`): PixiJS должен знать о каждом изменении списка фильтров, а `push` прошёл бы мимо сеттера. Менять список можно только присваиванием нового массива.

Скоро у экрана будет больше одного фильтра (ударная волна в шаге 8), поэтому напишем помощников, которые добавляют и убирают один фильтр, не трогая остальные. В конец `GameEffects.ts`:

```ts GameEffects.ts
/** Добавляет объекту фильтр. Массив filters заморожен: push в него не сработает, нужен новый массив */
export function addFilter(target: Container, filter: Filter) {
  target.filters = [...(target.filters ?? []), filter];
}

/** Убирает у объекта фильтр, остальные фильтры остаются */
export function removeFilter(target: Container, filter: Filter) {
  target.filters = (target.filters ?? []).filter((item) => item !== filter);
}
```

`Filter` импортируйте как тип: `type Filter` в списке импорта из `pixi.js`.

## Область фильтра

Какого размера временная текстура? По умолчанию — по **границам** объекта: перед каждым кадром PixiJS считает, сколько места занимают все его дети, и добавляет **отступ** (`padding`) — размытию нужно место, чтобы «расплыться» за края. У `BlurFilter` с силой 8 отступ 16 пикселей.

Экрану игры точные границы не нужны: пусть фильтры работают по всему экрану. **Область фильтра** (`filterArea`) задаёт прямоугольник вручную, в локальных координатах объекта. Тогда границы не считаются вовсе. В начало `resize`:

```ts GameScreen.ts
    // Фильтры экрана работают в прямоугольнике экрана: так их границы не пересчитываются каждый кадр
    this.filterArea = new Rectangle(0, 0, width, height);
```

Есть и случай, когда `filterArea` обязателен. Помните, что у контейнера частиц нет границ? Поставьте фильтр прямо на него — `this.sparks.filters = [...]`, — и искры исчезнут целиком: область фильтра пустая. Мы проверили: с `filterArea` на родителе контейнера частиц всё рисуется, без него — нет.

## Обесцвечивание

Второй фильтр — в конце игры. Когда время вышло, поле продолжает доигрывать каскад, но ходить уже нельзя. Пусть оно выцветет, как старая фотография. Это **`ColorMatrixFilter`** — фильтр с **цветовой матрицей**: каждый новый канал цвета (R, G, B, A) считается как сумма старых каналов с коэффициентами плюс сдвиг. Матрица 4 × 5 = 20 чисел. Готовые методы заполняют её за вас: `desaturate()` убирает цвет, `brightness()` меняет яркость, `sepia()`, `hue()` и десяток других.

В `onTimeUp`, перед надписью «Время вышло!»:

```ts GameScreen.ts
    // Поле выцветает: ходить больше нельзя
    const grey = new ColorMatrixFilter();
    grey.desaturate();
    this.board.filters = [grey];
    gsap.fromTo(grey, { alpha: 0 }, { alpha: 1, duration: 0.6 });
```

У `ColorMatrixFilter` есть свойство `alpha`: это не прозрачность объекта, а **доля эффекта**. При 0 фильтр возвращает исходные цвета, при 1 — полностью обесцвеченные, между ними — смесь. Анимируя `alpha`, мы плавно вытягиваем цвет из поля.

Одна ловушка: в комментариях к `desaturate` в исходниках PixiJS есть пример цепочки `colorMatrix.desaturate().brightness(1.2)`. Он не сработает: `desaturate()` ничего не возвращает (`void`), и TypeScript сообщит, что у `void` нет `brightness`. Вызывайте методы по отдельности. И обратите внимание: у `brightness` два обязательных параметра, второй — `multiply` (умножить на текущую матрицу или заменить её).

Не забудьте импорт: `BlurFilter`, `ColorMatrixFilter`, `Rectangle` из `pixi.js`, `addFilter` и `removeFilter` из `./GameEffects`.

## Что получилось

Нажмите паузу: экран под попапом за треть секунды расплывается, остаётся только цветовое пятно поля. «Продолжить» — и картинка снова резкая. А в конце игры поле выцветает в серый, и на нём загорается «Время вышло!». Проверка подтвердила: на паузе у экрана ровно один фильтр, `BlurFilter`, после продолжения — ни одного; в конце игры у поля `ColorMatrixFilter`, и экран результата открывается без ошибок.

## Эксперименты

- Попробуйте `this.filters.push(this.blurFilter)` вместо `addFilter` — увидите ошибку про «not extensible».
- Поставьте `quality: 1` в конструкторе `BlurFilter` и `BLUR_STRENGTH = 20`. Вместо мягкого пятна появятся полупрозрачные копии картинки, сдвинутые в разные стороны: один проход с пятью отсчётами на 20 пикселей читает соседей слишком редко, и между ними остаются «дыры». Несколько проходов подряд эти дыры замазывают.
- Замените `grey.desaturate()` на `grey.sepia(false)` или `grey.hue(180, false)`.
- Создайте размытие по-старому, как в оригинале: `new BlurFilter(5)`. Работает, но в консоли — предупреждение «PixiJS Deprecation Warning: BlurFilter constructor params are now options object». Это сигнатура v7.

## Связь с оригиналом

В Puzzling Potions размытие ставит сам попап: `PausePopup.show` пишет `navigation.currentScreen.filters = [new BlurFilter(5)]`, а `hide` — `filters = []`. Сила там не анимируется. Любопытно, что `PausePopup` и `InfoPopup` используют старую сигнатуру конструктора, а `SettingsPopup` — уже новую, `new BlurFilter({ strength: 4 })`: код писали в разное время. У нас за свои фильтры отвечает экран: так попапу не нужно знать о чужих фильтрах.

::: deep Под капотом: сколько стоит фильтр
Каждый фильтр — это:

1. **Переключение цели отрисовки**: вместо экрана объект рисуется во временную текстуру. PixiJS берёт её из пула текстур (`TexturePool`), а не создаёт каждый кадр.
2. **Проходы шейдера** по всем пикселям области. У размытия с `quality: 4` это 8 проходов: 4 по горизонтали, 4 по вертикали. На весь экран 583 × 700 при `resolution: 1` — это 8 раз по 400 тысяч пикселей, и каждый пиксель читает 5 соседей.
3. **Разрыв батча**: всё, что внутри фильтра, рисуется отдельно от того, что снаружи.

Для экрана под паузой это нормально: игра стоит. Но держать постоянное размытие на всём экране во время игры — расточительно, особенно на слабых телефонах. Отсюда приёмы: снижать `resolution` фильтра (размытию не нужна полная чёткость, `resolution: 0.5` вчетверо уменьшает число пикселей), уменьшать `quality`, задавать `filterArea` поменьше. А для эффекта «размытый фон» иногда проще один раз отрисовать экран в текстуру и показывать её (глава 16, `RenderTexture`).
:::
