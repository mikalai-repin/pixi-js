Каждая исчезнувшая фишка теперь создаёт два объекта — кольцо и копию — и через полсекунды их уничтожает. За минуту игры это сотни `new` и `destroy`. А в следующем шаге на каждую фишку добавится ещё дюжина искр. Пора научиться не выбрасывать объекты, а **использовать повторно**.

## Зачем переиспользовать

Создать спрайт в JavaScript недёшево: конструктор `Container` заводит десятки полей, точки позиции, масштаба и поворота, матрицы трансформации. `destroy` всё это разбирает. А потом сборщик мусора однажды остановит игру на несколько миллисекунд, чтобы освободить память от сотен брошенных объектов. Если это случится посреди анимации, игрок увидит рывок.

Есть и вторая причина. У каждого нового `Graphics` свой `GraphicsContext`: при первой отрисовке фигура разбивается на треугольники и выгружается на видеокарту (врезка «из чего на самом деле состоит круг» в главе 4). Новое кольцо — новая геометрия, каждый раз.

**Пул объектов** (object pool) решает обе проблемы. Это склад: когда объект нужен, берём свободный со склада, а если склад пуст — создаём новый. Когда объект отслужил, не уничтожаем его, а **возвращаем на склад**. Через несколько ходов на складе лежит ровно столько объектов, сколько одновременно бывает нужно, и новые больше не создаются.

## Класс Pool

В редакторе появилась вкладка `pool.ts` с заготовкой. Напишите пул:

```ts pool.ts
/**
 * Пул: склад объектов для повторного использования. get выдаёт свободный объект
 * или создаёт новый, giveBack возвращает объект на склад.
 * Как Pool в Puzzling Potions, но новые объекты создаёт переданная функция
 */
export class Pool<T> {
  /** Свободные объекты */
  private readonly items: T[] = [];
  /** Сколько объектов пул создал за всё время */
  created = 0;

  constructor(private readonly create: () => T) {}

  /** Свободный объект со склада, а если склад пуст — новый */
  get(): T {
    const item = this.items.pop();
    if (item !== undefined) return item;
    this.created++;
    return this.create();
  }

  /** Возвращает объект на склад */
  giveBack(item: T) {
    // Объект, сданный дважды, выдали бы двум владельцам сразу
    if (!this.items.includes(item)) this.items.push(item);
  }
}
```

Пул ничего не знает о PixiJS: он хранит что угодно. Как создать новый объект, ему говорит функция `create`. Счётчик `created` понадобится, чтобы проверить, что пул действительно экономит.

## Пулы в слое эффектов

Заведите в `GameEffects` два пула:

```ts GameEffects.ts
  /** Кольца и летящие копии зелий не создаются каждый раз заново, а берутся из пулов */
  private readonly rings = new Pool(() => new Graphics(RING_CONTEXT));
  private readonly copies = new Pool(() => new Sprite({ anchor: 0.5 }));
```

Кольца теперь рисуются из одного **`GraphicsContext`**, как подложки клеток в главе 4: геометрия строится один раз на все кольца. Добавьте его к константам:

```ts GameEffects.ts
/** Геометрия кольца одна на все кольца, как подложки клеток в главе 4 */
const RING_CONTEXT = new GraphicsContext().circle(0, 0, RING_RADIUS).stroke({ width: 4, color: 0xffffff });
```

Копии создаются без текстуры: `new Sprite({ anchor: 0.5 })` — спрайт с пустой текстурой и якорем в центре. Текстуру мы зададим при каждой выдаче из пула.

Теперь `playRing`:

```ts GameEffects.ts {2,4-6,11-13}
  private async playRing(position: PointData) {
    const ring = this.rings.get();
    // Объект из пула помнит прошлую жизнь: задаём всё, что меняет анимация
    ring.position.copyFrom(position);
    ring.scale.set(0.3);
    ring.alpha = 1;
    this.addChild(ring);
    gsap.to(ring, { alpha: 0, duration: 0.4, ease: 'quad.in' });
    await gsap.to(ring.scale, { x: 1, y: 1, duration: 0.4, ease: 'quad.out' });
    // Вместо destroy — обратно на склад
    this.removeChild(ring);
    this.rings.giveBack(ring);
  }
```

Главное правило пула: **объект со склада нужно «отмыть»**. Кольцо вернулось на склад прозрачным и большим — таким его оставила прошлая анимация. Если не вернуть `alpha = 1`, следующая анимация пойдёт от нуля к нулю, и кольцо будет невидимым.

И `playFlyToScore`:

```ts GameEffects.ts
    const copy = this.copies.get();
    copy.texture = Texture.from(textureName);
    copy.setSize(TILE_SIZE);
    copy.position.copyFrom(from);
```

```ts GameEffects.ts
    await gsap.to(copy.scale, { x: scale, y: scale, duration, ease: 'back.in(3)' });
    // Твины x и y кончаются в тот же момент, но могли и не успеть: копия не должна уйти на склад с живыми твинами
    gsap.killTweensOf(copy);
    this.removeChild(copy);
    this.copies.giveBack(copy);
```

Вторая опасность пула — **твины, которые пережили объект**. Мы ждём только твин масштаба. Твины `x` и `y` той же длительности закончатся в тот же кадр, но если бы хоть один был длиннее, он продолжил бы двигать копию, которую уже выдали новому владельцу. `gsap.killTweensOf(copy)` гарантирует, что на склад копия уходит «чистой». Оригинальная Puzzling Potions делает то же самое: `killTweensOf` перед каждым использованием фишки из пула.

## Что получилось

На экране ничего не изменилось — так и должно быть. Изменилось то, что под капотом. Чтобы убедиться, выполните в консоли браузера на странице превью (DevTools, контекст фрейма превью):

```js
__PIXI_APP__.stage.getChildByLabel('effects', true).copies.created
```

`private` в TypeScript — только проверка при компиляции, из консоли поле доступно. Проверка сделала шесть ходов подряд: за это время с поля исчезло 28 фишек, а пулы создали всего 7 колец и 10 копий. Без пулов это было бы 28 колец и 28 копий, и каждую пришлось бы уничтожить. Копий нужно больше, чем колец: кольцо живёт 0,4 секунды, а копия летит до секунды, и одновременно в воздухе их бывает больше.

## Эксперименты

- Уберите строку `ring.alpha = 1`. Первые кольца видны, а после первого хода кольца исчезают: из пула приходят полностью прозрачные. Видны будут только кольца, для которых склад был пуст и пул создал новые.
- Добавьте в `giveBack` вывод `console.log(this.items.length)`. Первые ходы наибольшее число растёт, потом перестаёт: склад «дорос» до самого большого числа объектов, нужных одновременно.

## Связь с оригиналом

В оригинале пул устроен чуть иначе: `MultiPool` в `utils/pool.ts` хранит отдельный склад для каждого класса, `pool.get(Match3Piece)` создаёт объект конструктором без аргументов, а настраивает его метод `setup`. Из пула берутся фишки поля, копии в полёте и взрывы. Даже навигация создаёт экраны через `pool.get(ctor)`, а уходящий экран не уничтожает, а сбрасывает методом `reset`. Правда, обратно в пул она его не сдаёт, так что каждый `pool.get` создаёт новый экран, — любопытная деталь, к которой вернёмся при разборе оригинала в главе 15.

::: deep Под капотом: почему мы не кладём в пул надписи «+30»
В главе 9 надписи «+N» создаются через `new Label` и уничтожаются. Кажется, им прямая дорога в пул. Но вспомните главу 9: дорогая часть `Text` — не сам объект, а **отрисовка текста в текстуру** через canvas и её выгрузка на видеокарту. Надпись из пула получит новый текст, «+40» вместо «+30», и отрисуется заново. Экономия — только конструктор. Пул окупается там, где объект после выдачи почти не меняется: кольцо с общей геометрией, спрайт с текстурой из атласа, частица.

Ещё одно следствие: у объектов на складе нет родителя, и `destroy({ children: true })` экрана их не уничтожит. Для спрайтов и колец это не страшно: своих текстур у них нет (текстуры зелий принадлежат атласу, геометрия колец — общему `RING_CONTEXT`), и сборщик мусора уберёт их вместе с самим `GameEffects`, когда на него не останется ссылок.
:::
