Кольцо и полёт — хорошо, но самый узнаваемый эффект в играх — **частицы**: искры, дым, брызги, осколки. Это много маленьких одинаковых картинок, каждая со своей скоростью, и живут они долю секунды. Пусть каждое зелье взрывается дюжиной искр своего цвета.

Дюжина искр на фишку, тройка — уже 36 объектов, каскад — сотня. Можно делать их спрайтами, оригинал так и поступает. Но в PixiJS есть инструмент, созданный именно для этого.

## ParticleContainer

**Контейнер частиц** (`ParticleContainer`) рисует тысячи маленьких картинок за **один вызов отрисовки**. В нём лежат не спрайты, а **частицы** (`Particle`) — облегчённые объекты всего с несколькими свойствами: позиция `x`/`y`, масштаб `scaleX`/`scaleY`, якорь `anchorX`/`anchorY`, поворот `rotation`, тонирование `tint`, прозрачность `alpha` и текстура.

У частицы нет того, что есть у любого `Container`: детей, событий, масок, фильтров, своей матрицы трансформации. Именно поэтому она лёгкая. Цена — ограничения:

- **одна текстура на всех**: точнее, один источник текстуры, разные кадры одного атласа можно;
- **добавлять частицы — только `addParticle`**: `addChild` у контейнера частиц выбрасывает ошибку;
- **у контейнера нет границ**: `getBounds()` всегда пустой прямоугольник, считать границы тысяч частиц каждый кадр слишком дорого.

И главное — нужно заранее сказать контейнеру, какие свойства частиц будут меняться.

## Статические и динамические свойства

Видеокарта рисует частицы из **буферов** — больших массивов чисел в её памяти: для каждой частицы там лежат координаты углов, текстурные координаты, цвет. Перекладывать все эти числа в видеопамять каждый кадр — работа. Поэтому свойства частиц делятся на группы, и для каждой группы вы решаете:

- **динамическая** (dynamic) — выгружается на видеокарту каждый кадр;
- **статическая** (static) — только когда меняется сам список частиц (добавили, убрали) или когда вы вызвали `container.update()`.

Групп пять — это опция `dynamicProperties`:

| Группа | Какие свойства частицы | По умолчанию |
|---|---|---|
| `position` | `x`, `y` | динамическая |
| `rotation` | `rotation` | статическая |
| `vertex` | `scaleX`, `scaleY`, `anchorX`, `anchorY`, размер кадра | статическая |
| `uvs` | кадр текстуры | статическая |
| `color` | `tint`, `alpha` | статическая |

Наши искры летят, уменьшаются и гаснут: нужны `position`, `vertex` и `color`.

## Искра

Частица не умеет двигаться сама: каждый кадр мы сдвигаем её по скорости. Значит, кроме свойств `Particle` искре нужны скорость и возраст. `Particle` — обычный класс, его можно унаследовать. Добавьте в `GameEffects.ts` над классом `GameEffects`:

```ts GameEffects.ts
/** Искр в одном взрыве */
const SPARKS_PER_POP = 12;
/** Сколько живёт искра, секунд */
const SPARK_LIFE = 0.7;
/** Начальная скорость искры, пикселей в секунду */
const SPARK_SPEED = 260;
/** Ускорение падения искр, пикселей в секунду за секунду */
const GRAVITY = 600;
/** Масштаб новой искры: текстура circle — 117 × 117 пикселей */
const SPARK_SCALE = 0.25;
/** Цвет искр для каждого зелья */
const SPARK_COLORS: Record<string, number> = {
  'piece-dragon': 0xff7a2a,
  'piece-frog': 0x4fa3ff,
  'piece-newt': 0x8cf05a,
  'piece-snake': 0xb25cff,
  'piece-spider': 0xffd84a,
  'piece-yeti': 0xff9fdc,
};

/** Искра: частица со скоростью и возрастом. Particle — простой класс, его можно наследовать */
class Spark extends Particle {
  vx = 0;
  vy = 0;
  /** Сколько секунд искра уже живёт */
  age = 0;
}
```

Текстура — белый круг `circle` из бандла `preload`: белый удобно тонировать в любой цвет.

## Контейнер и пул искр

В классе `GameEffects` — контейнер и пул искр:

```ts GameEffects.ts
  /** Все искры в одном контейнере частиц, у всех одна текстура */
  private readonly sparks = new ParticleContainer<Spark>({
    texture: Texture.from('circle'),
    // Каждый кадр у искр меняются позиция, размер (vertex) и прозрачность (color)
    dynamicProperties: { position: true, vertex: true, color: true },
  });
  private readonly sparkPool = new Pool(
    () => new Spark({ texture: Texture.from('circle'), anchorX: 0.5, anchorY: 0.5 }),
  );
```

Параметр типа `<Spark>` говорит TypeScript, что в `particleChildren` лежат искры, а не просто частицы. Пул из прошлого шага пригодился сразу: искры рождаются и умирают десятками. В конструкторе добавьте контейнер в слой: `this.addChild(this.sparks)`.

Взрыв — это выдача искр из пула с разными направлениями и скоростями:

```ts GameEffects.ts
  /** Взрыв: искры разлетаются во все стороны, падают и гаснут. Двигает их update */
  private playSparks(position: PointData, color: number) {
    for (let i = 0; i < SPARKS_PER_POP; i++) {
      const spark = this.sparkPool.get();
      const angle = Math.random() * Math.PI * 2;
      const speed = randomRange(0.4, 1) * SPARK_SPEED;
      spark.x = position.x;
      spark.y = position.y;
      spark.vx = Math.cos(angle) * speed;
      spark.vy = Math.sin(angle) * speed;
      spark.age = 0;
      spark.alpha = 1;
      spark.scaleX = spark.scaleY = SPARK_SCALE;
      spark.tint = color;
      this.sparks.addParticle(spark);
    }
  }
```

Вызовите его из `onPop`, между кольцом и полётом: `this.playSparks(position, SPARK_COLORS[piece.textureName] ?? 0xffffff);`.

## Движение искр

Частицы двигает не GSAP, а наш код каждый кадр, — как вращение подсветки в главе 8. Это маленькая физическая модель: скорость меняет позицию, гравитация меняет скорость, а возраст решает, сколько искре осталось:

```ts GameEffects.ts
  /** Каждый кадр: двигаем искры и убираем догоревшие. Вызывает экран игры, на паузе — не вызывает */
  update(ticker: Ticker) {
    const dt = ticker.deltaMS / 1000;
    const sparks = this.sparks.particleChildren;
    // Идём с конца: удаление искры не сдвигает те, что ещё не обработаны
    for (let i = sparks.length - 1; i >= 0; i--) {
      const spark = sparks[i];
      spark.age += dt;
      if (spark.age >= SPARK_LIFE) {
        this.sparks.removeParticleAt(i);
        this.sparkPool.giveBack(spark);
        continue;
      }
      spark.vy += GRAVITY * dt;
      spark.x += spark.vx * dt;
      spark.y += spark.vy * dt;
      // К концу жизни искра гаснет и уменьшается вдвое
      const life = 1 - spark.age / SPARK_LIFE;
      spark.alpha = life;
      spark.scaleX = spark.scaleY = SPARK_SCALE * (0.5 + life / 2);
    }
  }
```

- **`dt` в секундах** из `deltaMS` — урок главы 8: движение не зависит от частоты кадров, и слайдер скорости игры из главы 10 замедляет искры вместе со всем остальным;
- **обход с конца** — `removeParticleAt(i)` сдвигает все элементы после `i`. При обходе с конца это элементы, которые мы уже обработали.

Кто вызывает `update`? Экран игры, в начале своего `update`:

```ts GameScreen.ts
    // Искры живут на тикере, а не на GSAP: exportRoot их не остановит, поэтому на паузе их просто не двигаем
    if (!this.paused) this.vfx.update(ticker);
```

Это тот случай из главы 11: всё, что движется не через GSAP, пауза должна останавливать сама.

## Что получилось

Каждое зелье взрывается фонтанчиком искр своего цвета: огненное — оранжевыми, лягушачье — голубыми. Искры разлетаются, падают и гаснут за 0,7 секунды. Проверка: через 0,3 с после хода тройки в контейнере 36 частиц, после каскада — ноль. Если нажать паузу посреди взрыва, искры замирают: за 0,6 секунды на паузе не сдвинулась ни одна. За шесть ходов пул создал от 72 до 108 искр (в разных прогонах — смотря сколько было комбо), а выдал их сотни раз.

## Эксперименты

- Уберите `color: true` из `dynamicProperties`. Искры перестанут гаснуть и исчезнут разом в конце жизни: `alpha` у частиц меняется, но на видеокарту не выгружается.
- Попробуйте `this.sparks.addChild(...)` с любым спрайтом. Получите ошибку «ParticleContainer.addChild() is not available. Please use ParticleContainer.addParticle()».
- Поставьте `SPARKS_PER_POP = 100`. Триста искр на тройку — а вызов отрисовки по-прежнему один.

## Связь с оригиналом

Взрыв в оригинале — класс `PopExplosion`: 12 обычных спрайтов `circle`, каждый анимирован двумя твинами GSAP (позиция с прозрачностью и масштаб). Для 12 объектов это нормально. Наш вариант показывает инструмент, который понадобится, когда частиц станет сотни: дым, снег, звёздный фон.

::: deep Под капотом: как рисуется контейнер частиц
Обычный спрайт попадает в **батч** (подробно — в главе 16): рендерер каждый кадр собирает вершины всех спрайтов подряд в общий буфер. Для этого у каждого спрайта вычисляется мировая матрица, по ней — четыре угла, и всё это копируется. Работа на каждый спрайт.

Контейнер частиц устроен иначе. У него свои два буфера: **статический** и **динамический**. При отрисовке PixiJS проходит по частицам сгенерированной функцией, которая пишет в буфер только нужные числа: для `position` — `x` и `y` четыре раза (по разу на угол), для `color` — одно 32-битное число, в котором упакованы и тонирование, и прозрачность. Динамический буфер обновляется каждый кадр, статический — только когда список частиц изменился. Мировая матрица одна на весь контейнер, а поворот и смещение каждой частицы применяет вершинный шейдер на видеокарте. Поэтому десять тысяч частиц — это один буфер и один вызов отрисовки.

Отсюда и тонкость с экспериментом про `color`: статические свойства всё-таки выгружаются, когда список частиц меняется. Если во время жизни искр одной тройки рождается или умирает другая тройка, прозрачность в этот кадр обновится. Полагаться на это нельзя: что меняется каждый кадр, должно быть динамическим.
:::
