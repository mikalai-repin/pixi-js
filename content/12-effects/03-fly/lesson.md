Очки сейчас появляются на счётчике сами собой: число набегает, но между тройкой на поле и цифрой наверху нет никакой связи. В оригинальной Puzzling Potions каждое собранное зелье **прыгает в котёл** над полем, и игрок буквально видит, как его ход превращается в результат. Котла у нашей версии нет (в оригинале это скелетная Spine-анимация, до неё дойдём в главе 14), но есть счёт. Пусть зелья летят прямо в него.

## Копия, а не сама фишка

Фишку из поля отправить в полёт нельзя: она принадлежит полю, её гасит `animatePop`, а после анимации поле её уничтожает. Да и выглядела бы она странно: маска поля обрезала бы её на выходе за край.

Поэтому летит **копия**: обычный спрайт с той же текстурой в слое эффектов. Фишка исчезает на поле как раньше, а в этот же момент на её месте появляется копия и улетает. Глаз не отличит одно от другого. Так и делает оригинал. Для этого перед главой мы сохранили в фишке имя текстуры — `piece.textureName`.

## Куда лететь

Цель — надпись счёта в интерфейсе. Она лежит в `Hud`, у которого свои координаты, а копия — в слое эффектов. Задача та же, что в первом шаге: перейти через глобальные координаты. Пусть интерфейс сам скажет, где на экране его счёт:

```ts Hud.ts
  /** Где на экране счёт, в глобальных координатах: туда летят зелья */
  getScorePosition() {
    return this.scoreText.getGlobalPosition();
  }
```

А слой эффектов переведёт эту точку в свои координаты: `this.toLocal(this.game.hud.getScorePosition())`. Слой масштабирован как поле, но `toLocal` это учитывает.

## Кривая полёта

Если анимировать `x` и `y` одним твином с одной функцией плавности, копия полетит по прямой. По прямой летят пули, а не зелья. Секрет дуги — **разные функции плавности по разным осям**:

- по `y` — `sine.out`: копия сразу резко взмывает вверх, а к концу замедляется;
- по `x` — `sine.in`: по горизонтали копия поначалу почти не движется и разгоняется к концу.

В начале пути копия идёт почти вертикально, в конце — почти горизонтально. Получается дуга.

Третий твин — масштаб. Хочется, чтобы копия сначала чуть подросла («прыжок»), а потом уменьшилась, ныряя в цифры. Это делает одна стандартная функция `back.in`. Вспомните `back.out` из главы 8: значение проскакивает цель и возвращается. `back.in` — её зеркало: в начале значение уходит **в обратную сторону**. Для масштаба, который должен уменьшиться, обратная сторона — увеличение. Число в скобках, `back.in(3)`, — сила этого **замаха** (anticipation): чем больше, тем дальше уходит значение.

Добавьте метод в `GameEffects`:

```ts GameEffects.ts
  /**
   * Копия зелья летит в счёт: подпрыгивает, подрастает и ныряет в цифры.
   * Сама фишка тем временем исчезает с поля, как раньше. В оригинале зелья летят в котёл
   */
  private async playFlyToScore(textureName: string, from: PointData) {
    const copy = new Sprite(Texture.from(textureName));
    copy.anchor.set(0.5);
    copy.setSize(TILE_SIZE);
    copy.position.copyFrom(from);
    this.addChild(copy);

    // Счёт лежит в интерфейсе: его глобальную позицию переводим в координаты слоя эффектов
    const to = this.toLocal(this.game.hud.getScorePosition());
    // Дальние зелья летят дольше, а случайная добавка не даёт им лететь строем
    const distance = Math.hypot(to.x - from.x, to.y - from.y);
    const duration = distance * FLY_TIME_PER_PIXEL + randomRange(0.2, 0.4);
    // По y копия сразу взмывает вверх, а по x разгоняется не спеша: у осей разная плавность, и путь выгибается дугой
    gsap.to(copy, { x: to.x + randomRange(-20, 20), duration, ease: 'sine.in' });
    gsap.to(copy, { y: to.y, duration, ease: 'sine.out' });
    // back.in сначала уводит значение в обратную сторону: копия подрастает и только потом уменьшается
    const scale = copy.scale.x * 0.4;
    await gsap.to(copy.scale, { x: scale, y: scale, duration, ease: 'back.in(3)' });
    copy.destroy();
  }
```

И константу рядом с остальными:

```ts GameEffects.ts
/** Сколько секунд полёта добавляет каждый пиксель пути */
const FLY_TIME_PER_PIXEL = 0.0015;
```

Несколько деталей:

- **`copy.setSize(TILE_SIZE)`** — копия размером с клетку. Слой в масштабе поля, поэтому на экране она совпадёт с фишкой;
- **длительность зависит от расстояния**, иначе зелья с нижнего ряда неслись бы в шесть раз быстрее верхних (пути различаются вшестеро, см. ниже). Случайная добавка и случайный сдвиг цели по `x` разводят копии одной тройки: они летят не строем, а стайкой;
- **три твина одной длительности** закончатся одновременно, поэтому ждём только последний — как в главе 11.

Не забудьте импорты: `Sprite` и `Texture` из `pixi.js`, `TILE_SIZE` из `./Board`. И запустите полёт из `onPop`:

```ts GameEffects.ts {4}
  onPop(piece: Piece) {
    const position = this.toLocal(piece.getGlobalPosition());
    this.playRing(position);
    this.playFlyToScore(piece.textureName, position);
  }
```

## Что получилось

Каждое собранное зелье подпрыгивает, чуть вырастает и дугой улетает в надпись «Очки», уменьшаясь на подлёте. Мы сняли полёт по кадрам прямо из тикера и измерили пути: от верхнего ряда до счёта около 80 пикселей слоя эффектов (полёт 0,3–0,5 с), от нижнего — около 480 (0,9–1,1 с). Слой эффектов лежит поверх интерфейса, поэтому копии пролетают над счётом, а не под ним.

## Эксперименты

- Поставьте обеим осям одну и ту же функцию, например `sine.in`. Копия полетит по прямой: когда `x` и `y` проходят одинаковую долю пути в каждый момент, точка всегда лежит на отрезке между началом и концом.
- Замените `back.in(3)` на `quad.in`. Пропадёт «прыжок»: копия будет только уменьшаться. А `back.in(6)` раздует её почти в полтора раза (расчёт — во врезке).
- Перенесите `this.addChild(this.vfx)` в `GameScreen` выше строки `this.addChild(this.hud)`. Копии будут пролетать под надписью счёта: порядок детей — это порядок отрисовки (глава 3). Верните строку на место.

## Связь с оригиналом

`GameEffects.playFlyToCauldron` в оригинале устроен так же: три твина `x`, `y` и `scale` одной длительности, длительность растёт с расстоянием, цель слегка смещена случайно. Только кривые там свои: они заданы строками SVG-пути и подключены плагином GSAP `CustomEase`. В сборку GSAP нашего превью этот плагин не входит, но стандартных кривых хватает.

::: deep Под капотом: функция плавности как отображение времени
Функция плавности получает долю прошедшего времени `t` от 0 до 1 и возвращает долю пути. У `sine.in` это `1 − cos(t·π/2)`, у `sine.out` — `sin(t·π/2)`. Если по `x` взять одну функцию, а по `y` другую, точка в момент `t` окажется в `(fx(t), fy(t))` — это параметрическое задание кривой. С `sine.in` и `sine.out` получается четверть эллипса.

`back.in` устроена как `t²·((s + 1)·t − s)`, где `s` — сила замаха (по умолчанию 1,70158). При малых `t` выражение в скобках отрицательно, и значение уходит ниже нуля: это и есть движение «назад» перед основным. Чем больше `s`, тем глубже провал. При `s = 3` получаем `t²·(4t − 3)`: минимум −0,25 при `t = 0,5`. Масштаб копии должен пройти путь от 1 до 0,4, то есть на 0,6; в середине полёта он уходит на четверть этого пути в обратную сторону: 1 + 0,6 × 0,25 = 1,15. При `s = 6` минимум −0,65 (при `t ≈ 0,57`), и копия вырастает до 1 + 0,6 × 0,65 ≈ 1,39.
:::
