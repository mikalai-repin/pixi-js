Встроенных фильтров в PixiJS немного: размытие, цветовая матрица, прозрачность (`AlphaFilter`), шум (`NoiseFilter`) и смещение (`DisplacementFilter`). Всё остальное — свечение, обводки, тени, искажения — живёт в официальной коллекции **pixi-filters** от команды PixiJS. В ней 37 фильтров. Подключим её и возьмём два: **свечение** (glow) для выбранной фишки и **ударную волну** (shockwave) для длинного комбо.

## Подключение

pixi-filters — отдельный npm-пакет. Версия должна подходить к PixiJS: пакет 6.x требует `pixi.js` 8-й версии, а 5.x был набором пакетов `@pixi/filter-*` для v7. В старых статьях вы встретите именно их. В собственном проекте вы бы установили его командой `npm install pixi-filters`. В превью курса он уже подключён — так же, как GSAP и `@pixi/ui`, — и импортируется по имени:

```ts
import { GlowFilter, ShockwaveFilter } from 'pixi-filters';
```

## Свечение выбранной фишки

`GlowFilter` рисует вокруг непрозрачных пикселей объекта ореол заданного цвета. Пусть выбранная фишка светится золотым, в цвет рамки поля. В `Board`:

```ts Board.ts
import { GlowFilter } from 'pixi-filters';
```

```ts Board.ts
  /** Свечение выбранной фишки. Фильтр один: выбранная фишка всегда одна */
  private readonly glow = new GlowFilter({ distance: 12, outerStrength: 2, color: 0xffd27f });
```

В `select` снимите фильтр со старой фишки и поставьте новой:

```ts Board.ts {5,10}
    if (this.selected) {
      this.selected.setHighlight(false);
      gsap.killTweensOf(this.selected.scale);
      this.selected.scale.set(1);
      this.selected.filters = [];
    }
    ...
    if (!piece) return;
    piece.setHighlight(true);
    piece.filters = [this.glow];
```

Опции `GlowFilter`:

- **`distance`** — ширина ореола в пикселях, по умолчанию 10;
- **`outerStrength`** и **`innerStrength`** — яркость свечения снаружи и внутри контура, по умолчанию 4 и 0;
- **`color`** и **`alpha`** — цвет и прозрачность свечения;
- **`quality`** — сколько направлений проверять вокруг каждого пикселя, по умолчанию 0,1;
- **`knockout`** — рисовать только ореол, без самого объекта.

Один экземпляр фильтра можно ставить разным объектам: это просто программа и её параметры. Мы переносим его с фишки на фишку. Удалять фильтр, когда фишку уничтожают, не нужно: `destroy` контейнера только забывает свои фильтры, но не уничтожает их — поэтому общий фильтр в безопасности.

## Ударная волна

`ShockwaveFilter` искажает картинку кольцом, которое расходится из центра, — как волна от брошенного камня. Его параметры:

| Опция | Что задаёт | По умолчанию |
|---|---|---|
| `center` | центр волны, в пикселях | (0, 0) |
| `time` | время с начала волны, в секундах | 0 |
| `speed` | скорость, пикселей в секунду | 500 |
| `amplitude` | сила искажения | 30 |
| `wavelength` | ширина кольца, пикселей | 160 |
| `brightness` | яркость гребня волны | 1 |
| `radius` | где волна гаснет; −1 — нигде | −1 |

Сам фильтр не двигается: радиус кольца — это `speed × time`, и `time` нужно увеличивать каждый кадр. Это работа для твина.

Куда ставить фильтр? Волна должна идти по всему экрану игры — по полю, интерфейсу, искрам. Значит, на сам экран игры, рядом с размытием паузы. Отсюда и помощник `addFilter` из шага 6: у экрана может быть сразу два фильтра.

Теперь центр. В каких он координатах? Не в локальных координатах объекта, а **от левого верхнего угла области фильтра**. Мы проверили: контейнер с шахматкой от −150 до 150 вокруг своего начала и волна с `center: { x: 0, y: 0 }` — волна пошла из левого верхнего угла шахматки, а не из её центра. У экрана игры область фильтра мы задали сами — `filterArea` от (0, 0) во весь экран, — и сам экран не сдвинут и не масштабирован. Значит, центр волны — это просто глобальные координаты.

В `GameEffects`:

```ts GameEffects.ts
import { ShockwaveFilter } from 'pixi-filters';
```

```ts GameEffects.ts
/** С какого раунда комбо по экрану идёт ударная волна */
const SHOCKWAVE_ROUND = 3;
```

```ts GameEffects.ts
  /** Ударная волна по всему экрану игры из точки position (в координатах слоя эффектов) */
  async playShockwave(position: PointData) {
    // Центр волны отсчитывается от левого верхнего угла области фильтра. У экрана игры
    // filterArea начинается в (0, 0), а сам экран не сдвинут и не масштабирован: это глобальные координаты
    const center = this.toGlobal(position);
    const wave = new ShockwaveFilter({ center, amplitude: 20, wavelength: 100, speed: 500, radius: 350 });
    addFilter(this.game, wave);
    // time — секунды с начала волны: радиус волны — это speed × time
    await gsap.fromTo(wave, { time: 0 }, { time: 0.7, duration: 0.7, ease: 'none' });
    removeFilter(this.game, wave);
    // Свой фильтр уничтожаем сами: destroy контейнера фильтры не трогает
    wave.destroy();
  }
```

`radius: 350` — волна гаснет, пройдя 350 пикселей, а за 0,7 секунды при скорости 500 она дошла бы до 350 как раз к концу твина. `ease: 'none'` — время течёт равномерно.

И запуск — на длинном комбо, из центра поля:

```ts GameEffects.ts {4-5}
  onMatch(round: number) {
    if (round < 2) return;
    earthquake(this.game.board.pivot, Math.min(round * SHAKE_PER_ROUND, MAX_SHAKE));
    // На длинном комбо от центра поля расходится волна
    if (round >= SHOCKWAVE_ROUND) this.playShockwave(this.toLocal(this.game.board.getGlobalPosition()));
  }
```

## Что получилось

Выбранная фишка окружена мягким золотым ореолом поверх вращающейся подсветки. А на комбо ×3 поле не только трясётся: из его центра по всему экрану расходится кольцо искажения, фишки и надписи на миг изгибаются. Комбо ×3 случается не каждую партию, поэтому мы проверили волну напрямую: вызвали `playShockwave` и сняли три кадра — кольцо идёт ровно из центра поля, а через 1,2 секунды фильтров у экрана снова ноль.

## Эксперименты

- Чтобы не ждать комбо, временно поставьте `SHOCKWAVE_ROUND = 1`: волна пойдёт на каждом ходе.
- Передайте в фильтр `center: { x: 0, y: 0 }`: волна пойдёт из левого верхнего угла экрана.
- Поставьте `amplitude: 60` и `wavelength: 300` — получится уже не волна, а взрыв.
- Попробуйте в `select` изменить уже созданный фильтр: `this.glow.distance = 30`. Ореол не станет шире. В WebGL `distance` и `quality` вшиваются в текст шейдера при создании фильтра (во врезке — почему), и менять их нужно новым фильтром.

## Связь с оригиналом

В Puzzling Potions pixi-filters не используется: фильтры там — только встроенное размытие под попапами. Свечение спецфишек сделано подсветкой, а взрыв — частицами. Мы добавили эти эффекты, чтобы познакомиться с коллекцией: в реальных проектах её фильтры встречаются постоянно.

::: deep Под капотом: почему distance вшит в шейдер
Свечение для каждого пикселя вокруг объекта смотрит, есть ли рядом непрозрачные пиксели: шагает по нескольким направлениям на `distance` пикселей и суммирует прозрачность. Это два вложенных цикла. Авторы фильтра хотели, чтобы границы циклов были **константами**, известными при компиляции шейдера: в языке шейдеров WebGL 1 (GLSL ES 1.0) это обязательное правило, и компилятор может развернуть такой цикл заранее. Поэтому `GlowFilter` подставляет `distance` и шаг угла прямо в текст GLSL-программы перед компиляцией — об этом прямо сказано в комментарии в его исходнике. Изменение свойства потом обновит только отступ фильтра, а циклы останутся прежними.

Отсюда и цена свечения. Шаг угла равен `1 / quality / distance` радиан: при `distance: 12` и `quality: 0,1` — 0,83 радиана, то есть 8 направлений. 8 направлений × 12 шагов = 96 чтений текстуры на каждый пиксель области фильтра. Для одной фишки 50 × 50 с отступом это мелочь. Для свечения целого экрана — уже серьёзная нагрузка.

Ударная волна дешевле: каждый пиксель проверяет, попадает ли он в кольцо, и читает текстуру один-два раза — со сдвигом от центра или без него. Зато она работает по всей области фильтра — у нас это экран целиком.
:::
