Комбо — лучший момент в match-3: одна тройка тянет за собой другую, и очки умножаются. Сейчас о нём сообщает только надпись «Комбо ×2». **Тряска экрана** (screen shake) — самый дешёвый способ сказать игроку «произошло что-то мощное»: несколько десятых секунды поле дрожит, и удар чувствуется почти физически. Сделаем, как в оригинале: на комбо поле трясёт, и тем сильнее, чем длиннее цепочка.

## Как трясти

Тряска — это смещение на случайное расстояние, новое каждый кадр, с затуханием: сначала сильно, потом слабее, в конце — ровно на месте. Удобно описать её одним числом — **силой** (power): каждый кадр объект сдвигается на случайную величину от −power до +power, а сама сила плавно падает до нуля.

Плавное уменьшение числа до нуля за полсекунды — это твин. GSAP умеет анимировать свойства любого объекта, не только спрайта: заведём объект `{ power }` и анимируем его. А сдвигать будем в колбэке **`onUpdate`**, который GSAP вызывает после каждого обновления твина, то есть каждый кадр:

```ts GameEffects.ts
/**
 * Тряска: каждый кадр сдвигает точку на случайное расстояние, а сила тряски плавно падает до нуля.
 * Обычно трясут pivot: позицию объекта задаёт раскладка, а pivot свободен. Как earthquake в Puzzling Potions
 */
export async function earthquake(target: PointData, power = 8, duration = 0.5) {
  const shake = { power };
  await gsap.to(shake, {
    power: 0,
    duration,
    ease: 'linear',
    onUpdate: () => {
      target.x = randomRange(-shake.power, shake.power);
      target.y = randomRange(-shake.power, shake.power);
    },
  });
}

/** Случайное число от min до max */
export function randomRange(min: number, max: number) {
  return min + Math.random() * (max - min);
}
```

На последнем кадре сила равна нулю, и точка встаёт ровно в (0, 0). Функция принимает не объект сцены, а любую точку `{ x, y }`: трясти можно позицию, `pivot`, масштаб — что угодно с полями `x` и `y`.

## Почему pivot, а не position

Что именно трясти? Первое, что приходит в голову, — `board.position`. Но позицию поля задаёт раскладка: `resize` ставит поле в центр свободного места. Тряска, которая каждый кадр пишет в `position` числа около нуля, затрёт её, а в конце оставит поле в точке (0, 0).

Свободна **точка поворота** (`pivot`) из главы 2. Напомним, что она делает: `pivot` — точка в локальных координатах объекта, которая ставится в его `position`. У поля `pivot` равен (0, 0): центр поля стоит в позиции, которую задала раскладка. Если сдвинуть `pivot` на (5, 0), в позицию встанет точка на 5 пикселей правее центра, и всё поле съедет **влево**. Для тряски направление неважно, а раскладку `pivot` не трогает. И в конце тряски он вернётся ровно в ноль.

## Тряска на комбо

Эффектам нужно знать, что трясти, — значит, нужен доступ к экрану игры. Пусть `GameEffects` получает его в конструкторе:

```ts GameEffects.ts
import type { GameScreen } from './GameScreen';

/** Сила тряски за каждый раунд комбо и её предел, в пикселях */
const SHAKE_PER_ROUND = 4;
const MAX_SHAKE = 16;
```

```ts GameEffects.ts
  constructor(private readonly game: GameScreen) {
    super();
    this.label = 'effects';
  }

  /** Найдены совпадения. На комбо поле трясёт: чем длиннее цепочка, тем сильнее */
  onMatch(round: number) {
    if (round < 2) return;
    earthquake(this.game.board.pivot, Math.min(round * SHAKE_PER_ROUND, MAX_SHAKE));
  }
```

Комбо ×2 трясёт поле на 8 пикселей, ×3 — на 12, дальше не больше 16: слишком сильная тряска раздражает.

`GameScreen.ts` импортирует `GameEffects.ts`, а теперь и `GameEffects.ts` импортирует `GameScreen.ts`. В главе 11 мы выяснили, что превью не поддерживает циклические импорты. Но здесь импортируется **только тип**: `GameScreen` нужен лишь в аннотации параметра. Такие импорты TypeScript при компиляции в JavaScript удаляет, и в браузер цикл не попадает. `import type` делает это явным: импорт с этим словом исчезает всегда, а если по ошибке использовать `GameScreen` как значение (например, `new GameScreen()`), TypeScript сразу сообщит об ошибке.

В `GameScreen` передайте слою экран и сообщайте о совпадениях:

```ts GameScreen.ts
    this.vfx = new GameEffects(this);
```

```ts GameScreen.ts {3}
      if (round > 1) this.showCombo(round);
      this.hud.setScore(this.score);
      this.vfx.onMatch(round);
```

## Что получилось

Обычный ход выглядит как раньше. Но стоит случиться комбо, и поле на полсекунды вздрагивает, затихая. Комбо легко пропустить, поэтому мы проверили эффект напрямую: вызвали `onMatch(3)` и каждый кадр записывали `pivot` поля. Наибольший сдвиг в разных запусках — от 4,8 до 10,5 пикселя (сила 12, но случайные смещения редко попадают в самый край, а сила с первого кадра уже падает), в конце — ровно (0, 0).

Пауза из главы 11 замораживает и тряску: это твин GSAP, а `gsap.exportRoot()` собирает все текущие твины.

## Эксперименты

- Поставьте силу 40. Так трясёт на взрыве в боевике, а не на комбо в головоломке. Хорошая тряска короткая и чуть слабее, чем хочется.
- Трясите позицию вместо `pivot`: `earthquake(this.game.board.position, ...)`, а строку `if (round < 2) return;` временно уберите, чтобы тряска была на каждом ходе. Поле улетит в левый верхний угол и останется там: тряска закончилась в точке (0, 0). Вернётся оно, только когда сработает `resize` — например, если изменить размер окна.

## Связь с оригиналом

`earthquake` — почти дословно функция из `utils/animation.ts` оригинала. `GameEffects.onMatch` там тоже трясёт на комбо: `earthquake(this.game.pivot, Math.min(1 + data.combo * 0.5, 20))`. Только трясётся весь экран игры, а не поле, и слабее: у оригинала есть ещё и звук, а он сильно усиливает ощущение удара.

::: deep Под капотом: почему тряска не дёргает фишки внутри поля
Тряска меняет `pivot` поля 60 раз в секунду, но фишки внутри поля не знают об этом: их `position` не меняется. Меняется только локальная трансформация самого поля. Перед отрисовкой PixiJS пересчитывает мировые матрицы, и смещение поля автоматически переходит на всех детей — это то самое «почти бесплатно» из врезки про трансформации в главе 3. Поэтому тряска не мешает ни падению фишек, ни расчёту позиций эффектов: `getGlobalPosition()` учитывает текущий `pivot`, и кольца появляются там, где фишку видно в этот момент.
:::
