Игра готова: меню, поле, очки, таймер, результат. Сыграйте пару ходов и присмотритесь, что происходит, когда собирается тройка. Фишки за десятую долю секунды становятся прозрачными, сверху падают новые. Правила работают, но игра ощущается вялой: экран почти никак не отвечает на удачный ход.

В этой главе займёмся **«сочностью» (juice)**. Так разработчики игр называют всё, что делает отклик игры на действия игрока богаче: тряску, вспышки, разлетающиеся искры, предметы, которые летят туда, где их считают. Сочность не меняет правил. Без неё игра так же проходится, но выигрывать в ней гораздо приятнее. Широко известен доклад «Juice it or lose it» Мартина Йонассона и Петри Пурхо: авторы берут скучный клон Breakout и, не меняя правил, добавляют эффект за эффектом, пока игра не становится совсем другой.

К концу главы ваша Puzzling Potions будет трясти поле на комбо, взрывать фишки искрами и отправлять копии зелий в счёт, размывать экран под паузой, пускать ударную волну и в практикуме обзаведётся спецфишками — полосой и бомбой.

## Что изменилось в коде

Перед главой в коде три небольшие правки:

| Файл | Что изменилось |
|---|---|
| `Piece.ts` | Конструктор сохраняет имя текстуры в поле `textureName`: эффектам понадобится нарисовать копию фишки |
| `Board.ts` | Константа `TILE_SIZE` экспортирована, как раньше `BOARD_WIDTH` |
| `GameScreen.ts` | Поля `board` и `hud` больше не `private`: к ним будут обращаться эффекты |

И появился файл `GameEffects.ts` с пустым классом. Это задание шага.

## Слой эффектов

Где писать код эффектов? Можно прямо в `Board`: там, где фишки исчезают. Но тогда в коде правил появятся кольца, искры и тряска, и поле станет вдвое длиннее. Оригинальная Puzzling Potions поступает иначе: все эффекты живут в отдельном классе `GameEffects`. В его комментарии так и написано: эффекты изолированы, чтобы их можно было свободно менять, не затрагивая игровой процесс.

Значит, нужно две вещи:

1. **поле сообщает** о событиях: «фишка исчезла», «найдены совпадения». Что с этим делать, оно не знает. Мы уже так делали в главе 9: поле вызывает колбэк `onMatch`, а очки считает экран игры;
2. **слой эффектов** — контейнер поверх всего экрана игры — получает эти сообщения и рисует эффекты.

Начнём с поля. Добавьте в `Board` второй колбэк рядом с `onMatch`:

```ts Board.ts
  /** Вызывается для каждой фишки, которая исчезает с поля. Нужен эффектам, правилам игры он не важен */
  onPop?: (piece: Piece) => void;
```

И вызовите его в `popMatches` для каждой убранной фишки:

```ts Board.ts {5}
        if (piece === this.selected) this.select(null);
        setType(this.grid, position, 0);
        this.setPiece(position, null);
        popped.push(piece);
        this.onPop?.(piece);
```

Колбэк вызывается сразу, пока фишка ещё на месте и только начинает гаснуть: эффект появится одновременно с исчезновением.

## Первый эффект: кольцо

Теперь сам слой. Первый эффект совсем простой: на месте исчезнувшей фишки расходится и тает белое кольцо.

```ts GameEffects.ts
import gsap from 'gsap';
import { Container, Graphics, type PointData } from 'pixi.js';
import type { Piece } from './Piece';

/** Радиус кольца, которое расходится на месте исчезнувшей фишки */
const RING_RADIUS = 30;

/**
 * Слой эффектов поверх экрана игры. Эффекты не влияют на правила:
 * их можно менять и отключать, не трогая поле. Как GameEffects в Puzzling Potions
 */
export class GameEffects extends Container {
  constructor() {
    super();
    this.label = 'effects';
  }

  /** Фишка исчезла с поля */
  onPop(piece: Piece) {
    // Фишка лежит внутри поля, а слой эффектов — нет: переводим её позицию в свои координаты
    const position = this.toLocal(piece.getGlobalPosition());
    this.playRing(position);
  }

  /** Кольцо расходится и тает */
  private async playRing(position: PointData) {
    const ring = new Graphics().circle(0, 0, RING_RADIUS).stroke({ width: 4, color: 0xffffff });
    ring.position.copyFrom(position);
    ring.scale.set(0.3);
    this.addChild(ring);
    gsap.to(ring, { alpha: 0, duration: 0.4, ease: 'quad.in' });
    await gsap.to(ring.scale, { x: 1, y: 1, duration: 0.4, ease: 'quad.out' });
    ring.destroy();
  }
}
```

Главная строка здесь — перевод координат. `piece.position` — это позиция фишки **внутри поля**: центр поля в точке (0, 0), фишка слева вверху имеет координаты около (−150, −200). А слой эффектов лежит не в поле, а в экране игры, и у него своя система координат. Поэтому идём через глобальные координаты, как в главе 3:

- **`piece.getGlobalPosition()`** — где фишка на экране, с учётом всех родителей: позиции и масштаба поля, тряски (она появится в следующем шаге);
- **`this.toLocal(...)`** — где эта точка в координатах слоя эффектов.

Остальное знакомо: `Graphics` из главы 4, два твина GSAP из главы 8 — прозрачность и масштаб — и `destroy`, когда анимация закончилась. `import type` для `Piece` — эффектам нужен только тип фишки, а не сам класс.

## Слой в экране игры

Создайте слой в конструкторе `GameScreen`, сразу после подсказки:

```ts GameScreen.ts
    // Эффекты — последним слоем, поверх поля и интерфейса
    this.vfx = new GameEffects();
    this.addChild(this.vfx);
    this.board.onPop = (piece) => this.vfx.onPop(piece);
```

И объявите поле класса:

```ts GameScreen.ts
  /** Слой эффектов (vfx — visual effects), поверх поля и интерфейса */
  private readonly vfx: GameEffects;
```

Почему `vfx`, а не `effects`? Попробуйте назвать поле `effects`, и TypeScript ответит: «Property 'effects' in type 'GameScreen' is not assignable to the same property in base type 'Container<ContainerChild>'». У `Container` уже есть внутреннее поле `effects`: в нём рендерер хранит маски и фильтры объекта. Перезаписать его — значит сломать отрисовку экрана. Оригинал называет поле так же — `vfx`.

Осталась одна деталь. Поле масштабируется под экран (глава 10), а слой эффектов — нет. Кольцо радиусом 30 пикселей на крупном поле выглядело бы меньше фишки. Пусть слой эффектов всегда будет в масштабе поля. В конец `resize`:

```ts GameScreen.ts
    // Слой эффектов — в масштабе поля: эффекты получаются того же размера, что и фишки
    this.vfx.scale.copyFrom(this.board.scale);
```

Позиции при этом остаются верными: `toLocal` учитывает и масштаб слоя.

## Что получилось

Каждая собранная тройка вспыхивает тремя белыми кольцами, которые расходятся из центров фишек. Эффект скромный, но игра уже отвечает на ход заметнее. Проверка подтвердила: через 0,3 с после хода в слое эффектов столько колец, сколько фишек исчезло, а после каскада слой снова пуст — кольца уничтожаются.

## Эксперименты

- Замените `this.toLocal(piece.getGlobalPosition())` на `piece.position`. Кольца появятся у левого края экрана, и половина из них — за краем: координаты внутри поля отрицательные, а у слоя эффектов (0, 0) — левый верхний угол экрана. Верните строку.
- Сравните «до» и «после»: закомментируйте строку `this.board.onPop = ...`. Правила не изменятся ни на йоту, а ход станет заметно скучнее. Этот приём пригодится вам и дальше: все эффекты главы подключены к полю в одном месте.

## Связь с оригиналом

В Puzzling Potions слой `GameEffects` создаёт `GameScreen` и подписывает на события `Match3`: `onMove` (звук хода), `onMatch` (звук и тряска), `onPop` (взрыв и полёт фишки в котёл). Наши шаги идут по тому же списку.

::: deep Под капотом: можно ли верить getGlobalPosition посреди кадра
В главе 3 мы обожглись: `worldTransform` до первой отрисовки хранит устаревшее значение. Поле может трястись, фишки — двигаться, и мировые матрицы пересчитываются только перед отрисовкой. Не получим ли мы старую позицию?

Нет. `getGlobalPosition()` вызывает `parent.toGlobal(position)`, а `toGlobal` строит глобальную матрицу заново: проходит от объекта вверх по цепочке родителей и перемножает их локальные трансформации. Это чуть дороже чтения готового `worldTransform`, зато точно в любой момент. Для десятка фишек за ход разница незаметна.
:::
