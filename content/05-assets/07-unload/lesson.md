Загружать мы научились. Но память не бесконечна, особенно видеопамять на телефонах. Игра с десятью уровнями, у каждого из которых своя графика на 50 МБ, не может держать всё в памяти одновременно. Ресурсы, которые больше не нужны, нужно **выгружать**.

## `Assets.unload`

Выгрузка — операция, обратная загрузке:

```ts
await Assets.unload('result-atlas');        // по псевдониму
await Assets.unloadBundle('result');         // весь бандл
```

Выгрузка делает три вещи:

1. удаляет ресурс из кэша `Assets`;
2. **уничтожает** его: у текстур освобождается память видеокарты;
3. для атласа — уничтожает и все текстуры его кадров.

Проверим на бандле `result`: загрузим его, посмотрим в кэш, выгрузим и посмотрим снова. Псевдоним атласа `result-atlas`, а кадр внутри называется `result-base`:

```ts main.ts
// Экран результатов показали и закрыли — его ресурсы больше не нужны
await Assets.loadBundle('result');
console.log('result-base в кэше:', Assets.cache.has('result-base'));
await Assets.unload('result-atlas');
console.log('result-base после выгрузки:', Assets.cache.has('result-base'));
```

`Assets.cache.has` проверяет, есть ли ресурс в кэше, не выводя предупреждения, если его нет.

::: task
Загрузите бандл `result`, выведите, есть ли кадр `result-base` в кэше, выгрузите атлас и проверьте снова.
:::

## Что получилось

```
result-base в кэше: true
result-base после выгрузки: false
```

Атлас выгружен вместе со всеми своими кадрами.

::: warning
Мы выгрузили атлас по псевдониму `Assets.unload('result-atlas')`. Есть и `Assets.unloadBundle('result')`, который выгрузит весь бандл. В версии 8.22 он выводит для атласов предупреждение `Asset id … was not found in the Cache`: это особенность того, как бандл хранит ссылки на атласы, и на результат она не влияет. Не пугайтесь, если встретите его.
:::

## Выгруженное нельзя использовать

Выгрузка **уничтожает** ресурс. Если какой-то спрайт на сцене всё ещё использует текстуру из выгруженного атласа, рендерер попытается нарисовать уничтоженную текстуру и упадёт с ошибкой. Поэтому порядок всегда такой:

1. уничтожить или убрать со сцены всё, что использует ресурсы;
2. выгрузить ресурсы.

Проверьте, как выглядит нарушение порядка: перед выгрузкой создайте спрайт `new Sprite(Texture.from('result-base'))` и добавьте его на сцену. После выгрузки в консоли появится ошибка вроде `Cannot read properties of null (reading 'addressModeU')`, а приложение перестанет обновляться. Запомните эту ошибку: если вы встретите её в своём проекте, первым делом ищите текстуру, которую выгрузили или уничтожили раньше, чем спрайт, который её использует.

Уберите проверочный спрайт.

## `destroy` и его параметры

Объекты сцены уничтожаются методом `destroy`, который мы уже использовали для полоски загрузки. У него есть параметры:

```ts
container.destroy();                     // только сам объект
container.destroy({ children: true });   // и всех детей рекурсивно
sprite.destroy({ texture: true });       // и его текстуру тоже
sprite.destroy({ texture: true, textureSource: true }); // и источник текстуры
```

По умолчанию `destroy` **не трогает текстуры**: одна текстура может использоваться многими спрайтами, и уничтожать её вместе с одним из них опасно. Текстурами из `Assets` управляйте через `Assets.unload`, а не через `destroy`.

::: deep Под капотом: сборщик мусора текстур
У PixiJS есть свой сборщик мусора для видеопамяти — `TextureGCSystem`. Он периодически проверяет, какие текстуры давно не рисовались, и выгружает их данные **с видеокарты**. Сама текстура при этом остаётся в памяти JavaScript, и если она снова понадобится, PixiJS загрузит её на видеокарту заново.

Это страховка, а не замена `Assets.unload`: сборщик освобождает только видеопамять, а не саму картинку в памяти браузера, и делает это с задержкой. Если вы точно знаете, что ресурс больше не нужен, выгружайте его явно.
:::
