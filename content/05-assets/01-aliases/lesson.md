Сейчас код знает, **где лежат файлы**: `pieceUrl('dragon')` строит путь `/assets/game/piece-dragon.png`, а `Piece` получает уже готовую текстуру. Пока картинок семь, это терпимо. Но в оригинальной игре ресурсов десятки, они упакованы в атласы, у каждого несколько версий под разные экраны, и пути к ним содержат хеши вроде `game-atlas-jmixPg.webp`. Если код знает пути, любое изменение в сборке ресурсов ломает весь код.

В этой главе мы разделим «**что** нужно загрузить» и «**откуда**». К концу главы игра будет грузить настоящие атласы оригинала через манифест, а код игры при этом почти не изменится.

## Псевдоним — имя вместо пути

**Псевдоним** (alias) — короткое имя ресурса, по которому код его запрашивает. Связь «имя → файл» регистрируется один раз через `Assets.add`:

```ts
Assets.add({ alias: 'piece-dragon', src: '/assets/game/piece-dragon.png' });
```

`Assets.add` ничего не загружает, он только записывает соответствие. Загружать можно уже по имени:

```ts
await Assets.load('piece-dragon');
```

После загрузки ресурс лежит в кэше под этим именем, и его можно получить **синхронно**, без `await`:

```ts
Assets.get('piece-dragon');   // текстура или undefined, если ещё не загружена
Texture.from('piece-dragon'); // то же самое для текстур
```

## Регистрируем ресурсы

Замените в `main.ts` загрузку по путям на регистрацию псевдонимов и загрузку по ним:

```ts main.ts
const PIECES = ['dragon', 'frog', 'newt', 'snake', 'spider', 'yeti'];

// Регистрируем ресурсы под короткими псевдонимами: дальше код знает только имена, а не пути к файлам
for (const name of PIECES) {
  Assets.add({ alias: `piece-${name}`, src: `/assets/game/piece-${name}.png` });
}
Assets.add({ alias: 'highlight', src: '/assets/game/highlight.png' });

await Assets.load([...PIECES.map((name) => `piece-${name}`), 'highlight']);
```

Псевдонимы выбраны не случайно: так же называются кадры в атласах оригинальной игры. Когда в шаге 4 мы перейдём на атласы, имена совпадут, и коду фишек не придётся ничего менять.

## Фишка берёт текстуры сама

Теперь `Piece` может получать не текстуру, а **имя** текстуры, и брать её из кэша сама. Так устроен и оригинальный `Match3Piece`: `this.image.texture = Texture.from(opts.name)`.

```ts Piece.ts
constructor(textureName: string, size: number) {
  super();

  this.highlight = new Sprite(Texture.from('highlight'));
  // …
  this.image = new Sprite(Texture.from(textureName));
  // …
}
```

Константа `HIGHLIGHT_URL` больше не нужна: подсветка тоже берётся по псевдониму. А в `main.ts` фишка создаётся по имени:

```ts main.ts
const piece = new Piece(`piece-${name}`, TILE_SIZE);
```

::: task
Зарегистрируйте все текстуры под псевдонимами, загрузите их по именам и переделайте `Piece`, чтобы она принимала имя текстуры вместо самой текстуры.
:::

## Что получилось

Поле выглядит точно так же. Но теперь пути к файлам упоминаются в коде **ровно в одном месте**: при регистрации. Ни `main.ts` после загрузки, ни `Piece.ts` о путях не знают.

Поэкспериментируйте:

- создайте фишку с несуществующим именем: `new Piece('piece-unicorn', TILE_SIZE)`. В консоли появится предупреждение `Asset id piece-unicorn was not found in the Cache`, а фишка будет без картинки;
- выведите `Assets.get('piece-frog') === Texture.from('piece-frog')`: это один и тот же объект.

::: deep Под капотом: три части системы Assets
`Assets` — это фасад над тремя частями:

1. **Resolver** (разрешатель) — хранит соответствия «псевдоним → варианты файла» и выбирает лучший вариант: формат, разрешение. Работает при `Assets.add` и `Assets.init`.
2. **Loader** (загрузчик) — скачивает файл и превращает его в объект нужного типа. За каждый тип отвечает свой **парсер**: картинки → `Texture`, `.json` атласа → `Spritesheet`, шрифты → зарегистрированный шрифт. Парсер выбирается по расширению и содержимому.
3. **Cache** (кэш) — хранит готовые объекты по ключам: и по псевдониму, и по пути. Через него работают `Assets.get` и `Texture.from`.

Когда парсеры подключаются плагинами (звук через `@pixi/sound`, анимации через Spine), они встают в ту же цепочку, и `Assets.load('music')` начинает возвращать звук. Это мы увидим в главах 13 и 14.
:::
