Пора перейти на ресурсы, собранные так же, как в оригинальной игре. Главное отличие от наших отдельных PNG: картинки упакованы в **атласы**.

## Что такое атлас

**Атлас** (spritesheet, texture atlas) — одна большая картинка, в которую плотно уложено много маленьких, плюс файл с описанием, где какая лежит:

```
game-atlas.png (837 × 642)              game-atlas.png.json
┌───────────────────────────────┐        {
│ frog   books   …              │          "frames": {
│        dragon  highlight  …   │            "piece-dragon": {
│ spider   num-1 … num-5        │              "frame": { "x": 380, "y": 137, "w": 113, "h": 144 },
│ …                             │              "sourceSize": { "w": 150, "h": 150 }, …
└───────────────────────────────┘            },
                                            "piece-frog": { "frame": { "x": 2, "y": 497, … }, … },
                                            …
```

Каждая запись в `frames` — это **кадр**: имя и прямоугольник внутри большой картинки. PixiJS загружает атлас один раз и создаёт по `Texture` на каждый кадр. Все эти текстуры ссылаются на один и тот же источник (`TextureSource`), но с разными фреймами. Помните врезку про `Texture` и `TextureSource` из главы 2? Это она. Расположение кадров на схеме условное, а координаты — настоящие, из файла атласа.

Зачем это нужно:

1. **Один файл вместо десятков.** Меньше запросов, быстрее загрузка: это мы обсудили в прошлом шаге.
2. **Быстрее отрисовка.** Видеокарта рисует пачкой все объекты, которые используют одни и те же текстуры. Чем меньше разных картинок на экране, тем меньше пачек и тем быстрее кадр. Когда все фишки — кадры одного атласа, всё поле рисуется одной пачкой.

## Ресурсы оригинала

Атласы игры собраны инструментом **AssetPack**: именно он собирает ресурсы в оригинальной Puzzling Potions. Мы запустили его на исходниках игры, и результат лежит в `/assets/packed/`. Там же лежит сгенерированный манифест. Подробно об AssetPack поговорим в главе 15, а сейчас просто воспользуемся результатом.

Код с описанием ресурсов больше не нужен: манифест теперь — готовый JSON-файл. Замените содержимое `manifest.ts` на две константы:

```ts manifest.ts
/**
 * Манифест ресурсов, собранный AssetPack из оригинальных ресурсов Puzzling Potions.
 * Внутри — бандлы preload, game, common, home и result, а картинки упакованы в атласы.
 * Это «базовая» версия манифеста: без звуков и Spine-анимаций, которые понадобятся в главах 13–14.
 */
export const MANIFEST_URL = '/assets/packed/manifest-basic.json';

/** Пути в манифесте указаны относительно этой папки */
export const ASSETS_BASE_PATH = '/assets/packed';
```

А в `main.ts` передайте `Assets.init` путь к манифесту вместо объекта:

```ts main.ts
import { ASSETS_BASE_PATH, MANIFEST_URL } from './manifest';
```

```ts main.ts
await Assets.init({ manifest: MANIFEST_URL, basePath: ASSETS_BASE_PATH });
```

`basePath` нужен потому, что пути в манифесте относительные: `game/game-atlas-jmixPg.webp`. PixiJS добавит к ним `/assets/packed/`.

И главное: **больше ничего менять не нужно**. Бандл по-прежнему называется `game`, а кадры в атласе называются так же, как наши псевдонимы: `piece-dragon`, `highlight`. `Piece` и цикл создания поля работают как раньше.

## Смотрим, что загрузилось

Добавьте после загрузки бандла несколько строк, чтобы посмотреть на текстуру дракона:

```ts main.ts
// Какой файл атласа выбрал Assets
const dragonTexture = Texture.from('piece-dragon');
console.log('Атлас:', dragonTexture.source.label);
console.log('Кадр в атласе:', dragonTexture.frame.width, '×', dragonTexture.frame.height);
console.log('Исходный размер:', dragonTexture.orig.width, '×', dragonTexture.orig.height);
```

::: task
Перейдите на манифест AssetPack и выведите в консоль, из какого файла взят дракон и каков размер его кадра.
:::

## Что получилось

Поле выглядит как раньше, но загружено совсем иначе. В консоли:

```
Загружено: 0%
Загружено: 100%
Атлас: http://localhost:5173/assets/packed/game/game-atlas-jmixPg.webp
Кадр в атласе: 113 × 144
Исходный размер: 150 × 150
```

Три интересные вещи:

1. **Прогресс прыгнул с 0 сразу на 100%.** В бандле теперь один атлас, то есть один файл, а прогресс считается по файлам.
2. **Загрузился `.webp`, а не `.png`.** AssetPack собрал каждый атлас в нескольких форматах, и PixiJS выбрал самый лёгкий из тех, что поддерживает браузер. Об этом — в следующем шаге.
3. **Кадр 113 × 144, хотя картинка 150 × 150.** Это обрезка, о ней во врезке ниже.

::: deep Под капотом: обрезка прозрачных краёв (trim)
У картинок зелий по краям много полностью прозрачных пикселей. Хранить их в атласе — пустая трата места. Поэтому упаковщик **обрезает** прозрачные края (trim) и кладёт в атлас только непрозрачную часть: 113 × 144 вместо 150 × 150. А в описание кадра записывает, сколько обрезано с каждой стороны.

У текстуры из атласа поэтому два размера:

- **`frame`** — реальный прямоугольник в атласе (113 × 144);
- **`orig`** — исходный размер картинки до обрезки (150 × 150).

Спрайт использует `orig`: его размер по-прежнему 150 × 150, якорь `0.5` — по-прежнему центр исходной картинки, а непрозрачная часть рисуется со смещением ровно там, где была. Для кода обрезка невидима, а атлас стал заметно меньше.

Сам атлас доступен как объект `Spritesheet`: `Assets.get('game-atlas')`. У него есть `textures` (все кадры по именам) и `animations`, если в атласе описаны покадровые анимации. Их мы используем в главе 8.
:::
